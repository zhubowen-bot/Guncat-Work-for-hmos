# Guncat Work 6.3.0

> 鸿蒙掌上 Codex —— 原生 HarmonyOS AI 客户端。本版新增 **交互模式（Intelligent UI）**：一句话进来，一张能拖、能点、能改参数并即时重算的原生界面出去。

**版本** `6.3.0`（versionCode 720） · **commit** `0487fbc` · **日期** 2026-10-10

## ✨ 本版主线：交互模式（Intelligent UI）

<p align="center">
  <img src="https://raw.githubusercontent.com/zhubowen-bot/Guncat-Work-for-hmos/main/docs/images/interactive-home.jpg" width="45%" alt="交互模式首页" />
  <img src="https://raw.githubusercontent.com/zhubowen-bot/Guncat-Work-for-hmos/main/docs/images/interactive-ui.jpg" width="45%" alt="交互模式直出的可操作界面" />
</p>

交互模式是 **Agent 循环的第二种交付形态**，与工作模式共用同一套 Agent Loop、沙箱工作区与全部 45 个工具，但**行为纪律相反**：工作模式是「多轮工具循环 + 长程交付」，交互模式是「**快车道、一轮直出界面**」。

### 对标 GPT 的 Intelligent UI：回答不再是纯文本，而是一份界面程序

应用的交付物从文字变成一份**界面程序**，由渲染器转成原生可操作界面：8 种图表（柱状 / 折线 / 面积 / 横向条 / 饼环 / 径向 / 雷达 / 堆叠条）、表格、指标卡、图片墙、选项卡 / 折叠面板 / 步骤条 / 卡片块，以及整套表单控件（滑块 / 开关 / 单选 / 多选 / 下拉 / 标签选择 / 选项卡 / 输入框 / 文本域）。图表全部用声明式 `Shape` + `Path` 现画，**不引入图表库、不产生图片文件**。

上游研究材料随仓库提供：[open-intelligent-ui 规格](https://github.com/zhubowen-bot/Guncat-Work-for-hmos/blob/main/docs/reference/open-intelligent-ui-spec.md) · [openui-lang 规范](https://github.com/zhubowen-bot/Guncat-Work-for-hmos/blob/main/docs/reference/openui-lang-spec.md)。

### 交付格式重写：严格 JSON → 声明式界面语言 `guncat-ui lang`

旧的 JSON DSL 被**整体删除并重写**。核心变化是抗截断能力：

- **JSON → 按行语句**：每条语句独立成行（`root = Card([header, chart])`、`header = CardHeader("标题")`）。
  被输出上限截断时，旧格式**整块作废**；新格式只损失**最后一条没写完的语句**，前面的全部照常渲染。
  「补救」从主路径降级成兜底。
- **70 个原生组件**（9 组），组件库有**单一事实源**（`GuncatUiLibrary.ts`）：一张表同时生成提示词里的组件清单、解析期的参数映射、渲染期的合法性判断，三者不会再漂移。
- **回答不再有「卡片外壳」**：旧实现在界面外套了一层带边框、阴影与状态徽标的卡片，观感像"嵌在聊天里的小部件"；现在节奏只来自间距——这是最直观的一次观感提升。
- **容错策略（有意偏离参考实现）**：未闭合的括号 / 字符串自动补齐；未知组件名丢弃并给出诊断；但**必需参数缺失或类型不符不再丢弃组件**（用安全默认值渲染）——聊天场景里"少一个字段"远好于"整块消失"。

### 交互闭环：拖参数即时重算，需要换数据才回传模型

- **双向绑定（`$变量`）**：控件绑到 `$变量` 后，拖动 / 勾选会**立即用新值重新求值整棵树**（`"金额 " + $amount + " 万"` 会实时变），不发请求、不等模型。
- **回传模型**：需要换数据或换算法时，点按钮或提交表单，把设置与诉求打包回传，模型产出**更新后的完整界面**。
- **状态随消息持久化**：调过的参数以尾标记保存在消息里，滚动 / 切会话 / 重启后仍在；下一轮请求前会被翻译成一句人话交给模型。

### 快车道：默认零工具、一轮直出

此前交互模式**完整复用**了工作模式的系统提示词，而那套纪律是为「多轮工具循环 + 长程交付」写的——结果用户等来的是一串和界面无关的 `todo_write` / `load_skill` / `list_files` / mermaid 导图。本版把它改成快车道：

- 提示词分叉从「交付格式」改为「**行为纪律**」：默认一次回答直接给界面、不调用任何工具，工具是破例（一轮最多 1~2 次且优先只读）；
- 系统提示词 **36.7k → 22.8k 字符**（其中行为纪律段 15.6k → 1.7k），首答 TTFT 与输入 token 同步下降；
- 默认思考强度由「均衡(High)」改为「**快速(Low)**」；工具面与沙箱能力**一个没少**（工具定义与工作模式逐字相同）。

### 健壮性：本版花了大量力气在真机缺陷上

- **拖动绑定控件实时刷新**（真机缺陷：拖 `Slider` 手柄会动，但引用该变量的文字 / 指标卡 / 图表完全不刷新）。根因是三件事叠加：元素 key 生成漏了单元素属性（真机 19 个节点里 7 个 key 为空）、界面刷新不能靠"换 `ForEach` 键 ⇒ 重建该项"、以及 `Slider` 自身必须**豁免**指纹否则拖动会丢手势。
- **图表渲染三处修正**：共同根因是 ArkUI 的 `Path.commands` 以**物理像素 px** 为单位，而组件宽高与 `strokeWidth` 用 **vp**。折线图不再过小、饼图不再被裁成半圆（改实心扇形）、径向图比例回归正常。
- **活动折叠栏**：正文开始输出后，思考与全部工具调用自动收成一条「✓ 已完成 · 思考 ×N · M 个工具 · 12.4s」；按**回合**合并（不再出现四条「已完成」叠在一起）；每轮思考默认收起；手动停止的回合显示「已停止」而不是「已完成」。
- 顺带修掉三个既有缺陷：**聊天模式下不含界面的回答正文一个字都不显示**；界面绑定值不落盘（滚动即丢）；「重新回答」在交互模式下不走 Agent Loop，且会话标题 / 复制为纯文本 / 导出 Word 会把界面源码原样带出去。

## 🛠 工作模式与全局改动

<p align="center">
  <img src="https://raw.githubusercontent.com/zhubowen-bot/Guncat-Work-for-hmos/main/docs/images/work-delivery.jpg" width="45%" alt="工作模式长程任务交付" />
  <img src="https://raw.githubusercontent.com/zhubowen-bot/Guncat-Work-for-hmos/main/docs/images/run-js.jpg" width="45%" alt="run_js 设备内 JS 执行沙箱" />
</p>

- **启动落点固定为交互模式**：打开应用的第一屏就是"能操作的界面"，不再恢复上次偶然停在的智能体。
- **空态大标题换成模式切换胶囊**（对齐豆包首页的「对话 / 工作」大按钮）：点另一段即换挡，点击即落选中态、深色滑块瞬移不再闪在旧档位。
- **侧边栏「聊天引擎」分组默认折叠**：抽屉打开只露出标题行，把默认视野留给 Agent 模式与历史对话。
- **联网搜索：默认走服务端，本机工具降级为兜底**。原先本地工具叫 `search_web`，与服务端内置的 `web_search` 只差一个词序、极易混淆；现改名 **`local_web_search`**，并明确"未开启服务端搜索时它才是唯一通道"（旧名保留为分发别名，历史调用仍可执行）。
- **思考强度分档**：交互模式为 均衡(High) / 快速(Low) / **关闭(Off)**；工作模式仍为 极高(Max) / 均衡(High) / 快速(Low)。两档**各自持久化、互不影响**，「关闭」不会影响其它模式的深度思考。
- **按钮视觉统一**：`primary` / `secondary` / `destructive` / `tertiary` 四套语义色，深色模式下补描边（原来看不见按钮），单个按钮不再拉满整行。

## 📦 安装

本 Release **暂不提供预编译 HAP**，请从源码构建。

**环境要求**
- DevEco Studio 6.0.1 或兼容版本
- HarmonyOS SDK API 24（6.1.1）
- HarmonyOS 手机真机

**构建**

```bash
hvigorw --mode module -p product=default -p module=entry@default -p buildMode=debug assembleHap
```

或用 DevEco Studio 打开仓库根目录 → 配置签名 → 运行 `entry` 模块。

**首次使用**：打开设置 → 新建 API 配置 → 填写接入方式（OpenAI Completions / OpenAI Responses / Anthropic Messages）、Base URL、API Key、模型名 → 回到对话。

常用兼容地址：
- DeepSeek Responses：`https://api.deepseek.com`
- 火山方舟 Responses：`https://ark.cn-beijing.volces.com/api/v3`
- Anthropic Messages：`https://api.anthropic.com/v1`

## ⚠️ 已知限制

- 需要 HarmonyOS 真机；模拟器上 Preview Kit / Share Kit / CoreSpeechKit 等系统能力行为不一致
- 交互模式依赖模型按 `guncat-ui lang` 语法产出界面；模型若写了组件清单以外的名字会被丢弃并给出诊断，可让它重新生成一版
- 联网搜索、图片理解等能力取决于你所配置的模型服务是否支持
- 朗读可用音色及是否需要下载由设备与系统版本决定

## 🔒 隐私

运行时只使用应用沙箱（`filesDir/workspaces/`）与系统安全组件完成文件读写，**未新增任何存储权限**；聊天请求与附件只发送到用户自行配置的模型服务。
