# Guncat Work 7.0.0-alpha

| 项目   | 内容                       |
| ---- | ------------------------ |
| 版本   | 7.0.0-alpha              |
| 发布日期 | 2026-10-30               |
| 适用平台 | HarmonyOS · Windows      |

7.0.0-alpha 的核心变化是 HarmonyOS 版 `shell` 的执行核：从 QEMU 虚拟机内的 Alpine 换成 IEC 原生执行核。命令现在是随包的 HarmonyOS 原生 `.so`，没有虚拟机、没有指令翻译，也没有镜像冷启动。同时，Windows 版带来一批配置、界面与文件拖拽方面的小改动。

## 主要更新

### HarmonyOS：Shell 执行核换血（QEMU → IEC）

- **不再模拟一台电脑**：旧实现在应用里跑 QEMU + Alpine，每条命令都要逐条解释，重命令动辄数秒到数十秒。现在 `shell` 的命令都是原生 `.so`，由 IEC 的 exec 服务加载并 `fork` 执行，常见命令耗时回到 0.2~1.5 秒量级。
- **同一份文件系统**：不再有 virtio-9p 与宿主机、虚拟机两份视图。`cwd` 就是会话工作区，`shell` 写出的文件其它工具立刻可见，其它工具写入的脚本也能直接执行。
- **环境像一个系统**：注入 `PATH` / `HOME` / `TMPDIR`（`HOME`/`TMPDIR` 按会话隔离），`/etc` 映射到 sysroot；`id`、`whoami`、`logname` 等命令有正确结果；`#!/usr/bin/env sh` 之类的 shebang 可以直接工作。`/tmp` **刻意不提供**——沙箱只映射 `open`/`opendir`，保留它只会得到半挂载；临时文件统一用 `$TMPDIR` 或 `mktemp ./x.XXXXXX`。
- **mksh 走真语义**：管道、重定向、通配符、命令替换、here-doc、`case` / `for` / `while` 都由 mksh 执行；算术按 64 位重编，`$((2000000000+2000000000))` 不再溢出成负数。
- **CA 与网络开箱可用**：内置证书统一导出为 `GIT_SSL_CAINFO` / `SSL_CERT_FILE` / `CURL_CA_BUNDLE`，`git clone https://…`、`curl` 与 Python 的 `ssl` 都能直接校验证书。
- **旧栈移除**：QEMU 桥、内核、rootfs、EFI ROM、`libqemu` / `libslirp` 与相关构建链全部删除，约 94 MB；不保留慢速回退，执行核没接上时直接报错。

### HarmonyOS：随包命令集

| 类别 | 命令 |
| --- | --- |
| shell 与基础工具 | `sh` / `mksh`；`toybox` 70+ applet（`ls` / `cat` / `grep` / `sed` / `awk` / `find` / `xargs` / `dd` / `md5sum` / `od` 等） |
| 压缩与归档 | `tar` / `bsdtar`、`unzip`、`zip`、`cpio` / `bsdcpio` |
| 网络与传输 | `git`（含 HTTPS）、`ssh` / `scp` / key 工具（dropbear）、`sftp`、`curl`、`nc` |
| 数据与文本 | `jq`、`bc`、`hexdump` / `hd`、`diff` |
| 语言运行时 | `node` / `nodejs` 22.19、`npm` / `npx`、`python3` / `python` |

- 所有命令都是独立 `.so`，不再有 `apk add` 这一步，也不依赖镜像预装；能力边界由随包命令集决定。
- `npm` 的纯 JS 树随包放置，首次启动解到 sysroot，以“整包解完”的完成标记判断是否可用。
- 自编的 `nc` / `hexdump` / `diff` 与 BSD / util-linux / `git diff --no-index` 语义对齐，并有宿主侧逐字节对拍。

### HarmonyOS：shell 里的 `python3`

- **同一个 Python 3.12**：shell 里的 `python3` 与 `run_python` 共用 `libpython3.12.so`、标准库与 site-packages，不再经过虚拟机，`npy` 桥随之移除。
- **独立进程，崩溃隔离**：常驻 runner 为每次请求 `fork` 一个孙进程加载 CPython，单次崩溃或被 `SIGKILL` 只影响那一次，后续调用不继承上一次的解释器状态。
- **退出码原样回传**：`sys.exit(7)` 返回 7。
- **超时与取消收干净**：调用方消失或作业被取消时，连同进程组一起收掉。
- **边界**：shell 里的 `python3` 不能 `subprocess` 起 `sh`，需要管道时写在外层 shell。

### HarmonyOS：shell 语义与资源治理

- **超时由执行核强制**：默认 60 秒、上限 240 秒；到点先 `TERM` 后 `KILL`。
- **输出有界且可追溯**：stdout / stderr 各截断到 60 KB，完整内容落 `.spill/` 并给出相对路径；区分“引擎因上限丢弃的字节”与“壳层截断”。
- **二进制不装作文本**：输出含非法 UTF-8 或 NUL 时标记 `binary=true`，提示改用重定向或 `base64`。
- **状态行说人话**：区分 `exit 0`、非零退出、超时终止、被信号终止、启动失败与“未观测到退出状态”。
- **并发有上限**：同一时刻最多 8 条命令，超出排队。
- **作业级取消**：每条命令带作业标识，取消时整棵进程树一并结束；启动时清理上次遗留的孤儿进程。
- **stdin 不会挂住**：带数据的 `stdin` 先落成文件再重定向；没有 `stdin` 时接 `/dev/null`，不会因等输入而超时。
- **路径与脚本兼容**：`cwd` 必须是工作区内的相对路径；相对路径脚本与没有 shebang 的文本脚本有可预期的回落，不再直接 `127`。
- **UTF-8 统一**：工具与 `/bin/sh`（含 `sh -c`、`sh script.sh`、`#!/bin/sh`）默认按字符处理，`${#中文}`=2、切片正确；直接 `mksh script.sh` 仍需 `mksh -U`。`printf` 的字段宽度仍按字节（toybox），对齐用 awk/python。
- **后台进程回收**：命令结束后收掉残留的 `&` 后台进程，不跨调用泄漏。
- **软链跨工具可见**：文件工具统一解析 `.IEC_SYMLINK`，删除与移动作用于链接本身；越界与环境变量保护仍在。

### Windows：预置方案与多模型

- **新增两套预置配置方案**：`Deepseek`（`https://api.deepseek.com`）与 `Opencode Go`，都走 Anthropic Messages 接入，各预留一个模型。装上就有，补一个 API Key 即可使用。
- **老用户升级只播一次**：已配过 `api.deepseek.com` 的方案做兼容合并，Key、模型列表与多模态配置搬进预置项，不留两个同名同址的方案。
- **一个方案可以填多个模型**：设置里的「模型」改为多行输入（每行一个，也接受逗号 / 分号分隔），保存时去重；当前生效的模型被删除时退回列表第一个。老数据按单模型处理，原样保存。
- **顶栏模型胶囊升级为「方案 + 模型」菜单**：点开列出所有已填 API Key 方案下的全部模型，一点即切换。表格提取的模型下拉同步展开，没填 Key 的方案不列出，不让人选到一个必然失败的模型。
- **Opencode Go 网关适配**：`x-opencode-session` 请求头统一补上，会话 id 在整轮请求中保持稳定。

### Windows：设置面板

- 「自动朗读回答」与「语音输入（录音转文字）」改为与上方三节同款的折叠栏，缺省收起，面板一打开就是常用项。

### Windows：文件拖拽按模式自动分流

- **聊天模式**：文件拖到对话区或底部输入区，自动加入底部附件预览条；若右侧「工作区」面板展开且拖到该面板上，则导入当前会话工作区。遮罩层实时提示落点去向。
- **工作模式 / 交互模式**：文件或整个文件夹拖入窗口任意区域，自动导入当前会话工作区（递归收录文件夹内文件），导入后文件树立即刷新。
- **拖拽兼容性加固**：从浏览器、截图工具等无本地路径的来源拖入内存文件时，自动落入临时目录再走统一链路；拖离窗口的判定与复位更稳；拦住非应用内 URL 的导航，避免误触发浏览器默认的文件打开行为。
- **安装后首启降权**：安装程序完成页拉起应用时，未勾选「始终以管理员身份运行」则经由 `explorer.exe` 降权启动，避免新装首启继承管理员令牌后拦截资源管理器的拖拽。

## 升级说明

- **HarmonyOS**：HAP 未签名，需自行签名后安装。不需要迁移镜像，首次使用 `shell` 不再释放镜像或冷启动。旧版本可能在应用私有目录残留 QEMU 镜像，新版本不再读取。
- **HarmonyOS**：仅提供 arm64-v8a；x86_64 模拟器上 IEC 的 NAPI 加载失败，`shell` 不可用。
- **Windows**：可直接覆盖安装；明文 API Key 在下次写盘时转为密文，跨机器复制的配置中无法解密的条目会被剔除并提示重新填写。
- **配置迁移**：模型配置自动迁移，旧存档的单模型转为 `models` 列表；旧的 Deepseek 方案并入预置方案。

## 已知限制

- **HarmonyOS**：没有真 pty 与 job control，依赖终端的交互式 TUI 不适用；`&` 可以起后台进程，但没有 `Ctrl+Z` / `fg` / `bg`。
- **HarmonyOS**：不再提供 `apk add` 式的包管理器扩展；需要新命令时通过 IEC 构建链编成 `.so` 随包。
- **Windows**：安装包未签名，首次双击 SmartScreen 会拦一下，点「更多信息 → 仍要运行」即可。

## 数据与隐私

- 对话记录、工作区文件与会话日志保存在应用私有目录；删除会话时同步删除对应工作区。
- 模型请求与所附文件只发送到用户自行配置的模型服务。
- Windows 的 API Key 经系统凭据库加密后落盘（`enc:v1:`）。
- HarmonyOS 的命令在会话工作区内执行，`run_python` 的安装目录（标准库与三方库）只读。
