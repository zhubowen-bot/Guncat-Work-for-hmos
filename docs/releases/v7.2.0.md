# Version 7.2.0 发布说明

**发布日期：2026-11-05**

Version 7.2.0 把「这次对话花了多少钱、花在哪儿」做成可查、可导出的本地账本；把设置页从弹窗里的折叠表单改成独立分页。电脑版与安卓版同时修复了交互模式卡片文本被引号、全角标点截断的问题，并让卡片内的文本字段恢复 Markdown 渲染；安卓版与鸿蒙版修正了模式胶囊切换后误入历史会话的问题。鸿蒙版另有一轮针对闪退、后台存活与长会话的性能专项。

**自 Version 7.2.0-beta 1 起，各仓库的 Release 将仅提供与该仓库对应的发布包。例如，hmos 仓库仅提供鸿蒙版 HAP 发布包，不再同时提供电脑版、安卓版发布包。如需其他平台的发布包，请前往对应仓库的 Release 页面获取。**

**同时，鸿蒙版开始提供永久邀请测试分享链接，可以直接通过官方渠道获取最新测试版本：https://appgallery.huawei.com/apptest/955nTWBlvx0**

## 一、用量与成本（全平台）

新增本地用量账本和「用量与成本」页。每个完成的 LLM 响应在结束时归一化一次 `usage`，按「日期 → 服务商 → 模型 → 高峰 / 空闲」聚合。统计覆盖主对话、工作模式 Agent Loop、子代理、标题生成、上下文压缩、交互模式补救请求；电脑版 / 安卓版还覆盖命令自动审阅、多模态解析与表格识别。

### 记账与计价

* **三协议统一口径**：Anthropic 合并 `message_start`（输入与缓存读写）与 `message_delta`（累计输出）；Responses 同时识别 `response.completed` 与 `response.incomplete`；Completions 优先使用 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，并只对确认支持的服务商补 `stream_options.include_usage`，避免严格网关因未知字段直接 400。
* **DeepSeek 峰谷**：按北京时间（UTC+8，与机器时区无关）归日与判断峰谷。工作日 09:00–12:00、14:00–18:00 为高峰，其余时段与法定节假日为空闲；Flash / Pro 按缓存命中、未命中、输出分项计价，服务端联网搜索 / 抓取按 5 元 / 1000 次计入，页面按 1 USD = 7.2 CNY 折算展示。电脑版对未收录价目的模型只标记「未收录价目请求」，不硬套价格。
* **OpenCode Go**：按网关返回的 `opencode.tokens`、`allowance`、`cost`、`list_cost`、`billing_source` 统计，套餐内显示额度消耗与等价成本，不按模型名误套 DeepSeek 峰谷价。
* **缺失与失败**：缺失 `usage` 的请求如实计数，不猜测成本；失败或被中止的请求不计费；统计或写盘异常不会影响聊天与 Agent 主流程。
* **本地、轻量**：账本只保留按日聚合（约 400 天；鸿蒙版另有最近 8 天的小时桶），不保存逐请求明细，也不写进消息存档。页面只在打开时读取快照，不扫描历史、不轮询、不带后台任务；鸿蒙版首笔请求懒加载账本，聊天页不挂载统计对象。

### 页面与平台差异

* **电脑版**：独立全窗口页面，左侧分类导航；从侧栏「用量」或设置「账户与用量 → 用量与成本」进入。今日 / 近 7 天 / 本月 / 本月预计四张汇总卡，53 周热力图，费用 / Tokens / 请求数切换；点击某天查看按模型拆分、峰谷、联网搜索与 OpenCode 额度。支持月预算、CSV 导出；DeepSeek 余额手动刷新，6 小时节流。
* **安卓版**：独立页面，手机端筛选区纵向堆叠，刷新 / 导出 CSV 独立成行；服务商与主指标合并为全局筛选，切换指标时汇总卡、热力图、日详情与模型占比一起联动，汇总卡与热力图在窄屏保持完整宽度。设置页把「用量与成本」拆成独立「用量」分组；DeepSeek 余额 10 分钟节流。
* **鸿蒙版**：设置「模型」分组内的独立页面，宽屏侧边栏底部有「用量」快捷入口，工作区详情显示「最近一轮 Token / 费用」。53 周热力图首次打开自动滚到最近日期，之后尊重手动滚动；DeepSeek / OpenCode 两张卡片始终显示，未填 Key 标注「未启用」；汇率 / 预算 / 额度收在带遮罩的底部弹层；OpenCode 支持近 5 小时、近 7 天与本月额度窗口；账本额外保留 8 天小时桶。

补充说明：

* **峰谷节假日表**按端内置：电脑版 / 安卓版覆盖 2024–2026 年，鸿蒙版内置 2026–2027 年节假日；安卓版对 2027 年及以后尚未公布年份按工作日高峰保守估算。
* **热力图与对账**：DeepSeek 余额只作对账，不计入热力图和每日统计；OpenCode 使用网关返回的等价成本，不套用 DeepSeek 峰谷价。
* **导出**：CSV 带 UTF-8 BOM，包含人民币折算列；鸿蒙版同时支持清空统计。

## 二、设置页改版（全平台）

不再把所有配置塞进一个弹窗、靠折叠栏逐段展开；设置改为独立页面，模型配置、搜索、多模态、朗读、语音各自成页（鸿蒙版另有系统信息页），字段修改后自动保存。

* **电脑版**：铺满窗口，左侧分类导航、右侧当前分类；分组为模型配置、高级模型参数、本地联网搜索、多模态解析、用量与成本、自动朗读、语音输入。输入停顿后自动写入当前配置方案，移除保存 / 取消按钮；Esc 可关闭；顶部左侧线性返回箭头。
* **安卓版**：整页布局，一级列表 / 二级详情；一级按模型、能力、声音、系统分组，首屏只显示模块入口。二级页字段 350ms 防抖自动落盘；返回键先从二级详情回到一级列表，再退出设置；朗读与终端后端即时生效。
* **鸿蒙版**：按需 push 的独立路由页；模型配置、高级参数、本地联网搜索、多模态解析各成页，另有声音（朗读）与系统（终端）分组。所有分页共享同一份草稿，防抖自动保存；返回或切换方案前先冲刷草稿；聊天页不再常驻挂载整棵设置表单。

共同变化：

* **模型配置合并**：配置方案、配置名称、接入方式、Base URL、API Key 与模型列表收进同一页；方案可直接切换、新建与删除。电脑版与安卓版保存到当前配置方案；鸿蒙版切换方案前先把未保存草稿落盘，避免输入被静默丢弃。
* **自动保存**：去掉手动保存按钮，输入停顿后写盘；离开页面或切换方案时再同步一次，降低流式刷新时对配置项的重复求值。
* **视觉统一**：卡片式分组、开关式布尔项、字段级提示与填充式输入框；安卓版一级列表使用白色列表卡、无底色线性图标与分组摘要；电脑版放大正文字号并加宽版心；鸿蒙版沿用系统 SymbolGlyph 图标与品牌色。
* **终端环境页（鸿蒙版）**：设置「系统 → 终端」新增只读环境页，展示原生 Shell、原生 CPython 3.12 等运行组件，以及应用版本、系统版本、API 等级、设备类型、芯片平台与指令集。

## 三、交互模式：卡片文本与 Markdown（Windows 版 / Android 版）

> 两端共用同一份 HTML 渲染层，修复完全一致；鸿蒙版使用 ArkUI 原生组件，本轮更新记录没有这一项。

### 卡片文本不再被截断

* **根因**：界面程序由模型手写，字符串里偶尔出现未转义的引号、单引号包裹的英文撇号、以反斜杠结尾的 Windows 路径；旧词法器一见引号就收口，后面的中文被当成新 token 丢掉，表现为卡片标题、副标题、正文只显示前半截。全角逗号 / 括号 / 引号、少写逗号、用反引号包字符串还会让参数错位，严重时把后面的组件整段吞掉。
* **修复**：电脑版新增 `GuncatUiSourceRepair` 源码修复层，在词法分析前把字符串内部的成对引号补成 `\"`、把字符串外的全角标点归一成 ASCII，并让缺逗号、括号深度、注释与跨行续行都有明确处理；安卓版改为「只有引号后紧跟合法边界才收口」，整行无法干净解析时按行重切并做有上限的收尾重试。
* **安卓版顺带修复**：单字段文本上限与整程序上限对齐，不再悄悄砍到 4000 字；控件状态只在用户真的操作过控件后写回，且不再随每个流式 token 重建 400ms 定时器；短字段里的 Markdown 链接引用定义不再被整行吃掉。
* **性能**：电脑版修复层是单趟字符扫描，没有异常字符时直接返回原串、不产生副本，正常卡片解析仍在毫秒级；安卓版只在整行无法干净解析时才按行重切，正常路径不增加额外解析。流式重绘不会因此变卡。

### 卡片内所有文本字段恢复 Markdown

* **范围**：此前只有 `TextContent` / `MarkDownRenderer` 走 Markdown 管线；`CardHeader`、`Callout`、`InlineHeader`、`Text`、`BoldText`、`IconText`、`ImageText`、指标、标签、表格、键值清单、列表、步骤、卡片块、表单标签与按钮等仍把字符串原样输出。
* **修复**：新增行内 Markdown 渲染器 `InlineMarkdown`，复用 CommonMark + GFM 行内子集，自动去掉块级节点外壳，避免在表格单元格、按钮、标签里产生 `<p>` 破坏行内布局；`Callout` 正文、`ContextCardItem` 正文、`ListBlock` 副标题、`StepsItem` 详情等多行字段走完整 `Markdown` 管线。提问卡片的问题与选项、下拉框选项也一并处理，原生 `<option>` 只显示剥掉记号后的纯文本。
* **样式**：卡片内的段落、列表、标题、引用、表格、链接与行内代码补齐紧凑间距，深浅色沿用现有 CSS 变量，既有卡片布局不变。
* **回归**：电脑版 `render-check` 新增 6 项截断断言、5 项 Markdown 断言；安卓版新增七类截断断言与 14 项 Markdown 断言，覆盖粗体、行内代码、链接、多段落，并断言产物不再残留 `**`、交互元素内不产生嵌套 `<a>`。

## 四、模式切换：进入目标形态的新建对话（Android 版 / HarmonyOS 版）

* **问题**：胶囊与侧栏底部的形态切换原先走 `setMode → selectAgent`，而 `selectAgent` 的语义是「打开该引擎的最新会话」。工作模式一旦有历史会话，从交互模式的新建页切过去就会直接进入最近一条工作会话，用户还没开始新任务就被带进旧上下文。
* **修复**：形态切换改为「目标形态的新建对话」——先在该形态的会话里找 `messageCount === 0` 的空会话，按 `updatedAt` 取最新一条复用；没有空会话才新建。侧栏 / 抽屉的智能体列表仍保留「打开最新会话」的原行为，只有胶囊换挡走新逻辑。
* **鸿蒙版补充**：换挡不清理另一模式的空对话；交互 / 工作两个模式各自保留一份未使用的新对话，来回切换始终停在同一份草稿上，不会反复建 / 删，也不会越换越多。

## 五、附件先行解析默认关闭（Windows 版 / Android 版）

* **默认值**：多模态配置的 `preparseEnabled` 默认由开启改为关闭。新安装、以及配置里没有写过该字段的旧数据，图片和文档会直接交给当前接入方式的主模型处理，不再默认先调用独立的多模态解析接口。
* **不覆盖用户选择**：已经显式保存过「先行解析附件」开关的配置保持原值，不会被这次默认值调整覆盖；关闭时也不会因未配置多模态 Key 而先走一次失败解析。
* **鸿蒙版**：现有实现默认即为关闭，本次没有行为变化。

## 七、稳定性与性能（HarmonyOS 版）

针对「大工具输出闪退、历史积累后闪退、后台跑久回前台卡死、闪退后对话丢失」做的一轮系统性收敛：

* **会话存档与崩溃恢复**：从「每次工具步骤把全部会话 `toJson + stringify + 同步写盘`」改为 800ms 合并写，切后台 / 停止生成 / 退出前强制刷盘；写盘改为逐会话流式序列化，峰值内存从「全部历史之和」降到「最大单会话」；输出文件直接写字符串，去掉 `TextEncoder + ArrayBuffer` 的整份复制。存档采用「主文件 + `.bak` + `.tmp`」三段式原子提交，主文件损坏时自动回退 `.bak`，首次写入中途被杀也能从 `.tmp` 恢复；修复 `loadOk` 误判导致孤儿清扫删工作区的问题。
* **大输出与长历史**：IEC 输出边收边解码，去掉 8MB 字节块合并副本与二次扫描；shell 输出上限 8MB → 2MB；Python stdout / stderr / meta / diag 按头尾保留、总上限 2MB；附件、分享文件、工作区 zip 导出在分配内存前检查大小。消息时间线只渲染最近 40 条并可向前加载；聊天模式请求按 300k 字符滑动窗口裁剪，工作模式增加 2M 字符硬上限；压缩只改请求副本，不再永久截断用户记录；旧工具参数超 16KB 时替换为合法 JSON 占位；历史图片只重发最近 3 条用户消息。
* **后台保活**：切后台先申请长时任务再落盘；修复后台启动任务不申请保活与 start/stop 竞态；后台期间暂停页面整页刷新、1s / 100ms 轮询、气泡 50ms 文本刷新与 250ms 收尾采样，回前台补一次刷新。新增短时任务（约 3 分钟硬窗口）与长时任务分层保活：退后台先 `requestSuspendDelay`，再按设备申请 `dataTransfer`（2in1 优先 `taskKeeping`）；WantAgent 改用运行时 bundleName / abilityName，避免 beta / 正式包名不一致导致申请失败；监听长时任务取消 / 暂停，仅在系统取消且任务仍在跑时重试一次，用户取消 / 删除通知 / 低速率 / 违规不重试；短时任务超时回调与长时任务暂停时各补一次落盘；AI 与朗读的长时任务按各自 `continuousTaskId` 停止，不会互相误停。
* **消息跟随**：自动置底从「无条件跟随」改为「贴底才跟随」；用户上翻后彻底停止 `scrollTo`，Fling 惯性结束前不恢复，避免生成过程中与手势抢滚动造成抖动；回到底部自动恢复跟随；消息区底部新增系统 SymbolGlyph 的圆形「回到底部」按钮，不依赖 emoji。滚动帧内只更新普通字段，按钮显隐仅在跨越底部状态时写 `@State`，并合并同一帧内多次置底请求。
* **主线程与资源**：VM 通知 60ms 合并；工作区文件树 / 任务清单 / 目标 / 定时提醒按 mtime 缓存；目录列表每条目只 stat 一次；流式文本与思考按 80ms 批量上抛，降低逐 token 的 O(n²) 字符串复制；Markdown 表格规范化增加结果缓存。会话日志常驻 fd 限制为 8 个（LRU）；历史内联图片超过 12MB 后从最旧消息释放 `dataUrl`（保留缩略图）；设置面板按需挂载。

## 十、说明与边界

* **用量账本只在本地**：不云同步、不上传；清除应用数据或卸载后账本随之丢失。DeepSeek 余额仅作对账，不参与热力图与每日统计。
* **统计范围**：只统计本应用内完成的 LLM 请求；缺失 `usage` 的响应会计数但不猜成本；第三方客户端或其他设备的调用不在账本内。
* **峰谷与额度**：DeepSeek 峰谷按北京时间计算，节假日表按端内置；OpenCode 额度与成本以网关返回为准。
* **后台保活不是无限常驻**：HarmonyOS 仍可能回收后台进程；本版的目标是提高存活优先级，并在超时 / 暂停 / 退出前把已生成内容落盘。
* **平台差异是刻意的**：电脑版 / 安卓版共用 HTML 渲染层，鸿蒙版使用 ArkUI 原生界面；设置页、用量页与模式切换的交互形态按各端屏幕与系统能力分别实现，功能口径保持一致。
