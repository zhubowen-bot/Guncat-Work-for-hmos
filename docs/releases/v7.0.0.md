# Guncat Work 7.0.0

| 项目   | 内容                            |
| ---- | ----------------------------- |
| 版本   | 7.0.0                         |
| 发布日期 | 2026-10-28                    |
| 适用平台 | HarmonyOS · Windows · Android |

7.0.0 是 Guncat Work 的首个三端同版发布：Windows 与 Android 由此前的 0.2.1 测试版进入正式版，并与 HarmonyOS 统一版本号。变化集中在运行环境——HarmonyOS 版引入命令执行与进程内 CPython 3.12 运行时，手机端具备完整的 Linux 用户态与原生 Python 环境；Windows 与 Android 版补齐命令审批、后台任务与终端能力。功能层面，新增@ 引用工作区文件、编辑前读取校验与项目指令等功能。

## 主要更新

### 新增 Shell 命令执行

模型可直接调用系统命令行工具，管道、重定向、通配符与命令替换均为真实语义，`grep`、`sed`、`awk`、
`find`、`tar`、`xargs`、`sort`、`cut` 等标准工具可用。工作目录即会话工作区，因此 `cat data/a.csv`
与 `read_file("data/a.csv")` 指向同一文件。三端的运行环境不同：

| 平台        | 运行环境                                                      | 首次使用          |
| --------- | --------------------------------------------------------- | ------------- |
| HarmonyOS | QEMU 虚拟机内的 Alpine 3.22（内核 6.12），以 TCG 解释器（TCI）执行指令，不生成机器码 | 释放镜像并冷启动，约数十秒 |
| Windows   | 系统命令解释器（`cmd /d /s /c`）                                   | 无额外准备         |
| Android   | 内置 Termux 用户态；无可用 shell 时回退 `/system/bin/sh`              | 解压约 684 MB    |

共用语义：

- **输出有界**：stdout 与 stderr 各截断到 60 KB，全文写入工作区的 `.spill/` 供后续读取。
- **退出码**：非零退出码不判为工具失败（`grep` 无匹配返回 1 属正常语义），由模型结合 stderr 判断。
- **可扩展**：HarmonyOS 可用 `apk add`，Android 可用 `pkg install`，两者均可在 shell 内 `pip install`。

平台差异：

- **HarmonyOS**：工作区经 virtio-9p 挂载进虚拟机，虚拟机与工具层看到同一批文件，没有同步环节；
  镜像预装 python3、pip、jq 与 CA 证书；虚拟机内存 2 GB，空闲 10 分钟后关机释放，应用进程退出时
  虚拟机随之销毁；命令默认超时 60 秒，上限 240 秒。
- **Windows**：环境变量按白名单传递；超时后连同子进程一并终止。
- **Android**：Termux 用户态包含 bash、coreutils、grep / sed / awk、tar、curl、git、jq、sqlite3、
  apt / dpkg 与 Python 3.14；执行前将会话工作区写入设备目录，结束后回写；仅提供 arm64。

### 新增原生 Python（HarmonyOS）

Shell的引入带来强大的Python工具。Windows 使用机器上已安装的Python，Android 使用 Termux 自带的 Python 3.14 与预置库，可离线使用。

HarmonyOS 由于无法获取到JIT权限，在虚拟机内解释执行效率极低，因此引入了原生编译的CPython。

HarmonyOS 版的 `run_python` 使用在应用进程内执行的 CPython 3.12，而非虚拟机中的 `python3`。解释器
编译为 HarmonyOS 原生 `.so`（`libpython3.12.so`，5.8 MB；标准库 9.6 MB），中间没有指令翻译层，
CPU 密集型负载比虚拟机内的解释器快两到三个数量级。

- **运行参数**：工作目录为会话工作区；默认超时 30 秒，上限 180 秒；输出上限 20000 字符，超出部分写入 `.spill/`。
- **随包库**：numpy、pandas、scipy、matplotlib、lxml、sympy、python-docx、python-pptx；另有 regex、
  psutil、PyCryptodome、reportlab、watchdog、qrcode、XlsxWriter 与 `guncat_mp`。随包思源黑体，
  matplotlib 中文标签无需额外安装字体。
- **标准库补全**：`ssl`（含 118 张 CA 证书）、`sqlite3`、`bz2`、`lzma` 与完整 `zoneinfo` 时区数据。
- **`npy` 桥**：虚拟机内的 `npy` 把 Python 转发给宿主原生解释器，可在管道中使用（`npy gen.py | jq ...`）；
  单次往返约 134 ms，而在虚拟机内启动 `python3 -c pass` 需要 3.1 秒。
- **超时与隔离**：AST 截止检查在纯 Python 层抛出 `TimeoutError`，宿主在超过时限后放弃等待并拒绝本会话的
  新调用；每次调用前后对进程级状态做快照与回滚；安装目录只读。
- **内存**：调用结束清空上一次的全局字典，仅在 RSS 超过 400 MB 时触发 GC；matplotlib 字体缓存固定在
  应用 cache 目录；接近内存阈值时在结果前追加提示。

### 新增工作区引用、读取校验与项目指令

#### @ 引用工作区文件

- 输入 `@` 弹出文件候选（最多 8 项），选中后插入路径；发送时附加文件正文，会话记录保留原话。
- 预算为单文件 24000 字符、单轮 60000 字符、最多 8 份。
- 目录、二进制文件、不存在与越界路径均返回原因，越界路径不读取；邮箱与 URL 中的 `@` 不触发。
- 插话中同样可用；完整附上的文件按「已读取」登记，可直接编辑。

#### 编辑前读取校验

- `read_file`、`write_file`、`append_file` 成功后登记版本指纹，`edit`、`str_replace_editor` 执行前校验。
- 未读取返回 `FS_NOT_OBSERVED`，读取后文件发生变化返回 `FS_STALE_VERSION`，并给出「先读再改」指引。
- 指纹由文件大小、mtime 与首 8 KB 的 FNV-1a 组成；`delete_file`、`move_file` 清除登记。

#### 项目指令

- 工作区根目录的 `AGENTS.md`、`CLAUDE.md`、`GUNCAT.md` 作为项目指令提供给模型：开工前读取，
  「以后都按这个来」写入 `AGENTS.md`。
- 项目指令是数据而非权限，不能解除审批或扩大工作区范围；与用户当前消息冲突时以用户消息为准。
- Windows 与 Android 按会话快照注入；HarmonyOS 由提示词约束，模型自行读取。

### 新增命令审批（Windows / Android）

四档审批：`ask`、`ask-risk`、`auto`、`full-access`。163 条规则覆盖硬禁命令、危险操作、意图不明的写法、脚本内容、命令位、越界路径与编码载荷；`auto` 档由模型审阅，无法判定时转人工确认。

判定文本取三层：命令原文、去伪装还原（`^`、`@` 前缀、`%ComSpec%`、引号拆词）与脚本拆出的内容。
脚本按进程 cwd 与脚本所在目录分别解析，裸名按 `PATHEXT` 候选后缀查找；绝对 POSIX 路径落在工作区外
即判为危险。Android 与 Windows 共用同一判定层，判定逻辑可脱离真实进程断言。

HarmonyOS 不设审批：命令运行在仅挂载会话工作区的虚拟机内，破坏性操作限于虚拟机内部沙箱工作区，影响范围有限，考虑到此功能对性能造成的影响，设立危险命令审批的必要性不强。

### 新增后台任务（Windows / Android）

提供 `run_in_background`、`job_list`、`job_output`、`job_kill` 四个工具。单会话最多 8 个任务；输出写入
环形缓冲并落盘，读取带游标；应用重启后未结束的任务标记为「已中断」。Android 上息屏与切后台期间任务
继续执行，保活方式见「长任务保活」。

HarmonyOS 暂不提供后台任务功能。原因在于后台任务本身对性能负载要求较高；HarmonyOS 系统管控较严（不支持 JIT 等），虚拟机内命令执行与原生 CPython 运行的负载均偏高，内存压力较大，不适宜执行后台任务。

### 新增长任务保活

- **HarmonyOS**：前台运行期间保持屏幕常亮，流式回复与 Agent 循环不会因熄屏中断；切到后台时若流式仍
  在进行，申请数据搬运长时任务继续运行，回到前台立即释放。
- **Android**：以前台服务与常驻通知，配合部分唤醒锁、Wi-Fi 锁与电池优化白名单，息屏与切后台期间任务
  照常推进。
- **Windows**：不存在进程挂起，窗口最小化后继续执行。

### 新增预置服务商（HarmonyOS / Android）

- **预置方案**：Deepseek（Anthropic Messages，`deepseek-flash`）与 OpenCode Go（Anthropic Messages，`deepseek-v4.1-flash`）。启动时只补缺失项，已填 Key 的方案不覆盖。
- **旧配置迁移**：`https://api.deepseek.com` 方案并入 Deepseek 预置，Key、模型、参数与多模态配置一并
  迁移；正在使用的方案保留其当前模型。
- **多模型**：单个配置支持多个模型（`models` 列表可增删），旧存档的单 `model` 自动迁移。
- **选择器**：按「方案 × 模型」逐行展示，胶囊显示模型名，菜单显示服务商；未填 Key 的方案不出现。
- **配置管理**：可删除自建配置；默认配置与预置方案受保护；删除当前方案后自动切换到相邻方案。
- **会话头**：OpenCode Go 网关按文档补 `x-opencode-session` 会话头，绑定当前对话，流式对话、
  Agent Loop 与 Files API 三处统一注入。

### 优化多端适配体验

#### Windows

- **会话绑定磁盘目录**：会话可指定任意磁盘目录，一键恢复默认；侧栏文件树按需加载、按类型打开：
  图片进入灯箱，Markdown 走对话流渲染，代码高亮，Office 与 PDF 交给系统默认程序。
- **代码沙箱**：`run_js` 改由 `node:vm` 执行，死循环可被引擎中断，不再使用「放弃等待、后台继续占 CPU」的兜底。
- **凭据保险库**：API Key 经系统凭据库加密（`enc:v1:`）；跨机器解密失败时剔除对应项并提示；历史明文
  配置仍可读取，下次写盘转为密文。
- **分发与诊断**：提供便携目录与安装包两种形态；安装包支持 `--silent`、`--dir` 等静默参数，卸载可选
  是否删除本地数据；产物内含 `diagnose.cmd` / `diagnose.ps1`，另有兼容模式、管理员模式与桌面快捷方式脚本。

#### Android

- **窄屏界面**：会话抽屉、全屏工作区与设置、安全区适配、44 px 触控目标、16 px 输入字号、表格横向滚动、
  返回键分层处理；模型、推理强度、配置方案、接入方式、搜索引擎与命令审批统一使用底部选择器。
- **触屏交互**：不保留 hover 态；复制有原生桥回退；流式输出自动置底时不会打断正在拖动的选区。
- **设备接入**：原生相机（不依赖 AndroidX）、相册与文件选择、系统分享接收、系统 TTS 朗读、端侧语音
  识别（API 31 及以上，失败时回退服务商转写）。

#### HarmonyOS

- **搜索条数**：设置面板新增「单次结果条数」，范围 1~20，默认 8；读取时对历史值与字符串做夹取。

## 修复

### HarmonyOS

- **自动重试从未生效**：兜底 `catch` 把所有 `LoopError` 重新包成 `protocol`，429、5xx、传输中断与流截断
  在分类层即被判为不可重试，`RetryPolicy` 一次也未执行。现分类错误原样上抛，仅限流、服务端、传输与
  空响应进入重试；工作模式 5 次、聊天模式 3 次，`Retry-After` 单独封顶 60 秒；重试前清除上一次的半截
  输出，提示改为临时 toast，不再写入回答正文。
- **响应截断被当成正常结束**：三种协议此前只要 HTTP 200 且数据流结束就判定完成，半截正文进入会话，表现为
  任务静默停住。现要求收到终止事件（`finish_reason` / `[DONE]`、`message_stop` / `stop_reason`、
  `response.completed` / `response.incomplete`），否则按传输错误重试。
- **大请求体固定 30 秒超时**：使用 `view_image` 后请求体变大，连接阶段超时导致重复重连失败。
  `connectTimeout` 改为按请求体大小放大：256 KB 以内维持 30 秒，之后按约 100 KB/s 预留，封顶 180 秒。
- **重试重复携带内联图片**：传输或空响应失败后仍带着同一张图重试。现于重试前将内联图片从循环历史中移除并
  说明原因，由模型按需重新读取。
- **多图只送达最后一张**：一轮内多次调用 `view_image` 共用一个 `imageDataUrl`，后一次覆盖前一次。现按
  调用逐张追加为独立视觉消息，标注序号与来源路径；子代理同步修复。
- **大图无法送达**：超过 8 MB 的图片此前直接失败。现按 2048/90、1600/82、1280/72 逐级压缩，结果注明
  原图与压缩后大小；三档仍超限则如实报错，8 MB 以下按原图发送。
- **提问答案被丢弃**：`ask_user_question` 外层护栏 180 秒短于卡片 300 秒的等待，第 3~5 分钟作答不会送达。
  护栏提高到 360 秒，卡片不再在无人等待时继续显示。
- **跨会话消息误入其他会话**：A 会话执行中在 B 会话发送，消息被插入 A 的插话队列。现按运行期会话判定
  归属：其他会话发送时给出提示，提问卡与定时提醒只进入所属会话。
- **插话发送无响应**：执行中发送被界面层的 `isStreaming` 判断拦截，文字清空但任务无感知。现正常入队并回执
  「本轮执行完就接手」；插话只在轮边界注入，不打断在途工具与流式输出。
- **连续两次超时导致 Python 不可用**：软超时计数只增不减，两次后本会话所有 Python 调用被拒，只能重启
  应用。现仅统计软超时，任务结束即回退计数；原生侧在忙碌时直接拒绝新调用，不再覆盖队列槽位。
- **进程级状态跨调用泄漏**：`os.environ`、`sys.path`、`logging` 级别、`warnings.filters`、`random` 种子与
  numpy 打印选项在常驻解释器中保留到下一次调用。现每次调用前后快照与回滚，`sys.modules` 导入缓存保留。
- **输出捕获不完整**：`sys.stdout` 为裸 `StringIO`，`os.write(1, …)` 绕过捕获漏到宿主 stdout。现把
  fd 1/2 `dup2` 到真实文件并以 `TextIOWrapper` 包装，`print`、`buffer.write`、`fileno()` 与 `os.write`
  均落入同一份输出。
- **解释器安装目录可写**：`sys.prefix` 下的文件对此后每次调用、每个会话生效，写入即构成跨会话代码注入。
  现以审计钩子拦截写操作并抛出 `PermissionError`，读取与工作区写入不受影响。
- **`multiprocessing` spawn 静默失败**：嵌入式解释器没有可重新执行的 Python 主体，子进程以
  `exitcode=255` 结束且 `start()` / `join()` 不抛异常。现于首次 import 后替换 `spawn.get_executable`，
  直接抛出说明改用 fork、`guncat_mp` 或线程的 `RuntimeError`。
- **Python 闪退**：6 份崩溃日志堆栈一致（`SIGSYS(SYS_SECCOMP)`，syscall 235），根因是 OpenBLAS 在
  `blas_memory_alloc` 中调用 `mbind` 被沙箱拒绝。已避开该路径，同时修复 extras 未解压与
  `guncat_mp.available()` 恒为真的探测缺陷。
- **工作区残留**：删除会话时若任务仍在运行，收尾阶段会把刚删除的目录写回。现删除前停止任务、收尾补删，
  并在会话存档读取成功时清扫孤儿工作区与会话日志；空会话自动清理时同步删除目录。
- **交互卡片渲染回归**：围栏判定收紧后，交互模式整条消息不再渲染卡片；现恢复空 info 围栏并补充构建
  路径。工作模式改为结构性禁用卡片，不再出现不属于它的交互卡片。

### Windows

- **流式超时**：`readTimeout` 曾按整段时长计时，工作模式 5 分钟、聊天模式 3 分钟必被中断。改为按读空闲
  计时，另设 `connectTimeout` 覆盖等待响应头阶段。
- **定时提醒**：到期无动作，模型承诺的定时提醒不会发生。现每秒推进，到期注入提醒并唤醒工作循环。
- **第二轮丢失上下文**：`runWork` 每次开任务重建循环消息，只带本轮一句。现重放历史正文，不搬 `toolCalls`，
  避免工具结果撑爆预算与协议断链。
- **PDF 解析**：后端缺失（`backend === null`），任何 PDF、任何来源都返回「文档结构损坏」。现接入 PDF.js
  与 canvas 渲染。
- **SVG 栅格化**：`nativeImage` 只解码位图，输入 SVG 必然失败；改用 canvas 的 `loadImage`。
- **Mermaid 图表偶发退回源码**：三个独立原因分别导致不渲染——模型输出 Unicode 箭头、同帧挂载的两张图生成
  同一毫秒 id、`render` 不可重入导致多图与流式重绘互踩。现分别做箭头归一化、模块级自增 id 与串行排队，
  排队期间被新 token 顶掉的重绘直接跳过。
- **无语言标记的代码围栏**：此前被当成界面围栏，工具回显、公式与命令示例各画一个空块并吃掉正文；
  现按内容判定，不像程序则交回 Markdown 渲染。
- **停止状态显示**：轮次正文末尾标注停止、上限或失败，折叠栏标题改为「已停止」。
- **推理强度档位**：档位曾写死在主进程，工作模式拿不到 Max；现按形态分键持久化，顶栏与设置均可选。
- **设置面板**：修复一处静默丢配置；占位符与多模态字段按接入方式整组显隐。

### Android

- **流式超时**：与 Windows 同因（按总时长计时），改为读空闲计时，长流式不再因总时长被掐断。
- **响应截断重试**：必须收到终止事件才算完成，否则按传输错误重试。
- **选择器文件**：选择器返回的是一次性 `File`，内核只认路径；改为先落盘到工作区再交给内核。

## 升级说明

- **HarmonyOS**：HAP 未签名，需自行签名后安装；首次执行命令触发镜像释放与冷启动（数十秒）；运行库
  版本变化时会重新释放镜像。
- **Windows**：可直接覆盖安装；首次启动出现一次自我重启属预期（`--no-sandbox` 在真实命令行生效）；
  明文 API Key 在下次写盘时转为密文，跨机器复制的配置中无法解密的条目会被剔除并提示重新填写。
- **Android**：首次使用内置终端解压约 684 MB；`pkg install` 安装的包路径写死 `com.termux`，不保证直接
  可用；`targetSdk 28` 是执行私有目录二进制的前提，仅适合 sideload。
- **配置迁移**：模型配置自动迁移，旧存档的单模型转为 `models` 列表；HarmonyOS 的旧 Deepseek 方案并入
  预置方案。

## 数据与隐私

- 对话记录、工作区文件与会话日志保存在应用私有目录；删除会话时同步删除对应工作区，启动时清理历史
  残留产生的孤儿目录（HarmonyOS）。
- 模型请求与所附文件只发送到用户自行配置的模型服务。
- Windows 的 API Key 经系统凭据库加密后落盘（`enc:v1:`），历史明文配置在下次写入时转为密文。
- 命令执行的环境隔离：HarmonyOS 的命令运行在仅挂载会话工作区的虚拟机内；`run_python` 的安装目录
  （标准库与三方库）只读。
