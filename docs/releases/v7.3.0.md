# Version 7.3.0 发布说明

**发布日期：2026-11-09**

Version 7.3.0 把两件以前只能在每轮对话里反复交代的事做成设置项：新增「个性化指令」，保存后按生效范围自动拼进系统提示词；交互模式新增「能力调度」九档提示词，从轻简到专家按任务挑一套成熟提示词。鸿蒙版另把输入区改成悬浮式容器，并修好空输入框被「停止」按钮挤成两行的问题。三端版本号同步到 7.3.0。

**自 Version 7.2.0-beta 1 起，各仓库的 Release 将仅提供与该仓库对应的发布包。例如，hmos 仓库仅提供鸿蒙版 HAP 发布包，不再同时提供电脑版、安卓版发布包。如需其他平台的发布包，请前往对应仓库的 Release 页面获取。**

**同时，鸿蒙版开始提供永久邀请测试分享链接，可以直接通过官方渠道获取最新测试版本：https://appgallery.huawei.com/apptest/955nTWBlvx0**

## 一、个性化指令（全平台）

在设置里维护一组长期生效的偏好，保存后自动追加到所选范围的系统提示词末尾，不必每轮重复说。

### 入口、列表与编辑

* **入口**：电脑版在设置「模型与能力」分组（「高级模型参数」之后、「能力调度」之前），安卓版与鸿蒙版在设置「能力」分组（鸿蒙版为分组第一行）。根行副标题显示「尚未添加」或「共 N 条 · 自动拼进生效提示词」，列表逐条显示名称（未填名称时取正文第一条非空行）、生效范围摘要与正文摘要，右上角可新建、点条目编辑。
* **编辑页**：名称可选填（40 字上限）；正文 8000 字上限，支持 Markdown。「Markdown 渲染」只切换编辑页的原文 / 渲染预览，默认不渲染，纯文本也能直接保存——落盘的始终是用户原文，不因开关改变内容。
* **保存与删除**：点「添加」/「保存」才写入；编辑态可删除（页内二次确认）；有未保存修改时返回会先提示放弃编辑。

### 生效范围与拼装方式

* **范围多选**：交互模式、工作模式与每个聊天引擎。电脑版列出 `agents.json` 里全部 9 个聊天引擎（轻简 / 效率 / 专家 / 经典，加上论文转换、法律检索、深度研究、信息筛滤、LLM评估五个专项引擎）；安卓版与鸿蒙版同样覆盖交互、工作与各聊天引擎。新建时默认勾选交互模式与工作模式，至少选一项才能保存。
* **追加位置**：保存后从下一次请求开始，在所选范围的系统提示词**末尾**追加「# 个性化指令（用户在设置中添加）」段落；每条正文包在 `<personal-instruction>` 标签里（填了名称时带 `name` 属性），并说明这些内容是长期用户偏好、不是新任务、与安全 / 事实纪律冲突时以后者为准。同一范围多条按添加顺序拼接。
* **三条请求路径**：交互模式、工作模式（含上下文压缩后重建的提示词）与各聊天引擎都会补回这一段。原有提示词前缀逐字节不变、只在结尾追加，指令不改时相邻轮次仍能命中模型侧 KV 缓存；改指令只影响最后一段。

### 保存位置与边界

* **只在本机**：指令保存在本机偏好（键 `guncat_personal_instructions`），不上传、不云同步；清除应用数据或卸载后随之丢失。
* **长度预算**：单条正文 8000 字，拼进提示词的总预算 16000 字符，超出按添加顺序截断并在提示词里标注。
* **作用范围**：只作用于主对话请求，不注入子代理、会话标题生成、上下文摘要、多模态解析、交互模式界面补救这类内部辅助请求；不改变工具面与权限。

## 二、交互模式「能力调度」九档提示词（全平台）

* **九档选择**：设置 →「模型与能力 / 能力」→「能力调度」新增九档——轻简 / 效率 / 专家 / 经典 / 论文转换 / 法律检索 / 深度研究 / 信息筛滤 / LLM评估，默认「轻简」。档位只影响交互模式，工作模式与聊天模式不受影响；切档从下一轮任务生效，缺档位主体时自动回退轻简，不会交付没有业务主体的空壳档位。
* **轻简档原样保留**：直接复用原交互模式提示词，组装结果与旧四段逐字节一致（电脑版与安卓版有断言钉住），行为与速度不变。
* **其余八档移植成熟提示词**：把聊天引擎对应智能体的提示词**主体**移植进交互模式，角色、思维链、执行模式、反幻觉体系、工作流、输出模板与知识库逐字保留，只做交付形态适配——文字用界面组件承载、mermaid 由界面分层替代、确认参数改界面表单、平台工具映射为该端交互模式的真实工具，并按档位追加推荐思考强度。
* **丰富度口径**：八档把「输出丰富度原则」落成交互模式计量——组件、卡片、图表、分层与每块内容长度越多越好，12~20+ 个组件是常态、不设上限；轻简档保持原「典型 8~14 个组件、够用为准」。

### 工具面按档位只增不删

* **基础工具面**：电脑版 28 个（比另两端多一个 Word 导出渲染通道 `docx_render`），安卓版与鸿蒙版 27 个，均为物理裁剪的白名单。
* **档位追加**：效率 / 经典 / 信息筛滤追加 `record_search`；专家 / 法律检索 / 深度研究 / LLM评估追加 `record_search` 与 `todo_write`。对应数量：电脑版 28 → 29 → 30，安卓版与鸿蒙版 27 → 28 → 29；轻简与论文转换保持基础数量。
* **始终不下发**：`goal_*`、`schedule_*`、`session_search`、`subagent` 等长程维护类工具在任何档位都不下发（电脑版另含 `edit`、`shell`），切档只改变追加项，不改变物理裁剪的事实。

### 组件清单修正

* **列表与追问分组名对齐（三端）**：修正「列表与追问」分组名与分组定义不一致的问题——该组此前被整组静默丢弃，`ListBlock` / `ListItem` 从未出现在任何档位的组件清单里；对齐后九档清单都包含它们。组件库三端同源、注册 77 个；电脑版提示词清单可见 75 个（`FollowUpBlock` / `FollowUpItem` 按既有规则不发进提示词），安卓版与鸿蒙版 77 个全部可见。
* **RadarChart 补登记（电脑版 / 鸿蒙版）**：渲染层早已支持雷达图，但提示词组件清单一直漏登记，「多维对比 → 雷达图」的建议此前实际点不到该组件；本次补上说明后九档均可正常使用。安卓版此前已登记雷达图，本次没有变化。

### 提示词可核对

* **说明与导出**：新增《交互模式 · 能力调度档位提示词适配说明》与九档完整组合提示词导出（电脑版见 `docs/prompts/interactive-tier-adaptation.md`、`docs/prompts/interactive-tiers/` 与轻简档预览 `docs/interactive-prompt-preview.md`；安卓版见 `docs/prompts/`；鸿蒙版见 `docs/prompts/` 与 `test/guncat-harness/dump-interactive-tiers.mjs`），说明每档保留了什么、适配了哪些锚点、各自的工具面与思考强度，以及三端实现差异。
* **可重新生成**：导出脚本从真实模块 + 档位主体重新组装，改代码或档位主体后重跑即可刷新；电脑版脚本自带轻简档逐字节一致、段拼接、缺主体抛错三道自检。

## 三、输入区悬浮式改版（HarmonyOS 版）

* **输入容器包裹按钮**：输入框改为一个大圆角悬浮容器，文字独占一行，语音 / 拍照 / 附件 / 发送（执行中为插话 / 停止）收进容器底栏；每个按钮不再各带一层白色小圆底与投影，只保留图标本身，发送键保留一块主色圆底作为主操作。
* **上方胶囊独立悬浮**：模型选择、联网搜索、深度思考 / 工作区从「一整条工具栏」改成相互独立、彼此留出间距的小号悬浮胶囊，按内容取宽、靠左排列（不再铺满整行），并比输入容器再稍微右缩一点；高度、字号、圆角与投影统一。
* **去掉底部色块**：底部输入区不再铺独立的 surface 底色和上边缘阴影，背景与页面整体一致，悬浮层次改由容器与胶囊自身的圆角、描边和柔和阴影呈现，深浅色模式沿用同一套主题色。
* **字号与比例**：输入正文与占位文字统一为 16fp（原 15fp，占位文字不再靠缩字号塞进一行），单行高度、多行草稿展开上限与按钮尺寸一起放大；空输入框仍固定一行，发送 / 插话 / 停止等状态与操作路径不变。
* **键盘弹出时整块输入区可用**：输入区改成「文本 + 底栏按钮」的复合块后，页面改为按键盘高度压缩布局；键盘弹起时语音 / 拍照 / 附件 / 发送不再被键盘盖住，输入过程中也能直接操作。

## 四、空输入框固定单行（HarmonyOS 版）

* **问题**：交互模式 / 工作模式任务执行中，输入行右侧会多出「停止」按钮，输入框被挤窄后占位文字曾折成两行，把空输入框撑成两行高，与顶部的悬浮胶囊叠在一起。
* **修复**：占位文字与正文同字号，去掉末尾省略号（「描述问题」/「描述任务」/「输入消息」），空输入框固定保持一行；用户输入多行草稿时仍照常向上展开。

## 七、说明与边界

* **个性化指令只在本机**：不云同步、不上传；清除应用数据或卸载后丢失。单条 8000 字、总预算 16000 字符，超出按添加顺序截断并标注。
* **只作用于主对话**：不注入子代理、标题生成、上下文摘要等内部辅助请求，不改变工具面与权限；需要影响子代理行为时，仍应在对应请求里直接说明。
* **能力调度只影响交互模式**：工作模式与聊天模式使用各自智能体的原始提示词；切档从下一轮任务生效，缺主体自动回退轻简。
* **工具面差异是刻意的**：电脑版基础 28 个工具（含 `docx_render`），安卓版与鸿蒙版 27 个，是渲染层能力差异，不是功能缺口；长程维护类工具在任何档位都不下发。
* **输入区改版只在鸿蒙版**：电脑版与安卓版共用 HTML 渲染层，输入区形态本轮未变；鸿蒙版为 ArkUI 原生界面，按原生控件与键盘行为重做。
* **产物**：鸿蒙版 HAP 未签名，需自行签名后安装；安卓版 versionCode 由构建时间生成，仅本安装包有效。各仓库 Release 只提供本平台发布包，其他平台请到对应仓库获取。
