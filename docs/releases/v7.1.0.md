## 一、Agent 内核：跨轮次思考记忆

> **平台：电脑版 · 安卓版 · 鸿蒙版（三端同步）**

**问题根因**：历史轮次的 `reasoning` 一直存在会话里，但重建请求时被整段丢掉——工作 / 交互模式只搬正文；Chat Completions 请求体里普通 assistant 消息不写 `reasoning_content`，聊天模式还只在服务端联网搜索开启时才回传；Anthropic 的 thinking 签名只存内存、没随消息落盘；Responses 的 reasoning output item 则完全没有保存。

结果是**第二轮起模型看不到自己上一轮推理过的结论**；带 `tools` 的 DeepSeek 思考模式甚至会直接 400。

**修复：三种协议按各自规范回传**

- **OpenAI 兼容 Chat Completions**：历史 assistant 的 `reasoning_content` 一律回传，带 `tool_calls` 的消息也带；无论请求是否携带 `tools` 都不跳过（不带时服务端自动忽略）。
- **Anthropic Messages**：`thinking` 块随历史回传并置于消息首位，`signature` 与 `redacted_thinking` 随消息持久化、跨轮次与重启后原样带回；DeepSeek / Opencode 等兼容端点接受无签名块，官方 `api.anthropic.com` 仅对「历史 + 无签名」跳过。历史被修剪 / 摘要压缩 / 整条裁剪后旧签名绑定的前缀已失效，会先清掉再发，避免 `Invalid signature` 400。
- **OpenAI / DeepSeek Responses**：保存 `response.output_item.done` 里的 reasoning item，下一轮原样作为 `reasoning` input item 回传；DeepSeek 等兼容端点额外支持明文 `content` 兜底，官方 OpenAI 只回传带 `id` / `encrypted_content` 的原始 item。请求同时声明 `include: ["reasoning.encrypted_content"]`。

**顺带**：只有思考、没有正文的 assistant 历史消息不再整条跳过；思考内容全量落盘并计入上下文预算，长任务不会因为多带思考而悄悄超出预算。

## 二、Word 工具链：公式修复与写盘前自检

> **平台：电脑版 · 安卓版 · 鸿蒙版（三端同步）**
> `OmmlConverter` / `DocxBuilder` 三端共用同一份实现，本次按真机自检报告里的 8 类公式问题逐条修正。

- **命令后的上下标不再被吞**：`\mu_0`、`\alpha_2`、`\bar{I}^2`、`\left(...\right)^2` 此前会丢失并留下空 `m:t`。现在命令、字符、`{...}` 组、`\left...\right` 定界符统一走「原子 + 上下标」绑定路径；`\sum` 等 nary 没有上下限时改用合法的 `<m:sub/>` / `<m:sup/>`。
- **矩阵与对齐**：`bmatrix` 右定界符改为 `]`（此前左右都写成 `[`）；`cases` 生成左大括号而不是裸矩阵；`aligned` / `align` / `split` 改用 `m:eqArr`，不再退化成两列矩阵，等号能对齐；`array` / `alignedat` 的列格式参数不再混进公式正文。
- **单位与范数**：`\mathrm{m/s^2}` 先按数学解析再套正体，`^` 不再原样漏出；`\|` 映射为 `‖` 并把下标绑到双竖线上。
- **符号缺失**：命名定界符（`\langle` / `\lfloor` / `\rfloor` / `\mid`）不再被截成字母，直接映射为符号；`\mathbb{R}^n` 的空心体与上标都保留。
- **常见写法有明确处理**：未知环境、`\tag{}`、`\hline`、`\not=`、`\overset`、`\underbrace`、`\boxed` 等不再静默漏进正文。
- **写盘前自检**：`write_docx` / `edit_docx` 在写盘前扫描 `document.xml`，空 `m:t`、LaTeX 残留、未识别命令、公式父元素不合规都会**拒绝写盘**并返回具体原因（含示例命令），不再出现“已生成 xxx.docx”但文件里是坏公式的情况。
- **返回值给证据**：成功时附带可核对的自检结果，例如 `2 公式段 / 4 行内公式 / 空 m:t 节点 0 / LaTeX 残留 0 / 未识别命令 0`。
- **结构与字体**（电脑版 / 安卓版记录）：`\bar` / `\overline` 改用一层 `m:bar`，不再重复上划线；`\underbrace` 用合法的 `m:groupChr`；`m:oMath` / `m:oMathPara` 直接挂在 `w:p` 下；普通文本按字符范围拆 run——CJK 用宋体、Unicode 下标/数学符号用 Cambria Math，`Uₐ` 不再因缺字形变成 `U`。

### 平台差异：`docx_render`

> **仅电脑版新增**

- **电脑版**：新增 `docx_render(path, page?, page_count?, width?)`，把 .docx 经 LibreOffice（优先）或 Microsoft Word COM 转 PDF，再用 PDF.js 逐页渲染成 `docx_render/<文件名>/pNNN.png`，返回图片路径供 `view_image` 自查；未安装 LibreOffice/Word 时返回明确错误，结构自检不依赖渲染。
- **安卓版**：**不提供**该工具——内置 Shell 明确不支持 `libreoffice` / `soffice`，也没有 Word COM，避免提供一个必然失败的能力。
- **鸿蒙版**：本次更新记录未包含该工具。

## 三、交互模式：`TextContent` 的 Markdown 现在真的会渲染

> **平台：电脑版 · 安卓版**（两端共用同一份渲染层，修复完全一致；鸿蒙版此前版本已修复此问题）

组件契约明确允许行内 `**粗体**`、`[链接](…)` 与 `` `行内代码` ``，但渲染层 `renderNode` 直接输出了原始字符串——用户看到的是 `**1,284 万**` 而不是加粗数字。

现在 `TextContent` 改走与消息正文相同的 Markdown 管线（CommonMark + GFM + LaTeX），行内语法与段落、列表、表格、代码块等块级语法一次性对齐；`size` 档位与卡片内排版保持不变，并为 Markdown 生成的段落补上首尾边距归零规则。`MarkDownRenderer` 仍是需要完整排版时的首选组件。

## 四、工具注册：插件热加载后核心工具定义不再丢失

> **平台：仅电脑版**

插件热加载会先把 `ToolRegistry.synced` 置 true，导致之后核心工具定义不再补同步，schema 校验、只读/变更标记与工具清单都可能缺失。现在核心工具用独立标记 + 幂等 `sync` 补同步，插件与核心工具可以共存。
