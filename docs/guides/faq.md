# 常见问题与排障

> [← 返回 README](../../README.md)

## 常见问题

### API Key 无效

- 检查是否带有多余空格。
- 确认模型、接入方式与 Base URL 匹配。
- 检查账户额度、接口权限和网络连接。

### 文件解析失败

- 确认格式和文件大小受模型接口支持。
- 检查多模态配置是否正确。
- 可以关闭预解析，改用支持附件直传的 Responses API 模型。

### 流式输出中断

- 检查网络稳定性及服务端限流信息。
- 尝试切换 API 配置。
- 对简单问题关闭深度思考可减少响应等待。

### 图库分享列表中没有 Guncat Work

- 确认安装的是包含 Share Kit UTD 声明的最新 HAP。
- 更新安装后重新打开图库分享面板，让系统刷新分享目标。

### 交互模式的界面没出来 / 只出了一部分 / 显示「界面未写完」

- **界面在写的过程中就成形**：第一行 `root = Card([...])` 先渲染外壳，后面的语句逐条补齐，所以"看起来还没出来"通常只是刚开始写。
- **显示「界面未写完，以上为已生成的部分」**：模型输出被截断或中断，**已写完的语句全部照常渲染**（这是按行语句相对单块 JSON 的核心优势）。多数情况不用你处理——若模型压根没产出可用界面，应用会自动单独请求一次（会话里会出现「（界面已重新生成）」）。仍不完整时回一句「继续」或「重新生成一版更简短的界面」；反复被截断说明单次输出太长，可以让它少放几个组件、或分两轮给。
- **界面是空的（只有「这段界面没能渲染成可交互组件，可以让我重新生成一次。」）**：点开底部的「查看原始输出」看模型到底写了什么；若有「诊断 · N 条」面板，点开能看到具体原因，最常见的是**用了组件清单以外的组件名**（未知组件会被丢弃，避免渲染成莫名空卡片）。
- **常见的写法错误**（会出现在诊断里）：忘了第一行 `root = Card([...])`；参数写成键值 `CardHeader(title: "x")`（必须是位置参数）；定义了变量却忘了放进 `root` 的子项数组（未引用的语句不会渲染）；组件名不在清单里。
- **控件点了没反应**：只有**最新一条**界面可交互（历史界面自动置灰归档），且界面没写完时控件也是灰的；此外「回传模型」的动作只在交互模式下生效（聊天模式里出现的界面只能本地调参）。
- **参数调了但数字没变**：只有绑定了 `$变量` 的控件才会实时重算（`Slider(..., $amount)`），且表达式里要真的引用它（`"金额 " + $amount`）。让模型"把这个数值也做成可调的"即可。
- **它为什么在调工具，而不是直接给界面？**：交互模式的设计是**默认零工具、一轮直出**（工具只在"界面必须引用工作区真实数据"时破例，一轮最多 1~2 次）。如果它明显在跑一串和界面无关的调用（建清单、加载技能、反复核验），先确认没切到工作模式；再看提示词是不是仍然由 `PromptBuilder.assembleInteractiveSystemPrompt()` 组装成「**最前方的一级标题「最高优先级 · 快」** + 界面语言契约 + 快车道底座 + `INTERACTIVE_DUTY`」四段（**顺序不能变**：纪律必须在第 0 段，否则模型要先读完 8k 组件清单才看到"要快"），以及**下发的工具面是否仍然是裁剪后的 27 个**（`ToolRegistry.INTERACTIVE_TOOL_WHITELIST` → `AgentLoopService.toolDefsForMode(conv.mode, ...)`）——把 `PromptBuilder.build()`（工作模式底座）拼回去、让别的段插到"快"前面、或让交互模式重新拿到全量 47 个工具定义，都会让它重新开始跑长程流程。这也是 `test-core.mjs` 里"快车道不复用工作模式的行为纪律""「快」在组装后的提示词里就是第一段"与"47→27 工具面裁剪"几组断言专门拦的情况。

## 设置与用量

### 设置没有保存按钮，会不会丢？

- 设置页已改为自动保存：输入停顿后防抖写盘，返回或切换配置方案前会再同步一次。正常返回不会丢。
- 如果修改后直接强杀应用，最后一次防抖窗口内的输入可能来不及落盘；重新进入设置确认一遍即可。
- 设置页没有独立的「放弃」按钮；如果不想保留修改，需要在返回前手动改回原值，否则停在页面上的修改会被自动保存。

### 用量与成本为什么和账单不完全一致？

- 账本只统计**本应用内完成且服务端返回 `usage` 的请求**；缺失 `usage` 的响应会计数但不猜成本，第三方客户端或其他设备的调用不在账本内。
- DeepSeek 按北京时间峰谷与内置节假日表估算；OpenCode 以网关返回的额度 / 成本字段为准。两边都不是官方账单，只作本地对账。
- DeepSeek 余额改为手动刷新，仅作对账，不参与热力图与每日统计。清除统计会清空本机账本，操作前可先导出 CSV。

### 「检查更新」打不开 AppTest

- 应用会优先用 `apptest://` 拉起 AppTest；未安装时自动回退到官方公开链接，由页面引导安装或查看测试版本。
- 如果系统仍提示链接无法打开，先确认已安装最新 AppTest，或直接打开回退的公开链接。

### 工具目录为什么不能开关工具？

- 「系统 → 工具」是只读目录，页首的「工具自动管理」只是状态说明，不是设置项。工具由软件统一调度、按需加载；目录使用静态快照，打开页面不会构造工具定义或发起请求。

## 后台任务与落盘

- 手机端没有对第三方开放的通用计算保活，长任务不承诺永不回收；退后台会先申请短时任务，再按设备申请长时任务。详见[后台保活策略](../architecture/background-keepalive.md)。
- 流式内容每 5 秒增量落盘，切后台、停止生成、退出前再强制 flush；即使进程被系统回收，已生成内容通常不会整段丢失。
- 如果回前台发现任务停了，先看通知栏长时任务是否被系统或用户取消；被取消后应用只会在「系统取消且任务仍在跑」时重试一次。

## 后台朗读停止

- 确认应用通知和后台运行权限未被系统限制。
- 不同机型的后台策略和可用系统音色可能不同。
