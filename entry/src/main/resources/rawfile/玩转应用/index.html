Guncat Work
关于 Guncat Work
Guncat Work 是整合多项前沿技术打造的新一代智能体平台，能力分为三条主线：
① 交互模式（Agent 引擎 · 推荐）：把一句话直接变成能看、能点、能拖的原生界面——图表、指标卡、表格、表单，调参即时重算，也是应用启动后的默认入口；
② 工作模式（Agent 引擎）：同一套引擎的另一种交付形态，调用数十种工具与技能，端到端产出 Word、Excel、PPT 等成品文件；
③ 聊天引擎：4 个通用对话智能体 + 5 个专家智能体，体验是传统的「提出问题→给出回答」，一轮问答即交付。
适配网页端、安卓端、鸿蒙手机、鸿蒙PC等多端，为用户提供便捷的智能体服务。
三大能力体系怎么分工
应用的能力分成两套引擎：Agent 引擎（交互模式 + 工作模式）与聊天引擎。
交互模式与工作模式共用同一套 Agent 循环、同一个沙箱工作区与同一套数十种工具，差别在「交付什么」和「怎么干」：交互模式的交付物是界面，默认零工具、一轮直出；工作模式的交付物是文件成品，多轮工具循环、长程推进。
聊天引擎是另一条线：不读写工作区文件、不产出成品文件，只把问题答好，适合想要一段纯文字回答的场合。
一句话选型：日常提问、试算、对比、看数据 → 交互模式；要正式文件的长程任务 → 工作模式；只想聊天式问答或指定某位专家 → 聊天引擎。

基础功能
开关深度思考（聊天引擎）
聊天引擎保留可手动开关的「深度思考」。开启后更擅长应对高复杂度问题，处理数学计算、文稿撰写、资料调研、数据分析等任务时，以及使用垂直专家智能体时，建议启用该能力。
聊天引擎中的三种通用智能体可自动管理深度思考能力：轻简模式与效率模式自动关闭，专家模式则自动开启。其他智能体不支持自动开关深度思考。
思考强度：按模式分档（Agent 引擎）
交互模式与工作模式的深度思考都强制开启（工具行不再显示该开关），思考强度在模型胶囊的「能力预设」里切换。两个模式的档位各自保存、互不影响。
工作模式提供三档：极高（Max）、均衡（High）、快速（Low）。极高档追求极致的交付质量，但交付时间较长；快速档交付更快，质量有所下降。
交互模式提供三档：均衡（High）、快速（Low）、关闭（Off），并且默认落在快速档——它的交付物是界面，「快」比「多思考两秒」更重要。
「关闭」只作用于交互模式，不会把工作模式或聊天引擎的深度思考一起关掉。
联网搜索：建议开启
* 自 6.1.2 版本开始，新增本机内置联网搜索兜底能力，不支持关闭。“联网搜索”开关仍控制 API 服务端联网能力；
联网搜索默认开启，建议不要手动关闭。关闭联网搜索后，模型无法获取实时网络信息，回答仅依赖过时的知识库。自6.1.2版本开始，关闭联网搜索开关后通过本地联网搜索仍可获取实时网络信息，但仍然建议您开启该开关，以获得最高的性价比和搜索质量。
联网搜索不属于本地工具，可用能力取决于对接的 API 平台，部分平台不支持该功能就会调用报错。
DeepSeek 、火山方舟等不少 API 平台在使用 OpenAI‑Completions 协议时可能报错，接入联网搜索更推荐选用 OpenAI‑Responses 或 Anthropic‑Messages 协议。
图片与文件的支持能力
点击拍照按钮可拍照上传照片，点击文件按钮可上传本地图片和文件。交互模式与工作模式还可在工作区面板上传文件。

对于交互模式与工作模式，上传的文件会被保存到工作区沙箱，模型可调用工具对文件进行读写操作，你可以自由上传图片、PDF、Office 文档或代码文件等任意文件。

交互模式的回答通常秒级返回（默认零工具、一轮直出），一般不需要后台等待；需要长时间执行的多文件任务请交给工作模式。

快速上手
日常提问与试算：交互模式
帮我算一下 30 万房贷在不同利率下的月供；对比这三个方案并让我调参数；把这段数据做成能筛选的表格——这类问题的答案本来就是「一张表、一张图、一个能拖的滑块」，用文字描述既啰嗦又不好用。
交互模式把答案直接交付成界面：指标卡给结论、图表给趋势、表格给明细，滑块和选项就地调参、界面即时重算。应用启动默认就落在交互模式，打开即用。
它默认不调用任何工具、一轮直出，所以响应很快；只有界面里的数字必须来自工作区真实文件时，才会破例读一次文件或算一次。
长程任务交付：工作模式
- 请结合参考资料①②，为我生成心得体会。
- 请根据根据这些电脑的价格截图，为我判断哪一款性价比最高。
- 请结合现有法律法规和标准体系，为我创作关于人工智能合规性审查的调研报告和对应的PPT。
- 请为我做一个从峨眉坐火车到青海五天四晚游的行程攻略。
这些任务需要涉及多样的参考资料，或是多步骤拆解、分段执行的复杂目标，依靠单次简短对话无法完成。工作模式下将自主梳理任务流程、分阶段完成信息整理、对比分析与内容创作，持续推进直至交付一份结构完整、结果可用的成品文件（docx / xlsx / pptx）。适合报告撰写、方案规划、对比研判等具备完整交付目标的工作场景。
使用聊天引擎（不推荐）
* 自 6.3.0 版本开始，不再推荐使用聊天引擎的所有模式。
对于日常生活问答，交互模式提供可视化和交互性都更强的体验，同时兼顾快速与准确性；
对于专业任务，工作模式提供更强的处理能力和更高的生成质量，还能实现Office等文件端到端交付；
原有五大专家智能体的能力也已经包含在交互模式和工作模式的技能中，面对专业知识可获得更加专业的回答。
工作模式
工作模式是什么
工作模式是 Agent 引擎下的第二种交付形态：交互模式是「一句话→一张界面」，工作模式则是「布置任务→交付结果」；再往下的聊天引擎则是「提出问题→给出回答」。它们并列存在，随时切换。
它拥有一个本地沙箱工作区和数十种工具，接到任务后按「思考→调用工具→观察结果→更新清单」的多轮循环自主推进，不用你一步步指挥，就能处理文件、搜集资料、分析数据、写长文，搞定整套复杂的长线工作。
适合报告撰写、方案规划、资料调研、数据分析等具备完整交付目标的场景。虽然工作时长较长，但是支持后台运行——交完任务你可以去干别的，回来验收成品即可。
布置一个任务的流程
① 点空态大标题处的「工作模式」一档即可换挡（应用启动默认落在交互模式；也可以走侧边栏「Agent引擎（推荐）」分组里的「工作模式」，它排在「交互模式」下方），页面标题与空态随之切换为工作模式。
② 需要材料时，通过工作区面板「上传」添加文件。上传的文件保存到工作区沙箱，智能体可用工具读写。
③ 在输入框描述任务，越具体越好：目标是什么、材料在哪里、要什么格式、有什么口径。遇到影响方向的关键选择，它也会主动弹出问题卡片问你（见「向你提问」一节）。
④ 复杂任务会先建立任务清单，再逐项调用工具执行；时间线实时展示每一步的思考、工具调用与产出，点击任意工具步骤可展开参数与结果。
⑤ 任务执行中你可以继续发消息补充要求：消息不会打断任务，会在本轮结束后作为「用户补充」自动纳入下一步执行。
⑥ 完成后输出详尽总结，附每个产出文件的路径与用途；点击右上角「导出」可把整个工作区打包为 .zip 保存。
若任务被中断（关闭应用、断网等），重新打开后发送「继续任务」，它会接着之前的进度继续执行。
工作模式干活的原理
工作模式的底层是一个 Agent 循环（Agent Loop）。
系统同时赋予它四种角色：规划者（动手前拆解任务、编排工具、预估步数）、指挥者（按信息缺口推进，一步到位不绕路）、执行者（亲自调用工具、亲自阅读、亲自验证）、终验者（所有结论有依据、有验证之后才交付）。
标准工作流程：需求分析→规划（复杂任务先建任务清单）→逐项执行（每一次工具调用都为明确的信息缺口服务）→观察与更新（每次工具返回后核对是否覆盖缺口）→终验（确认产出物存在且非空、抽查关键内容）→收口输出总结。
沙箱工作区保障绝对安全
每个工作会话绑定一个独立的沙箱工作区，所有文件读写都发生在手机本地；文件选择与保存走系统安全组件，不新增任何权限，也不会上传到任何服务器。
智能体只能通过工具访问工作区内的文件，所有路径都是工作区内的相对路径；代码里从根源上就没有给绝对路径、越界路径留下调用的入口，它从原理上碰不到手机的其他目录。
你上传的文件出现在工作区根目录。对上传的原始文件默认不修改、不删除，产出物一律写新路径（如 output/report.docx），方便对比与回溯。
工作区面板可随时查看文件树、上传文件、导出 .zip 或清空。工作区文件不参与上下文压缩，无论任务多长，文件始终完整可查。
时间线：看着它干活
工作模式的执行过程以单容器时间线呈现：每轮按「思考→工具步骤→正文」时序排列，像看一场工作直播。
思考行实时滚动智能体的推理内容与耗时；工具行显示工具名、参数摘要与状态耗时，点击展开参数与结果详情；编辑文件会渲染成 diff 卡片（+新增 −删除），写任务清单会渲染成清单卡片。
最终回复下方还附有输出速度、缓存命中率与工具耗时统计，过程透明、每一步都可回溯。
长任务中早期历史会被自动压缩为状态摘要，时间线会标注「已自动压缩早期历史」。被压缩的只是对话记录——工作区文件与任务清单始终完整。
思考档位：质量与速度
工作模式的深度思考强制开启（工具行不再显示该开关），并提供更细的思考档位：极高（Max）、均衡（High）、快速（Low），在模型选择按钮处切换。交互模式有自己的一套档位（均衡 / 快速 / 关闭），两者各自保存、互不影响。
极高档位追求极致交付质量，耗时更长；快速档位交付更快，质量有所下降；多数任务建议均衡档位。
经验法则：写长报告、做 PPT、多文件处理这类大任务用极高；查资料、改文档等中等任务用均衡；轻量小任务用快速。
交付格式：手机能打开的成品
工作模式的产出直接是手机能打开的格式：报告、方案、纪要等阅读型文档交付 .docx；表格数据交付 .xlsx；演示交付 .pptx；代码、配置与机器可读数据保持源格式。
它不会把 .md 当作交付格式——即使中途用 Markdown 打了草稿，交付前也会转成对应的成品格式。
交付前有一套自检清单：产出物全部存在且非空、关键内容抽查核对、所有失败如实报告、总结覆盖每个产出文件的路径与用途。
最终总结的末尾还会附一张「任务导图」（Mermaid 图），把任务目标、执行路径与产出文件浓缩成一张竖屏可读的总览图，一眼回顾全貌。
任务清单（todo_write）
这个工具由AI在工作过程中自动管理调用，你无需手动做任何操作。
任务清单是复杂任务的总管家：智能体用它创建和更新任务清单，每项任务带状态——待办、进行中、已完成，最多 50 项。
它的纪律很严格：清单整体替换式更新；同一时刻只保留一项进行中；一项任务真正完成并验证之后才会被标为完成，杜绝「边做边全勾完」的假进度。
清单会随「运行时上下文」快照自动注入对话，并在时间线上渲染成清单卡片——你随时能看到任务推进到了哪一步。预计三步以上的复杂任务，它都会先建清单再动手。

list_files：递归列出工作区的文件与目录（含子目录与文件大小），是确认产出物、查看目录结构的第一入口。
glob：按文件名模式找文件，支持跨目录、段内通配、单字符、分支。只匹配路径不读内容，找素材特别快。
grep：按正则表达式搜索文件内容，返回「文件:行号: 内容」，适合按编号、日期、代码标识等模式精确定位。
search_files：大小写不敏感的普通子串搜索，覆盖文本文件与 Office 文档（Word/Excel/PPT 自动抽取文字层），还能按文件名过滤（比如只在 *.md 里搜）。
典型配合：先 glob 或 search_files 缩小范围，找到目标后用 read_file 分页精读。

写入与整理工具

写入与整理工具是智能体在工作过程中最常用的一套工具之一，帮助它快速写入与整理文件。
write_file：覆盖写入文本文件，自动创建父目录，单次上限 512KB；更长的内容会分多次写——先写首段，再连续 append_file 续写。覆盖已有文件前会确认不会丢失你需要的数据。
append_file：向文件末尾追加内容（文件不存在则创建），长文档分段写作的标准做法。
create_dir / move_file / delete_file：创建目录、移动或重命名、递归删除。移动时目标已存在会被拒绝（不会覆盖）；删除是不可逆操作，会先核对范围——清空整个工作区只在你明确要求时执行。
download_file：把网络上的文件（不超过 20MB）下载进工作区。要在产出物里引用网上的图片、素材或数据文件时，它会先用这个工具把原件拿进工作区再使用。
精准编辑（edit）
edit：对已有文件做逐字符精确匹配替换。旧文本必须与文件内容逐字符一致，默认要求唯一匹配（多处匹配会被拒绝，需要补充上下文或改为全部替换）；返回行级 diff（+新增 −删除），时间线上渲染成 diff 卡片，改了什么一目了然。
相比 write_file 整个重写，edit 只动该动的那几行，更安全更快，是对已有文件做小改动的首选。
str_replace_editor：多命令编辑器，提供 view（分页查看）、create（新建）、str_replace（唯一匹配替换）、insert（在指定行后插入）四个命令，需要在特定行插入内容时用它。
简单记：新建文件用 write_file，改已有文件优先 edit。
数据管道（transform_file）
transform_file 专门处理「read_file 读不全」的大文件与非标数据：支持 CSV、TSV、Markdown 表格、JSON、JSONL、文本行等输入，能做过滤、派生列、正则提取、拆列、去重、排序、替换、数值化，以及 CSV、TSV、JSON、Markdown、Excel 之间的相互转换。
最大的特色：数据全程在本地管道里流动，不经过模型上下文——再大的表也不会撑爆对话记忆，上限为单次 2MB、10 万行、30 个步骤。
工作纪律是「先预览、后写盘」：先不带输出参数预览前 3 行，确认转换逻辑无误后再写盘并抽查结果。
完整语法内置在 data 技能里，执行前会自动加载。小表格直接生成即可，不必动用管道。
Office 办公三件套（write_docx / write_xlsx / write_csv）
write_docx：把 Doc JSON（或 Markdown）生成 Word 文档（.docx）。分级标题、加粗斜体、列表、表格、引用、代码块、公式、封面、静态目录都支持，产出排版精良、手机上可直接阅读的成品；read_docx 读回源、edit_docx 改块/增删/全文替换/换样式，外来文件修改前自动备份。
write_xlsx：生成 Excel（.xlsx）。正式表格用 Workbook JSON：多工作表、表头、公式（合计/同比等派生值必须写成公式，改数自动联动）、数字格式（金额/百分比/年份）、列宽、冻结窗格；简单表也可直接吃 Markdown 表格/CSV/TSV。read_xlsx 读回、edit_xlsx 改单元格/加行/加表/全局改词。
write_csv：同样输入生成 CSV 文件，遵循 RFC 4180 标准转义，默认带 UTF-8 BOM——用 Excel 或 WPS 打开中文不乱码。
怎么选：给人看的、带样式的表格选 xlsx；后续还要程序处理或导入其他系统选 csv；文章报告选 docx。
与聊天引擎「一键导出 Word」的区别：导出是把已有回答转成 Word；write_docx 是工作模式里主动产出的成品文件，内容、文件名、路径都由任务决定。生成前会先加载 docx / xlsx 技能获取语法与排版规范。
演示文稿三件套（write_pptx / read_ppt / edit_ppt）
write_pptx：生成 16:9 演示文稿（.pptx）。三种输入方式：deck（结构化 Deck 源，13 种版式、图表、表格、图片、演讲备注——正式 PPT 一律用它）、deck_file（很长的内容先写成文件再导出，改内容后可重复导出）、outline（「# 页标题 / ## 分节 / - 要点」的简易大纲，快速起稿）。
内置 8 套主题（brand-blue、midnight、forest、sunset、violet、graphite、ivory、crimson），支持柱状、折线、面积、饼、环五种图表，深色背景自动反白保证可读性。
read_ppt：把 .pptx 读回结构化源——本应用生成的文件可无损还原；外来 pptx 会近似导入（文本、表格、版面保留）。
edit_ppt：对已有 PPT 应用结构化操作后保存：加页、删页、移动、改单页内容、全局替换文字、换主题、改标题、改备注。外来文件修改前会先自动备份。
做正式 PPT 前，它会先加载 ppt 技能获取 Deck 语法与设计规范，保证版式统一、细节到位。
SVG 绘画生图（write_svg）
write_svg 是工作模式最有特色的工具之一：没有接入专门的绘画服务，而是让模型直接手写 SVG 矢量代码来「画」图——图标、示意图、流程图、架构图、信息图、简单插画都能画，而且矢量格式无限放大不失真。
保存为 .svg 矢量文件的同时，自动栅格化出一张 PNG 预览（同名 _preview.png），方便查看与引用。
标准工作流：先加载 svg 技能获取绘制规范与配方→生成→view_image 预览→发现不满意就修正重画，循环直到满意再交付。
与其他工具联动：write_pptx 可以直接引用 .svg（导出时自动转成 PNG），write_docx 引用预览 PNG——汇报里配一张自己画的流程图非常方便。
边界说明：照片级的真实图像画不了，那类素材会用 download_file 下载原件。
联网搜索与网页抓取（record_search / web_fetch）
工作模式保留联网搜索开关（工具行可开可关）。开启后，服务端会为智能体补充最新网络资料；它与本地工具并存，互不冲突。
一个关键机制：服务端搜索不会在对话历史里留下「搜过什么」的记录。所以智能体每次搜索获得有用信息后，都会立即用 record_search 把关键词、结论摘要与来源网址登记到工作区的 .searches.md 文件——这样后续任何一轮都能追溯，也避免重复搜索。收口前它会通读这份登记簿，汇总所有来源。
web_fetch：抓取网页或接口原文（单次不超过 2MB）。网页会自动剥离脚本与样式、只留可读正文；JSON 与纯文本原样返回。看到来源网址后它会主动抓取原文核对，不只凭搜索摘要下结论。
记住分工：只读网页内容用 web_fetch；要把文件本体（图片、PDF、数据）存进工作区用 download_file。
向你提问（ask_user_question）
ask_user_question 让智能体暂停执行，弹出一张问题卡片等你作答：支持单选、多选，也可以自由输入补充说明，统一点「提交」发送。
它的提问很克制：只有存在影响整体方向的关键缺口（目标格式、范围、口径、删除确认等）且没有合理默认值时才会问；小事不问，先用合理默认值做，并在总结里说明。
因为提问会暂停整个任务，它会一次把问题问全，不会挤牙膏式追问。若 5 分钟未作答会按取消处理，然后基于合理假设继续推进，并在总结中标注哪些是假设。
用好它的诀窍：看到问题卡片尽量给出明确答复——方向确认得越早，返工越少。
定时提醒与自主目标（schedule / goal）
schedule_create：会话内定时提醒。可以是一次性（多少秒后触发）或循环（最小间隔 5 分钟）；到点后自动作为一条消息「唤醒」智能体继续执行。schedule_list 查看全部提醒，schedule_delete 取消某个提醒。你说「10 分钟后提醒我」「每小时检查一次」，就是它在干活。
goal_create / goal_get / goal_update：会话自主目标。长任务开工前先立一个目标锚定总意图，执行中随时记录关键进展或受阻原因——目标会随运行时快照注入每一步，防止多轮执行之后「忘了当初为什么出发」。执行轮次达到上限会自动暂停并等你确认。
子代理（subagent）
subagent 会派生一个「子代理」去独立完成子任务：它与主任务共享同一个工作区（能读写同样的文件），但拥有独立的上下文，最多 40 步，完成后把最终报告交还主任务。
价值在于分工：把成体系的大块工作外包出去——独立调研、批量检索、成套素材整理——主任务只消费报告，上下文保持轻盈，整体更快更稳。
子代理的指令是自包含的（背景、要求、验收标准、产出路径都要写清楚），它不能向用户提问，也不能再派出自己的子代理。
会话检索（session_search）
长任务执行中，早期的对话历史会被自动压缩成状态摘要，细节可能被精简。session_search 可以检索本会话的事件日志（历史消息、每次工具调用与结果），找回被压缩掉的具体细节。
典型用途：核对「之前执行过什么」、找回某个中间数据、确认某次工具调用的原始结果——相当于给任务配了一本全程可查的工作日志。
技能系统（list_skills / load_skill）
技能是打包好的领域操作指南（纯文档）。接到对应任务时，智能体先 list_skills 查看有哪些技能，再 load_skill 按需加载——就像新员工上岗前先翻一遍岗位手册，而不是凭感觉干活。
内置技能从十大扩展到三十二个（10 个核心技能 + 22 个移植领域技能）。核心技能：ppt（Deck 语法、设计规范、主题、自检清单，任何 PPT 任务开始前先加载）；svg（SVG 绘制规范与「生成→预览→修正」工作流，图标/流程图/信息图配方）；data（数据管道的完整语法与清洗、提取、互转配方）；docx（Word 的 Doc JSON 语法与排版规范，任何 Word 任务先加载）；xlsx（Excel 的 Workbook JSON 语法、公式优先与数字格式规范，任何表格任务先加载）；以及五位专家智能体技能：paper（论文改写）、law（法律意见书）、research（深度调研）、sift（时效信息筛滤）、llm-eval（大模型评测）——需要专家级处理时说明用哪一位，即按该专家的完整方法论执行。
22 个移植领域技能（来自四大主流 AI 工作平台并完成本应用工具适配）——写作类：humanizer（去 AI 味/可读性）、khazix-writer（公众号长文）、newmedia-writing（小红书/公众号/短视频新媒体）、content-rewrite（多平台改写分发）、translation（法律/医学翻译与术语一致性）；Office/内容类：prompt-engineering（提示词工程）、pdf（PDF 读取/搜索/扫描件阅读）、html（单页 HTML 开发）；营销类：marketing-plan（营销策划方案）、marketing-material-review（营销素材审核）、sentiment-tracker（舆情追踪与溯源）；学术类：paper-reviewer（学术论文审稿）、paper-rebuttal（审稿意见回复）、paper-close-reading（论文精读）、reference-audit（参考文献审计）、research-lineage-map（研究谱系演进图）、journal-format（学术论文 DOCX 格式排版）、research-proposal（学术立项书/基金申请撰写）、patent-drafting（专利申请文件撰写）；研究类：questionnaire（问卷/深访/原声打标/定量分析）、industry-analysis（行业深度研究）、review-agent（代码评审）。这些技能在交付时都会按需加载 docx / xlsx / ppt / svg / data 等核心技能，用本应用的 Office 工具直接产出文件。
加载是渐进式的：先读技能正文，需要细节再读参考分册。技能正文优先于模型自己的默认做法——这保证了产出稳定符合规范，也是 PPT、生图、Office 文档与专家任务质量的秘密所在。
设备内执行代码（run_js）
run_js 补上了工作模式最后一块拼图：在没有终端、不能安装软件的环境里，它也能「写几行代码算一下」。典型场景——把格式凌乱的文本按正则清洗、统计一组数据的分布、按规则从已有文件重组出结构化数据、批量生成接下来要成文的表格；凡是「写段代码处理」比「读进对话再写」更划算的活，都可以交给它。
它是设备本机上的独立 JS 引擎沙箱：每次执行都是全新实例，不联网、不能读写文件系统、也不能加载外部模块。文件进出由工作区显式桥接——在 files 参数里列出的工作区文件会以只读方式预载给脚本，脚本里用 write 声明的产出会在执行成功后落入工作区（路径同样受工作区边界校验）。
执行跑在后台线程，界面不会卡住；单次执行有默认 10 秒上限，内存与输出体积也都有上限。唯一无法兜底的是死循环——JS 引擎没有中断接口，遇到这种情况系统会放弃等待、把错误交回，让你改写代码（连续超时后本会话会暂时停用该工具，重启应用即恢复），而不是让界面一直转圈。
与 transform_file 的分工：规则固定、批量清洗转换用 transform_file（内置管道，数据不进对话）；需要现写逻辑、做计算或程序化拼数据时用 run_js。最顺手的接力是 run_js 产出 JSON，再交给 write_docx / write_xlsx / write_pptx 成文。
聊天引擎
聊天引擎是什么
侧边栏「聊天引擎」分组下的智能体统称聊天引擎，目前包含 4 个通用对话智能体和 5 个专家智能体。该分组默认折叠，点击标题行即可展开或收起。对话体验是「提出问题→给出回答」：一轮问答即交付，速度快、效率高。
聊天引擎不执行复杂长程任务——它不读写沙箱工作区、不产出成品文件。需要多轮工具调用、文件产出与过程管理的工作，请交给 Agent 引擎（要成品文件走工作模式，要能操作的界面走交互模式）；三条线在侧边栏中并列，随时切换。
推荐：日常提问、试算、对比、看数据，优先用「交互模式」——回答可直接点、可调参、可回传重算；聊天引擎更适合想要一段纯文字回答，或需要指定某位专家智能体的场合。
深度思考默认值：轻简模式与效率模式默认关闭，专家模式默认开启，新建对话时自动重置；其他智能体不自动管理这个开关，可在工具行手动切换。
超过 200 字的正式回答都会以一张 Mermaid 结构图开篇（流程图或时序图，专为手机竖屏优化），先看清全局骨架，再进入正文。
怎么选模式
先想一句：如果答案本来就是一张表、一张图或一个能拖的参数，直接用「交互模式」更划算；下面这些模式适合「要一段文字」的场合。
① 日常闲聊、快问快答、生活小科普 → 轻简模式。
② 高质量日常问答、轻量任务，想要详尽又不想等太久 → 效率模式。
③ 硬核复杂问题、专业领域分析、追求最强质量 → 专家模式。
④ 经典稳定的轻量全能、结构清晰的长输出 → 经典模式。

AI 内容过滤：盘点体标题、无署名、时间模糊、版本号无出处、模板化结构等特征内容一律降级或排除；信源按 S/A/B/C/D 分级，历史信息与当前状态严格隔离。

表格识别插件
表格识别插件是什么
插件是 Guncat Work 面向特定任务开发的独立嵌入式功能，目前提供表格识别插件：把图片里的表格一键转成可编辑的 Excel，流程为 图片 → HTML 表格 → Excel。
入口：在任意回答的操作区点击「表格识别」，进入独立的表格识别页。识别由多模态模型完成，Excel 导出在设备本地生成，不依赖网页上传。
适用场景：截图表格、拍照的登记表、报表、审批单、成绩单等纸质与图片表格的数字化。
操作步骤
第 1 步 选择识别模型：下拉框自动汇总所有 API 配置中的主模型与多模态解析模型（去重后直接选择）。识别时使用所选模型对应的地址与 API Key，无需在此填写；请选择具备多模态（视觉）能力的模型。
第 2 步 上传表格图片：点击虚线框选择图片，支持 JPG/PNG/WebP，建议宽度 1000-3000px；过大的图片会自动压缩后再上传，不影响识别清晰度。
第 3 步 点击「识别表格」，等待识别完成（状态栏会显示进度与结果状态）。
第 4 步 在结果区查看与核对：渲染预览、HTML 代码、网格结构、调试信息四个标签页（见下一节）。
第 5 步 点击「下载 Excel (.xlsx)」导出文件，或在 HTML 代码页复制、下载源码。
识别能力
合并单元格：跨行（rowspan）、跨列（colspan）的合并关系完整保留，导出 Excel 后仍是真实合并单元格，不会拆散。
表头与内容：表头单元格与数据单元格区分标记；数字、小数、百分比、货币符号、千分位、空格原样保留；单元格内换行保留；空单元格保留为空，绝不擅自补全。
行高信息：视觉上明显更高、预留给人手写填写的行（如审批意见、签名栏），按「书写行数」单独标注，并在预览与导出的 Excel 中还原行高；仅因文字换行撑高的行不会被误标。
忠实原则：看不清或模糊的字一律留空，宁可空着也不猜测；不添加原表没有的标题、说明或汇总行。
结果查看与导出
渲染预览：网格化还原表格——合并单元格跨行跨列显示，高行按书写行数加高，所见即所得。
HTML 代码：查看识别出的 HTML 表格源码，可一键复制或下载为 .html 文件，方便在网页或文档中二次加工。
网格结构：自动校验并显示「共 N 行 × M 列」、列数一致性检查结果与高行标注，帮你快速核对识别质量。
调试信息：模型原始输出，排查识别问题时使用。
导出 Excel：点击「下载 Excel (.xlsx)」，在设备本地原生生成文件；导出前显示「N 行 × M 列 · X 个合并 · Y 个高行」摘要，合并单元格与行高在 Excel 中完整还原。
使用建议
拍摄时保证光线充足、表格完整入框、避免透视变形与反光，识别质量更好；表格过长或分页时，分开拍摄、逐张识别。
个别单元格识别有误时，可在 HTML 代码页复制源码手动修正后再用，或重新拍摄更清晰的图片识别。
识别依赖多模态模型：请先在设置中配置好主模型或多模态解析模型，并选择具备视觉能力的模型，否则会提示配置缺失。
表格识别是独立页面，不占用对话上下文；识别结果与聊天记录互相独立，可放心反复尝试。

交互模式
交互模式是什么
交互模式是 Agent 引擎下与工作模式并列的第二种交付形态，也是应用启动后的默认落点：它的回答不是一段文字，而是一份界面程序，应用把它渲染成原生可操作的界面——图表、指标卡、表格、卡片、表单。
它与工作模式共用同一套 Agent 循环、同一个沙箱工作区和同一套数十种工具，差别在纪律：工作模式是「多轮工具循环 + 长程交付」，交互模式是「一句话进来，一张能操作的界面出去」。
适合日常提问、试算、对比、看数据这类「答案本来就是一个面板」的场景——用文字描述一张表，既啰嗦又不好改参数。
怎么进入、怎么换挡
打开应用默认就落在交互模式。要换挡，点空态大标题处的「交互模式 | 工作模式」胶囊的另一档即可；也可以走侧边栏「Agent引擎（推荐）」分组里的「交互模式」项——它是该分组的第一项，排在「工作模式」上方（宽屏左侧栏里这一节叫「引擎」，两个模式与聊天智能体并列）。
换挡本质上是切换会话：切过去会打开该模式最近的一个会话，没有就新建一个空会话。
正在生成或解析中会拒绝换挡，并提示「请等待当前任务完成后再切换模式」；连续点击也会被忽略，避免两次切换交叉。

表单控件：滑块、开关、单选、多选、下拉、标签选择（Chips）、选项卡、输入框、文本域，以及按钮与图标。
组件共 70 个（9 组），全部原生渲染：图表用系统绘图能力现场绘制，不引入图表库、也不会产生图片文件。
快车道：默认零工具、一轮直出
交互模式默认一次回答直接给界面，不调用任何工具。通用知识、估算、示例、方案对比、概念解释，都不需要工具。
只有四种情况会破例：① 你点名要读上传的文件；② 界面里的数字必须来自工作区里的真实文件，需要读一次或算一次；③ 你问的是需要核实的外部事实（联网搜索 / 抓取网页）；④ 你明确要导出文件（Word / Excel / PPT / SVG）。
破例同样克制：一轮最多 1~2 次、优先只读，拿到结果立刻出界面，不会连续探索、反复核对；宁可把界面做小一点，也不为了凑数据去跑工具链。
所以它比工作模式快得多：工具是例外，不是流程。它也不会建任务清单、立目标、定时提醒、派子代理、写自检报告或画 mermaid 导图。
本地交互：拖动即重算，不发请求
界面里的控件可以绑定到一个变量。你拖动滑块、切换开关、勾选选项，界面会立刻用新值重新计算整棵界面——数字、文案、图表一起刷新，不发请求、不等模型。
适合：拖动滑块看图表变化、切换口径看同一份数据的另一种切法、在几个方案之间来回对比。
边界：本地绑定只负责「换一个已经算好的结果」，不会替你做数学；要换算法、换数据，用下一节的回传按钮。
回传重算：让模型重出一版界面
形如「按这个方案重新测算」的按钮，会把你的设置与诉求打包成一条消息回传，助手随即产出更新后的完整界面——界面因此可以反复操作，而不是一张死图。
表单（Form）提交会把全部字段值一起带上；选项卡（OptionCards）和标签选择（Chips）点一下就回传，比打字描述快。
回传的内容就是你看到的那句诉求（例如「按金额 120 万、期限 20 年重新测算」），会作为一条消息出现在对话里，随时可查、可重新生成。
入口按需给：只有确实存在和当前数据直接相关、点一下就推进的动作时，才会给 1~2 条；没有就不给——不会每轮都在末尾塞一组收尾按钮。
边写边成形：流式渲染与「界面未写完」
界面在你读完整答案之前就开始出现了：输出的第一行就是界面外壳，随后每一行语句逐条补齐，标题、指标、图表、表格一个个长出来。
未写完时控件是置灰、不可点的，避免你在残缺界面上误操作；写完后才恢复可交互。
如果输出被模型长度上限截断，已经写完的部分照常渲染，底部会标注「界面未写完」——不会整块作废，也不会永远停在生成中。
界面里不会出现程序之外的大段文字：标题、结论、说明都由界面组件承载，观感始终是一张完整的卡片。
只有最新界面可交互，参数会保存
只有最新一条界面可以操作，历史界面会自动置灰归档，避免你改到上一轮的旧参数上。
你调整过的参数会随消息一起保存：滚动、切换会话、重启应用之后，参数还在原处。
下一轮请求前，应用会把当前界面上的设置翻译成一句人话交给模型（例如「用户在当前交互界面上的设置：金额=45；口径=customers」），所以助手知道你正在调什么，不用每次重复说明。
思考强度：均衡 / 快速 / 关闭
交互模式的深度思考强制开启（工具行不再显示该开关），强度在模型胶囊的「能力预设」里选择：均衡（High）、快速（Low）、关闭（Off），默认落在快速档。
它没有工作模式的「极高（Max）」档：交付物是界面，长思考的收益有限，「快」比「多思考两秒」更重要。
选「关闭」只会让交互模式响应更快，不会把工作模式或聊天引擎的深度思考一起关掉；两套档位各自保存、互不影响。
过程怎么看：活动折叠栏与原始输出
交互模式的产出是界面，过程信息不该和界面抢版面：正文开始输出后，本回合的思考与全部工具调用会自动收成一条「✓ 已完成 · 思考 + N 个工具 · 12.4s」折叠栏，点开可看完整思考与每次工具调用的输入输出。
一个用户任务往往要跑好几轮，但只会合并成一条折叠栏（不是每轮一条）；里面每轮的思考默认收起，需要时单独展开，跑动中的那一轮会在标题行滚动显示最新一句。
界面底部还有「查看原始输出」，可以展开界面程序源码，排查模型到底写了什么；有解析诊断时会显示「诊断 · N 条」。
需要材料：上传到工作区
和工作模式一样：通过「工作区」面板上传文件，文件会进入本会话的沙箱工作区；拍照的图片也可以直接进工作区。
上传后，界面里的数字可以来自这些真实文件——助手会读一次或算一次，再画进指标卡、图表与表格。
真实数据纪律：图表、表格、指标里的数字必须来自工作区真实文件、刚拿到的工具结果或你自己给出的数字；给不出时会缩小界面并用提示条说明缺口，绝不编造。
需要正式文件：Word / Excel / PPT 照常落盘
交互模式并不取消文件能力：直接说「把这个结果导出成 Word / Excel / PPT」，助手会照常产出文件，并在界面里用一个提示或按钮告诉你文件放在哪。
这条路径走简化流程：不追问一堆前置参数（要确认参数就在界面里给一个表单或选项），也不写自检报告。
只用回答下方的「导出 Word」按钮时，导出的是界面里可见的文字（表格会还原成 Markdown 表格），不会把界面源码写进文档。
什么时候用它、什么时候换别的模式
适合：计算与试算（房贷月供、利率对比、收益测算）；方案对比与选择（选项卡 + 对比表）；数据看板（指标卡 + 图表 + 明细表）；参数调优（拖动滑块即时看变化）；结构化知识呈现（步骤条、卡片块、分节）。
该换模式的时候：要交付正式文件、要处理多份材料、任务要跑很久 → 工作模式；只想要一段文字回答、或需要指定某位专家智能体 → 聊天引擎；图片里的表格转 Excel → 表格识别插件。
简单判断：回答的终点是「一份能点的东西」就用交互模式，是「一个文件」就用工作模式，是「一段话」就用聊天引擎。

Version 6.3 新功能体验
全新「交互模式」上线：回答即界面
Agent 引擎新增第二种身份——交互模式（Guncat Canvas）：你的每一轮提问，得到的不是一段文字，而是一张能看、能点、能拖的原生界面。
它与工作模式并列，共用同一套 Agent 循环、同一个沙箱工作区与同一套数十种工具；差别在交付形态与行为纪律：工作模式交付文件成品，交互模式交付可操作的界面。
70 个原生组件：图表、指标卡、表格、表单一次到位
界面语言重写为声明式的界面程序，可用的原生组件扩展到 70 个（9 组）：8 种图表（柱状 / 折线 / 面积 / 横向条 / 饼环 / 径向 / 雷达 / 堆叠条）、表格与实体列表、指标卡、卡片块、分节 / 选项卡 / 折叠面板 / 步骤条 / 轮播，以及一整套表单控件。
全部原生渲染：图表用系统绘图能力现场绘制，不引入图表库、不产生图片文件；组件清单与解析、渲染共用同一份事实源，模型能写出来的就是应用能画出来的。
拖动即重算：参数绑定界面即时刷新
把控件的值绑定到变量，拖动滑块、切换开关、勾选选项时，界面立刻用新值重新计算——数字、文案、图表同步变化，不发请求、不等模型。
于是「调参看效果」第一次变得和本地 Excel 一样顺滑：利率、金额、期限、口径，拖一下就换一版结果。
