## 6. 写入 Markdown/Word（本项目）

只有交付模式为 `doc` 时才创建一个 Markdown/Word 文档。论文片段、短论文和快速翻译默认不得因为“看起来更正式”而自动创建文档；但用户明确要求 Markdown/Word/文档产物时必须创建：

1. 按本技能第 3 节形成的完整译文组织成结构化内容（章节、段落、表格、图注、语义高亮）；
2. 替换全部占位符；文档标题、`translation_label` 和章节标签使用目标语言，中译英标题使用 `English Translation`，不得残留“中文翻译”；默认参考文献策略下不得写入参考文献标题、条目或占位说明；
3. 用 `write_docx`（先 `load_skill("docx")`）生成 Word，或 `write_file` 生成 Markdown；
4. 写入后核对返回的文件路径存在且非空；
5. 表图媒体若无法可靠写入，必须保留完整文字题注和图中可读文字，不能只留“见图”；只有题注或可读文字也缺失时才降级，原始位图未嵌入本身可记录为不影响范围的交付说明；
6. 排版保留“可见结构与语义高亮”：原文明示的重要结论、主要发现、安全性风险、警示和关键限制可在原位置使用多个语义明确的强调块（如 Word 强调段落/Markdown 引用块）；优先直接包裹对应完整译文，不删减、不重复、不拔高结论。

高亮块的多少由原文实际重点决定，不设置生硬的数量机器门槛。

不因材料较长、章节较多或预计文档较大而预先创建骨架或默认分段写入。用户要求的目标范围翻译完成、合并成完整译文并通过门槛 A 后，默认用这份完整译文整篇一次创建文档，再按第 7 节核对交付结果。

只有整篇创建明确因载荷、长度或服务限制失败，且没有留下可用文档时，才启用分段写入兜底：把已经通过门槛 A 的完整译文按原文顺序机械切成最多 3 个连续大段，写入同一份目标文档的连续章节。不得默认逐章更新，不得为每段创建文档，也不得用追加填充中间章节；只有某个大段本身再次明确触发长度限制时，才允许只拆分该失败大段。分段是传输方式，不得重新翻译、删减或改变已经校验的完整内容。

创建结果未通过门槛 B 时，先检查同一份写入调用的报错信息；不得假装成功，也不得未经检查直接创建第二份文档。若返回了可用文件，需要修复时只更新该文件并核对更新结果；权限、结构、参数或普通网络错误不通过分段规避，应修复根因后重新执行，或明确停止。

Markdown/Word 文档禁止使用不兼容的上下标 HTML 标签；固定上下标直接使用普通 Unicode，例如 `10⁹/L`、`m²`、`cm²`、`CO₂`；复杂公式才使用 Word 公式或 LaTeX 语法。

正常路径只执行一次整篇创建。只有该次创建明确受载荷、长度或服务限制阻断且未留下可用文档时，才允许为上述分段兜底再执行一次恢复性创建；恢复后所有内容只写入这一份文档。后续发现真实缺章、缺表或残留标签时，只更新这一份可用文档，不得为了满足格式要求重复创建。
