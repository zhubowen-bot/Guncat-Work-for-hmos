# 数据清洗与转换（transform_file）V2

大文件与非标数据的唯一处理手段：**数据不经过模型上下文**，你写"管道"（steps），本地求值器执行。小表格（十几行）直接 `write_file`/`write_csv` 更快，不要滥用。

## 工具链与工作流

| 工具 | 用途 |
|---|---|
| `transform_file(input, steps)` | **预览模式**：执行管道但只回前 3 行效果——第一次调用永远这样 |
| `transform_file(input, steps, output)` | 确认无误后写盘（.csv/.tsv/.json/.md/.xlsx/.txt） |
| `read_file(path)` | 写盘后抽查前几行确认结果 |
| `write_csv` / `write_xlsx` | 小表格直接生成时用（数据走上下文）；大表用 transform_file 输出 |

核心流程：**冻结口径 → 读源边界 → 预览 → 写盘 → 回读审计 → 交付说明**。后面的 0–4 节是 V2 强化的执行门，不改变任何工具签名。

## 0、先冻结口径（调用前强制门）

1. **逐字记下任务契约**：用户原话中的输入文件、输出格式、目标列名、去重键、过滤条件、拆列分隔符、日期/金额/百分比口径、前 N / 仅保留 / 固定列 / 精确行数等数量与范围约束，先写成内部验收清单。不能为了“更完整”而扩大范围，也不能漏掉用户明确点名的列或文件名。
2. **规则解释优先级固定**：用户明确规则 > 文件说明/数据字典/表头 > 可观察字段和值 > 常见惯例 > 分析假设。使用假设时必须写明“假设”，不能伪装成源数据事实。
3. **先区分“能判断什么”**：缺字段时，分别报告可证真的命中、可证伪的不命中、未知量；不能把未知当 0，不能把“没有报错”当成“数据已全部清理干净”。
4. **每个清洗动作都要有口径**：去重是整行还是指定列、保留哪条；过滤是排除空值还是排除异常值；拆列遇到段数超限怎么处理；金额/日期统一成什么格式。口径不明确时，先选最保守的默认值（如 `dedupe` 保留首行、不删除只标注），并在交付说明中声明。
5. **先预览后写盘**：第一次调用永远省略 `output`，只有预览符合预期后才写盘。

## 1、读源与边界确认

1. **读前 30 行**：确认列名、分隔符、脏数据模式；`read_file` 不要只看 1 行。能分段读取时补看中/尾样本；只能读前几行时，在交付说明中标注“仅核对头部样本，未覆盖全表尾部”。
2. **列名核对**：全半角空格、大小写、重复列名——报错“列不存在”优先核对列名。
3. **识别汇总行与表尾**：先确认“合计/总计/小计/累计”行是否存在。若存在且与明细口径不同，先用 `filter` 排除后再做去重/过滤/排序，避免汇总行参与统计或残留到结果表；用户要求保留原样时不得删除。
4. **空值**：缺失是空串 `''`；用 `is_empty` 判断，需要时 `fill`。缺失值不编造，源数据没有的事实字段不得用推算值充数。
5. **类型**：金额/百分比/日期在表达式中都是字符串；比较前先 `to_num` 或 `regex_replace` 清理。
6. **重复**：明确去重口径（整行 or 指定列；保留哪条）后再 `dedupe`。用户没有指定保留规则时，默认保留首行并写明该口径。
7. **异常值**：过滤或标注前先 `sort`/`filter` 看极值，别盲目删除。发现会改变主数字、口径或可信度的异常时，建立“发现 → 原值 → 重算/证据 → 影响”台账，并在最终交付说明中逐项披露。

## 2、写管道与预览

1. 先写 steps，**省略 output 预览**；预览返回前 3 行效果。
2. **预览通过 ≠ 语义正确**：管道能跑只代表语法和求值没报错，不代表筛选/去重/转换口径正确。预览时要对照冻结的口径逐列检查表头、示例值和边界行为。
3. 每个步骤写明“为什么”：`filter` 的表达式必须对应任务原句；`dedupe` 的 keys 必须对应明确业务键；`rename`/`select` 的目标列名必须逐字匹配用户要求。
4. 能先写预期就写预期：去重后应保留多少行、过滤后应剩多少行、应保留哪些列、输出应是什么格式。写盘后按预期抽查，差异先回到步骤而不是改口说“差不多”。
5. 报错信息含行列定位，照着修；修步骤，不要绕过报错去“手算后硬写结果”。
6. 管道里出现的常量（如阈值、固定替换词）在最终交付说明中列出，作为可审计的参数；不要只藏在表达式里不交代。

## 3、写盘、回读与交付核对

1. 预览对 → 加 `output` 写盘；写盘后必须 `read_file` 抽查输出。
2. **回读抽查头/中/尾**（工具支持时），重点核对：表头逐字串、首尾数据行、被过滤/替换的旧值是否残留、空值列是否被意外引入。
3. **可机械核对项逐项断言**：用户点名的列名、输出文件名、输出格式、行数、关键合计、日期格式等，能回读核对的都要核对；不能只报“成功示例”或“看起来没问题”。
4. **替换/删除残留复查**：按旧值条件做 `replace`/`filter`/`drop` 后，回读时抽查旧值是否仍在结果中；发现残留先修步骤再重跑。
5. **回复里声称的每一项，产物里都要能指到位置**：例如说“已去重到 N 行”“已拆出日期列”，就应在输出文件中读到对应行/列；指不到位置的，要么补做，要么把该句改为“未完成+原因”。
6. **交付说明写清审计信息**：输入文件、读取覆盖边界、应用了哪些步骤、输出路径、回读核对了哪些项、哪些项未验证。未验证的不能声称已完成。

## 4、异常归因与证据分级

1. **证据分三级**：
   - **事实**：直接来自源字段或可复算的管道步骤；
   - **派生**：经过某条公式/规则得到，写明规则与输入；
   - **假设/无法判断**：缺少证据或依赖未确认口径，必须显式标注，不能写成确定结论。
2. **归因只在证据足够时给**：如果用户问“为什么某列大量为空/为什么去重后少了很多行”，只能报告可复算的规则结果和源数据表现；不能仅凭列名或关键词推断业务原因。
3. **重大异常必须进入交付说明**：会改变主数字、口径、可信度或后续行动的发现，逐项列出“发现 → 原值 → 重算/证据 → 影响”。与任务无关的小问题可以不展开。
4. **能力边界照实说**：transform_file 是行级变换管道，没有分组聚合/透视/merge/concat op。需要按组统计、合并多文件或透视时，小数据让模型读入后用 `write_xlsx` + 公式完成；大数据先清洗成规范表再交给 xlsx 技能建模，或说明边界并给替代方案。

## 输入格式（format 省略时自动识别）

| format | 内容 | 说明 |
|---|---|---|
| `csv` | 逗号/分号分隔 | RFC 4180 引号字段正确解析；`delimiter` 可显式指定单字符；`has_header` 默认 true |
| `tsv` | 制表符分隔 | 同上 |
| `md` | Markdown 表格 | `\|` 分隔，首行即表头 |
| `json` | JSON | 顶层数组或对象；`json_path: "data.items"` 定位数组（数字段为 0 起下标） |
| `jsonl` | 每行一个 JSON | |
| `lines` | 纯文本行 | 每行一条记录，单列 `line`（正则提取的常用入口） |

## 数据模型

统一为「表头 + 字符串单元格」。列引用两种写法：`col('年龄')`（需表头）或 `col(2)`（1 起列号，无表头时唯一选择）。`rownum()` 返回当前 1 起行号。

## 常见字段处理速查

| 字段类型 | 常见脏形态 | 处理 |
|---|---|---|
| 手机号 | 空格、`+86`、`-` | `regex_replace(col('手机号'), '^\\+?86[- ]?', '')` + `trim` |
| 身份证 | 科学计数、文本被转数字 | 保持字符串；长度校验 `len(col('身份证')) == 18` |
| 金额 | `￥1,234.50`、`1,234元` | `regex_replace` 去 `￥`/`元`/千分位后 `to_num` |
| 百分比 | `12%`、`12.5 %` | `regex_replace(col('x'), '%', '')` 后 `to_num`；如要小数再 `/100` |
| 日期 | `2026/03/21`、`2026.3.21`、`2026-3-1` | 统一用 `regex_replace` 转 `YYYY-MM-DD`，或 `extract` 拆年月日 |
| 枚举/状态 | `完成`/`已完成`/`done` 混用 | `map` 或 `replace` 归一为统一词表 |
| 空白/不可见字符 | 首尾空格、全角空格 | `trim`；全角空格用 `replace(col, '　', ' ')` |

## 表达式语法（filter/derive/map/sort 的 expr 字段）

- 字面量：数字 `18`、字符串 `'待定'` 或 `"待定"`、`true`/`false`/`null`；字符串内转义 `\n` `\t` `\'` `\\`
- 运算符：`+ - * / %`、`== != < <= > >=`（`=` 宽松按 `==`）、`&& || !`；`+` 任一侧为文本时做拼接
- 比较规则：两侧都能解析成数字 → 数值比较；否则按文本比较。**等值比较不忽略空格**，脏数据先 `trim()`
- 数字解析（`num()` 与数值上下文共用）：去首尾空白、剥离千分位逗号与 `￥$€£¥` 前缀后前缀解析；解析不出得 NaN——比较按文本、算术传播 NaN、filter 中视为假。`'12%'` 不会自动转数字，先 `regex_replace(col('x'), '%$', '')`
- 空值：单元格缺失即空串 `''`，用 `is_empty(col('x'))` 判断

## 函数表

| 函数 | 说明 |
|---|---|
| `trim(s)` `upper(s)` `lower(s)` `len(s)` `str(v)` | 文本基础 |
| `substr(s, start, end?)` | 0 起、含头不含尾 |
| `replace(s, old, new)` | 字面量**全部**替换 |
| `regex_replace(s, pattern, repl)` | 正则全部替换，repl 支持 `$1` |
| `matches(s, pattern)` | 正则测试（部分匹配即真），返回布尔 |
| `extract(s, pattern, group?)` | 首个匹配的第 group 组（默认 0=整个匹配），无匹配返回 `''` |
| `split(s, sep)` / `join(arr, sep)` | sep 是字面量；split 结果通常立刻 join 或取 extract |
| `num(s)` `round(n, d?)` `abs` `floor` `ceil` `min(a,b,…)` `max(a,b,…)` | 数值 |
| `if(cond, a, b)` `coalesce(v1, v2, …)` | coalesce 返回第一个非空（`''`/null/NaN 视为缺失） |
| `is_empty(v)` `starts_with` `ends_with` `contains` | 判断 |
| `col('名')` `col(1)` `rownum()` | 数据引用 |

## ops 全表（steps 数组元素）

| op | 参数 | 说明 |
|---|---|---|
| `filter` | `expr` | 保留真值行（`''`/0/null 视为假） |
| `derive` | `name, expr` | 追加计算列 |
| `map` | `col, expr` | 重算某列（可引用自身） |
| `select` | `cols`, `optional?` | 保留/重排列；`optional: true` 时缺失列跳过 |
| `drop` | `cols` | 删除列 |
| `rename` | `from, to` | 改列名（需表头） |
| `set_header` | `names` | 为无表头数据定义列名（个数=列数） |
| `promote_header` | — | 首行数据提升为表头（当前无表头时） |
| `sort` | `expr, desc?` | 排序，空值恒排最后 |
| `limit` / `skip` | `n` | 截取/跳过 |
| `dedupe` | `keys?` | 按整行（或指定列）去重，保留首个 |
| `drop_empty` | — | 剔除全空行 |
| `fill` | `col?, value` | 填充空单元格 |
| `trim` | `cols?` | 去首尾空白（缺省全部列） |
| `replace` | `col?, find, replace, regex?` | 单元格替换（缺省全部列） |
| `extract` | `col, pattern, name?, group?` | 正则提取为新列 |
| `split_col` | `col, sep, names` | 拆列；任何行拆出段数超过 names 即报错 |
| `to_num` | `cols?` | 列数值化（解析失败置空） |

列引用统一为：列名字符串或 1 起数字（如 `"cols": ["姓名", 3]`）。

## 配方（三类场景，四个示例）

### ① 表格清洗与规范化

**CSV 清洗 → 规范 CSV**

```json
{"input":"客户名单.csv","steps":[
  {"op":"trim"},
  {"op":"filter","expr":"col('手机号') != '' && matches(col('手机号'), '^1\\d{10}$')"},
  {"op":"to_num","cols":["消费额"]},
  {"op":"fill","col":"城市","value":"未知"},
  {"op":"dedupe"},
  {"op":"sort","expr":"num(col('消费额'))","desc":true}
],"output":"客户名单_清洗.csv"}
```

### ② 非表格抽取与转换

**从文本提取结构（正则）**

```json
{"input":"日志.txt","format":"lines","steps":[
  {"op":"extract","col":"line","pattern":"\\[(\\d{4}-\\d{2}-\\d{2})\\]","name":"日期","group":1},
  {"op":"extract","col":"line","pattern":"耗时 (\\d+)ms","name":"耗时ms","group":1},
  {"op":"select","cols":["日期","耗时ms"]},
  {"op":"filter","expr":"num(col('耗时ms')) > 500"}
],"output":"慢请求.csv"}
```

**JSON → 表格**

```json
{"input":"接口返回.json","json_path":"data.orders","steps":[
  {"op":"rename","from":"create_time","to":"下单时间"},
  {"op":"select","cols":["下单时间","amount","status"]}
],"output":"订单.xlsx"}
```

### ③ 下游建模预处理与合并前统一

**多文件合并前的单表清洗**

```json
{"input":"销售明细.csv","steps":[
  {"op":"trim"},
  {"op":"to_num","cols":["金额"]},
  {"op":"filter","expr":"col('状态') == '已支付'"},
  {"op":"select","cols":["日期","区域","金额"]},
  {"op":"sort","expr":"col('日期')"}
],"output":"销售明细_清洗.csv"}
```

> 合并多个同结构 CSV：分别用 transform_file 清洗成统一列名后，用 `concat` 思路？——**当前无 merge/concat op**：多文件合并请先各自清洗到同一 schema，再让模型用 `read_file` 读取后由 `write_csv`/`write_xlsx` 汇总，或用 xlsx 技能在 Excel 内用公式汇总。

**能力边界（诚实声明）**：transform_file 是"行级变换"管道，**没有分组聚合/透视/merge/concat op**。需要按组统计（如按区域汇总）、合并多文件、透视表时：小数据让模型读入后用 `write_xlsx` + 公式（SUM/SUMIF 等）完成；大数据先把源清洗成规范表，再交给 xlsx 技能建模，或说明能力边界并给替代方案。

## 限额与限制

- 输入 ≤2MB 文本、≤10 万行、≤512 列；steps ≤30 步；xlsx 输出 ≤5 万行（更大用 csv）
- 输入按 UTF-8 读取；GBK 等编码的旧文件请先让用户转码
- 单元格全是字符串：数字比较依赖自动解析，金额/百分比等脏格式先 `to_num`/`regex_replace`
- 求值无任何 I/O 与网络：管道只能变换数据，取文件用 `input`，写文件用 `output`

## 交付前自检清单

- [ ] 用户原话中的约束逐条冻结成验收项了？没有自行扩大或缩小范围？
- [ ] 先预览后写盘，写盘后 `read_file` 抽查过头/中/尾（或至少头部并声明覆盖边界）？
- [ ] 列名与输入/用户要求完全一致（空格/全半角）？报错"列不存在"时优先核对列名
- [ ] 源表里的合计/汇总行已识别，未混入明细处理？
- [ ] 数字列做过 `to_num` 或比较用 `num()`？百分比/千分位先清理？
- [ ] 去重/过滤的口径与用户要求一致（保留哪条、空值算不算）？不确定处已在交付说明声明？
- [ ] 替换/删除后回读过旧值残留？
- [ ] 交付说明区分了事实、派生口径和假设/无法判断？
- [ ] 输出格式匹配下游用途（给 Excel 用 csv+bom 或直接 xlsx；给程序读的 json/csv 用 `bom: false`）？
- [ ] 回复中声称的每一项都能在产物或交付说明中指到位置？
