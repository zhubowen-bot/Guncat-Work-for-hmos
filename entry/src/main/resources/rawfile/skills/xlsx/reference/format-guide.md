# 表格规范：公式优先、数字格式、财务惯例与编辑完整性

面向用户最终交付的 Excel：报表、预算、经营数据、财务模型、统计表、清单。
核心原则：**派生值用公式、数值有格式、假设与计算分离、只改该改的**。

## 1. 公式优先（最重要的规则）

**任何"算出来的"单元格都必须写成 Excel 公式，禁止硬编码计算结果。**

- 合计行 → `"=SUM(B2:B9)"`；跨行合计 → `"=SUM(B2:B3)"`。
- 同比/环比 → `"=(B3-B2)/B2"`；比率 → `"=B3/B2"`；占比 → `"=B2/$B$10"`。
- 跨表引用 → `"=假设!B2"`（表名含空格用单引号：`"='销售数据'!D2"`）。
- 好处：用户改输入数字，Excel 自动重算，不会出现"表里数字对不上"的硬伤。
- 例外：原始录入数据（本来就是数字）不算公式；只有**派生**值要公式。

## 2. 数字格式纪律

按列给 `formats`，别裸奔：

| 场景 | formats | 说明 |
|---|---|---|
| 金额列 | `money` 或 `number` | 千分位 + 两位小数；同簿一致 |
| 数量列 | `int` | 千分位整数 |
| 比率/增长率/毛利率 | `percent` | **值存小数**（0.08=8%），不要存 8 |
| 年份列 | `year` | 防 2024 显示成 2,024 |
| 日期列 | `date` | — |
| 标识符列（身份证/电话/邮编/编号/订单号） | `text`（@） | 以字符串写入，保留前导零和原字符；不可当数值计算 |

- **小数纪律**：要求两位小数就整列统一格式，禁止 12875 与 12875.00 混排。
- **负数**：金额负数显示 `(¥1,234.00)` 括号风格（对外交付标准）；全簿统一一种风格。
- **零值**：稀疏报表零值显示 `-`；数量列零值保留 0。

## 3. 假设与模型分离（财务模型）

- 假设（增长率、税率、单价、折扣）集中放一个 sheet，如"假设"：
  - 每行 = 假设名 + 数值；数值单元格配对应格式（比率 percent、金额 money）。
- 模型/计算区只写引用假设的公式：`"=B2*(1+假设!B2)"`，**不写死数字**。
- 好处：改假设一处，全表联动；审查者一眼看清哪些是可调参数。
- 简单模型也可同表分区：前几行假设块，空一行，下面模型块。

## 4. 结构规范

- **表头**：`headers` 必给，列名简短明确（"月份"不要"月"）；单位/口径写进表头或加一行说明。
- **列宽**：文本列 12~18，数字列 12~14；长文本列宽不够会截断显示（中文/全角按 2 个字符估算，8~50 为常用上限，超出启用换行）。
- **冻结**：普通报表默认不冻结；只有长明细需要滚动定位表头/关键标识列时才 `freeze: "A2"`（参考 doubao sheet）。
- **一表一事**：不同主题分 sheet（"收入""费用""利润"），不要全塞一张表。
- **空行**：数据中间不插空行（会破坏 SUM 连续区域语义），用合计行或分区。

## 5. 编辑完整性（edit_xlsx 硬规则）

1. 编辑前先 `read_xlsx` 拿当前源，**基于它写 ops**，不要凭记忆重写全表。
2. 只改任务要求的单元格/行/表；其它数据一律不动。
3. `add_row` 的列数必须与现有列数一致（多列补空串、少列会报错）。
4. `replace_text` 会跳过公式与数字——改词只影响文本。
5. 交付后 `read_xlsx` 验证：表名、行数、抽样数据、关键公式仍在。
6. 外来 xlsx 编辑前自动备份 `*_原版备份.xlsx`；那是近似导入重建的，原样式细节不在备份里。

## 6. 常见错误

| 错误 | 正确 |
|---|---|
| 合计行写死 `200000` | `"=SUM(B2:B9)"` |
| 比率存 `8`（显示 800%） | 存 `0.08` + `percent` 格式 |
| 年份列显示 `2,024` | `year` 格式（`0`） |
| 行不矩形（某行少一列） | 补空串对齐 |
| 金额格式混用 | 整列统一 `money`/`number` |
| 表头列数与数据不一致 | 对齐后再 write_xlsx |

## 7. 数据分析与报表交付链路（参考 doubao-data-analysis / ChatGPT spreadsheets 思路）

当任务是"从数据到结论"时，按以下顺序，不要直接跳到最后一步：

1. **读数据**：先 `read_file`/`read_xlsx` 看结构、列名、口径、脏数据模式；
2. **清洗转换**：脏数据/多文件/去重/正则提取用 `transform_file`（`load_skill("data")`），数据不经过模型上下文；
3. **定口径**：指标定义、时间范围、单位、筛选条件先明确；口径写进表头或"说明"sheet；
4. **建模**：按"假设与模型分离 + 公式优先"建 Workbook；派生值全部用公式；
5. **验证交付**：`read_xlsx` 抽查关键值/公式/格式；交付时给结论，不只丢表。

**表格可读性**（参考 ChatGPT documents skill 的 table gate）：

- 只有"行×列可比较/可查询"的数据用表格；单元格里出现整段文字时改回文本/列表。
- 列宽按内容分配，不要默认均分；短字段（编号/状态/日期/金额）紧凑，长文本列放宽。
- 数字列右对齐、文本列左对齐；表头清晰；冻结表头（`freeze: "A2"`）。
- 数据中间不插空行，避免破坏 SUM 连续区域语义；不同主题分 sheet。

## 8. 工作簿分层与视觉规范（参考 Doubao sheet / doubao-data-analysis）

**工作簿分层**：不要把原始数据、计算和结论混在一个 sheet。

```
说明（口径/来源/更新时间）
原始数据（只读导入）
计算（中间计算/构建层）
结论 / Dashboard（摘要与结论，放在最上面或独立 sheet）
```

- 财务模型建议：`Assumptions`（输入）→ `IS/BS/CF`（报表）→ `Supporting Schedules`（构建）→ `Check`（勾稽）。
- 敏感性分析独立 sheet 或明确分隔块，不混在结果页。
- 结论放最上面（报表顶部摘要），不要堆在底部。

**视觉规范**（参考 doubao sheet ref-excel-visual-standards，用户明确要求优先）：

- 美化不是默认动作：只计算/汇总的临时表、原始数据导出，默认只保留数字格式和列宽适配。
- 正式报表才做“最小充分美化”：表头加粗、居中、低饱和度底色（浅灰或主题深色白字均可，按模板/源文件延续），表头与数据区层级清晰。
- **数据区默认不使用斑马纹/交替行底色**；只有用户明确要求或源文件已用且新增内容需延续时才用。
- 对齐：文本左对齐、数值右对齐、日期/短分类居中，所有内容垂直居中。
- 边框：只在表头底部、分组起始和汇总行用连续实线；不要给普通明细逐行加分隔线，少用垂直线；不使用点状/虚线边框（用户要求或源文件已有除外）。
- 冻结表头只在长明细需要时启用；列宽按内容分配，横向合并标题不撑宽首列。
- 颜色纪律：不是信号色（正/负/警示）不使用红绿填充；避免彩虹配色；修改源文件时延续原样式，不要整簿重套主题。
- 勾稽检查：模型必须带 `Check`/`Checks` 表，用公式算 Actual/Delta/Threshold/Status；全部 PASS 才显示 `Model Status = PASS`，未通过不得交付为"已验证模型"。

## 9. 交付前自检清单

- [ ] 所有派生值都是公式，没有手算数字？
- [ ] 写聚合公式前确认过区间首尾：起点跳过表头、终点覆盖真实末行？
- [ ] 金额/数量/比率/年份各用了正确格式？
- [ ] 比率值存的是小数？
- [ ] 负数/零值显示风格全簿一致？
- [ ] 有表头、列宽合理、长表冻结了表头？
- [ ] 工作簿分层（说明/原始数据/计算/结论）清晰？
- [ ] 模型有 Check/勾稽，Model Status 为 PASS？
- [ ] read_xlsx 抽查过最终文件？
- [ ] 外来文件编辑前有备份？

## 10. ChatGPT spreadsheets 可移植规则（适配 Workbook JSON / edit_xlsx）

参考 `chatgpt/plugins/openai-primary-runtime/spreadsheets/26.805.11740/skills/spreadsheets/SKILL.md`，以下规则与现有工具契约兼容：

- **指令优先级**：用户要求 > 参考/模板 > 领域默认与格式默认。用户明确点名的 sheet/字段/公式/样式，优先于通用规范。
- **编辑前先研究原文件约定**：`read_xlsx` 后匹配已有表头风格、数字格式、公式模式和布局；做视觉/格式修复时从最小局部改动开始，不要整簿重排、自动换行或全局重设样式。
- **公式可审计**：复杂计算用辅助单元格拆成中间步骤，避免单格超长公式；公式里引用假设/原始数据单元格，不写死 magic number（如 `=A5*(1+$A$6)` 而不是 `=A5*1.05`）；同一列/同一期公式模式保持一致。
- **跨表引用推荐总是单引号包表名**：`='Sheet Name'!A1`，即使表名没有空格也建议这样写，避免后续改名或含特殊字符时报错。
- **公式错误扫描**：交付前在 read_xlsx 结果或 Excel 中检查 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`，并核对零值/负数边界和循环引用。
- **百分比精度**：内部/分析单元格用 1 位小数；面向用户的 Dashboard 用 0 位小数；利率等小差异敏感场景用 2 位小数。
- **不要用字符串伪装类型**：数字、百分比、货币、日期用真实单元格值 + `formats`，不用预先格式化好的文本；只有身份证/账号/SKU/邮编等真标识符用文本。
- **来源内嵌**：需要追数据来源时，给行式数据加“来源”列，或在“说明”sheet 记录文件/URL/口径；不要只靠对话承诺。
- **只读问题不改文件**：用户只是问表格里某个值怎么算，用 `read_xlsx` 回答并追踪公式到假设/原始输入；不要顺手导出或改写工作簿。

## 11. Doubao sheet 编辑准则补充（适配 Workbook JSON / edit_xlsx）

参考 `doubao/skills/sheet/SKILL.md` 的“飞书表格编辑准则”，补充以下与当前工具兼容的硬规则：

- **补齐只写空单元格**：用户要求补全/填充时，只改空单元格；已有值哪怕看着可疑也先保留，最多在交付说明备注“建议核实”。
- **新增计算列/汇总行必须显式给格式**：公式默认可能输出多位小数，新增的均值/占比/金额列要按语义配 `formats`（比率两位小数、占比 `percent`、金额 `money`/`number`），不要交给 General。
- **聚合公式先确认区间边界**：写 `SUM`/`COUNTIF`/`AVERAGE` 前，起点跳过表头、终点覆盖真实末行；写完抽查区间首尾两格，避免漏掉末行或把表头算进去。区间错误的结果常常“看着合理但不报错”。
- **“生成成功”不等于“计算结果正确”**（参考 Doubao sheet AI 公式例外）：批量/AI 生成公式后必须 `read_xlsx` 抽样核验真实落格与关键值；语义判断类（无固定分隔符/模式）不要用固定偏移/正则硬套，逐行独立语义任务应显式说明或逐行处理。
- **公式里输入列可能为空时先判空**：例如 `=IF(B2="","",B2*C2)`，避免空格按 0 参与算术产生无错误码的错值。
- **日期列转换先扫全列锁定月/日位**：如 `9/3/24`，先看全列是否存在大于 12 的数值段来确定是月/日还是日/月；不要逐格凭感觉解析，否则月日易颠倒。
- **单位/口径/来源等元信息另置**：写在“说明”sheet、标题下副标题行，或并进字段名（如 `营收（万元）`）；不要占用已有表头格或数据格。
- **新增内容要能看懂**：新增列给可区分含义的表头（不与原列同名）；题面/模板指定的 sheet 名、标题、备注、图例文案逐字照搬，不缩写、不润色。
- **批量替换/删除后做残留复查**：逐个旧值执行“搜索→替换→再搜索”，回读采样覆盖前部/中段/表尾，不只抽前几行。
- **全量处理前置断言条数**（参考 Doubao sheet 规则 10）：翻译/打标/批量公式等逐条任务，先把预期条数写进计划/脚本，再 `assert actual == expected`；断言不过优先补齐。能力不足补不了时，先落地可打开的主体产物，未完成项在交付说明声明。
- **中间结果放右侧或新建空白 Sheet**：分析/清洗的中间结果不要覆盖原始区域；原表其它单元格、行列结构、Sheet 名、合并区、格式保持 1:1。
- **禁止删/改名/隐藏/移动已存在 Sheet**（用户明示要求除外）：确认影响后执行；交付说明里记录结构变化。
- **筛选/排序/删除后回读确认**：筛选/排序后核对前几行和表尾顺序，删除后确认已空、相邻行未被误删；不要只凭操作返回结果声称完成。

## 12. ChatGPT spreadsheets style_guidelines 可移植规则（适配 Workbook JSON / edit_xlsx）

参考 `chatgpt/plugins/openai-primary-runtime/spreadsheets/26.805.11740/skills/spreadsheets/style_guidelines.md`：

- **编辑带格式的工作簿先摸清样式**：`read_xlsx` 后确认现有表头、数字格式、边框、合并、列宽等约定；只改值时，不要覆盖或清除这些格式。
- **表头与数据/派生区视觉可区分**：表头统一加粗/低饱和底纹（由 `style` 预设或源文件延续），与数据区有清晰层级。
- **边框只用于结构，不装饰每格**：优先表头底部、分组起始、汇总行用连续实线；不要给每个填充格都加边框。
- **只给已填充/有意预留的范围设样式**：不要给几百行空行套格式，避免把“已使用范围”撑大、影响渲染与打印。
- **对齐按数据类型整列/整块设置**：文本左对齐、数值/货币右对齐、日期显式 `date` 格式、金额/货币显式 `money`/`number`；重要数值列不要留在 General。
- **重要合计放可见摘要区**：顶部摘要/侧栏用公式引用明细合计，而不是只放在表尾；摘要卡与明细区用底纹/边框区分。
- **布局保持紧凑可扫读**：并排区块变挤时改为上下堆叠；交付前按正常缩放检查标签/数值是否被裁剪、断连或重叠。
- **加粗克制**：只用加粗建立阅读顺序，不要大范围强调；标题/章节留出足够留白。

## 13. 续写/扩展继承样式（参考 Doubao sheet）

续写、补齐、复制区块、新增行列时，禁止“只写值不延续样式”：

- **新区域与相邻原始区域视觉一致**：表头风格、数字格式（`formats`）、对齐、边框、底色/交替行、列宽都要跟随相邻列延续；新增列时同步给它与相邻列一致的 `formats` 与列宽。
- **新增列/行先对齐结构再填值**：确认列数/行号与现有结构一致（`add_row` 列数与表头一致），不要让新数据破坏 SUM/SUMIF 连续区域语义。
- **延续公式与汇总**：新增数据行后，若下方有合计/汇总行，检查公式区间是否覆盖到新末行；新增列后如有跨列合计，更新对应汇总引用。
- **不要整簿重套样式**：只是续写时延续原样式即可，不要给整簿换主题/重置样式，破坏已有视觉约定。

## 14. 供人填写的工作簿与已有文件编辑（参考 QwenWork xlsx）

- **创建“给人填的模板”时**：给一个图例，说明哪些单元格可编辑、哪些是公式/假设；并放一行真实示例数据展示预期格式。示例行只用于“新建模板”，**不要加到用户要求编辑的已有文件里**。
- **编辑已有文件时**：先找设计输入区（通常用颜色/填充/标注标出），只写那里；已有公式一律不动；原文件约定优先于本指南。
- **财务模型颜色约定适配**：若工具不支持单元格字体/填充颜色，用“说明”sheet 以文字标注哪些是输入、哪些是公式、哪些是跨表引用；不要让用户只能靠颜色读懂模型。
- **公式“能求值”≠“算对”**：绿色/无错误只证明公式可运行；区间错位、引用错行仍会给出干净但错误的结果——交付前仍要对账关键合计。

## 15. 数据验证/条件格式的替代方案（参考 ChatGPT spreadsheets）

- **状态/优先级/风险/差异等字段**：若工具不支持数据验证/条件格式，用“说明”sheet 写明允许值列表与填写规范；状态列使用统一词表（未开始/进行中/已完成/阻塞），不要混用同义词。
- **需要随未来变化自动反应的字段**：保持公式驱动，不要一次性静态填色/填结果；交付说明提示用户可在 Excel 中按需一键加条件格式或数据验证。
- **扫描型列**（状态/风险/阈值）：先保证值本身统一、公式可复核；颜色/图标只是加分项，不能代替数据正确。
