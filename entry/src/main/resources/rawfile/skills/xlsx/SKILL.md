## 0. TL;DR 铁律（优先级最高，冲突时以本节为准）

1. **[铁律] 每次接到新 Excel 指令或新附件后，第一个工具调用必须是 `load_skill("xlsx")` 全量加载**。`load_skill("xlsx")` 会一次返回 SKILL.md + 全部 reference（workbook-dsl / format-guide / report-blueprints / analysis-playbook / troubleshooting）。禁止只读 SKILL.md 后挑读 reference，禁止跳过、中途截断或凭记忆继续。
2. **[铁律] 新建工作簿/正式报表（工作流 A）动手前，必须先调用一次 `ask_user_question` 前置提问**：用途/读者、表结构/字段口径、周期/范围、交付格式、素材附件一次问全。用户已提供全部关键信息或明确说“不用问/直接做”时才能跳过，且必须在最终总结记录假设。
3. **[铁律] 交付前必须产出可核对的自检报告**：用 `read_xlsx` 回读核对，写入 `xlsx_qa_report.md`，并在最终总结附 `## Excel 交付自检报告` 摘要。没有报告不视为完成。
4. **[铁律] 数据可审计**：禁止编造数据；关键数字建立“源数据 → 计算 → 写入 → 回读”对账；派生值必须公式优先，不写死手算数字；缺失值留空 + 备注，不填 0/估算。
5. **[铁律] 编辑最小改动**：已有工作簿先 `read_xlsx` 读回，只改任务要求的区域，保留未要求改动的结构、公式与格式；外来文件自动备份不删。

## 1. 规则分级与冲突裁决

| 级别 | 含义 | 违反后果 |
|---|---|---|
| **铁律** | 任何情况下不可跳过，除非用户显式覆盖 | 任务未完成，回到对应步骤补齐 |
| **强规则** | 必须遵守；与用户明确要求冲突时以用户为准 | 视为质量问题，在自检中列出并修复 |
| **建议** | 默认应遵守；有充分理由时可偏离 | 偏离时在自检报告说明理由 |
| **软参考** | 帮助判断，不强制 | — |

**冲突裁决程序（按此顺序，不自行选阻力最小路径）**：

1. 用户当前明确指令 > 用户历史明确指令 > 模板/既有表约定 > 本技能铁律 > 强规则 > 建议 > 软参考。
2. “默认不打断”与“不确定项一次问清”冲突时：**新建工作簿/正式报表走“前置提问门”（铁律），编辑/读取/修复走“不打断”**；按场景路由分流，不并存。
3. “公式优先”与“直接给静态结果更简单”冲突时：派生值必须公式，禁止手算数字；除非用户明确要求“只要结果不要公式”。
4. “忠实用户字面约束”与“更合理/更完整”冲突时：用户点名的表名/表头/数量/口径逐字保留，不擅自扩展或润色。

## 何时用

- 生成/重建 `.xlsx`（报表、预算、经营数据、统计表、清单、财务模型）→ `write_xlsx`
- 读回已有 `.xlsx` 的内容用于仿制/分析 → `read_xlsx`
- 对已有 `.xlsx` 改单元格/加行/加表/替换文字 → `edit_xlsx`
- 触发词：Excel、表格、报表、预算、明细、统计、透视、xlsx、财务模型

## 工具链

- `write_xlsx(path, workbook?, workbook_file?, table?, name?, style?)`：三选一输入。
  **正式表格一律用 `workbook`（Workbook JSON）**——支持多工作表、表头、公式、数字格式、列宽、冻结窗格；
  `workbook_file` 先 `write_file`/`append_file` 分块写好 JSON 再导出（长表）；
  `table`（Markdown 表格/CSV/TSV）只适合一次性简单表，首行作表头、无公式无格式。
- `read_xlsx(path)`：读回 Workbook JSON。本应用生成的文件无损还原；外来 xlsx 近似导入（数值/文本/公式还原，样式细节丢失）。编辑前**先读它**。
- `edit_xlsx(path, ops)`：ops 为 JSON 数组（详见 workbook-dsl.md 的算子表）。外来文件自动备份 `*_原版备份.xlsx`。
- 数据来源：工作区已有文件（CSV/JSON/xlsx）用 `read_file`/`read_xlsx` 读取；大文件清洗转换用 `transform_file`（load_skill("data")）。
- 图片不进入 xlsx（Excel 嵌入图片本环境不支持）。
- 编辑/修复原则：先 `read_xlsx` 读回，再**最小改动**——只改任务要求的单元格/行/表，保留未要求改动的结构、公式与可保留的格式；外来文件备份是回滚快照，不要删。

## 开工前：拆解验收清单（所有工作流）

动手前把用户请求拆成**可逐条回读验证的清单**：产出文件名、sheet 名、表头/字段、指标、数量、公式、数字格式、单位/口径。用户点名的内容逐字保留，不缩写、不润色、不擅自扩展；交付前按清单逐项核对，找不到位置的“已完成”不算完成。

> 这条前置规则来自数据分析审计实践：先冻结“原请求 → 验收项”，再生成产物；不能事后用“更完整/更合理”替代用户字面约束。

## 工作流 A：新建工作簿

1. **前置提问**：`ask_user_question`（§3）。收到回答后确定用途、结构、口径、周期、素材。
2. 先对照验收清单确认：sheet 名（≤31 字符、唯一）、列含义、单位/口径、数字格式、哪些列是公式；用户点名/模板指定的名称与文字逐字照搬。
3. `list_files` 看工作区有没有可复用的数据文件；有就先读。
4. 规划工作表结构：不同主题分 sheet，不要全塞一张表；表头必给且列名简短。
5. **公式优先**：合计/同比/比率等派生值必须写成公式（`"=SUM(B2:B9)"`、`"=B2*C2"`），不要手算成数字——Excel 里改数自动联动，这也是财务表格的硬规范。
6. 组织 `workbook` JSON（语法见 `reference/workbook-dsl.md`，常用公式速查见该文件 §6），直接传 `write_xlsx`；长表先 `write_file` 写 JSON 文件再用 `workbook_file` 导出。
7. 交付前 `read_xlsx` 抽查：表名、行数、关键单元格、公式是否在；再对照验收清单逐条核对关键指标/数量/格式。
8. 写 `xlsx_qa_report.md` 并在最终总结附自检摘要。

最小示例（含公式 + 数字格式 + 表头）：

```json
{
  "name": "月度经营表",
  "sheets": [{
    "name": "收入",
    "headers": ["月份", "线上", "线下", "合计"],
    "rows": [
      ["1月", 120000, 80000, "=SUM(B2:C2)"],
      ["2月", 150000, 95000, "=SUM(B3:C3)"],
      ["合计", "=SUM(B2:B3)", "=SUM(C2:C3)", "=SUM(D2:D3)"]
    ],
    "formats": ["text", "money", "money", "money"],
    "freeze": "A2"
  }]
}
```

## 工作流 B：编辑/修复已有工作簿

### 常规编辑

1. `read_xlsx(path)` 拿到当前 Workbook JSON（外来文件会提示"近似导入"）。
2. 编辑前先确认原表约定：原表已有的表头、公式、布局是基线；只改任务要求的区域。外来文件样式细节若无法通过当前工具完整还原，要在交付说明中披露，不假装保留。
3. 按目标写 `ops` 数组，**一次调用完成一批操作**（单次 ≤50 个）：
   - **坐标约定**：`row`/`index` 按**数据行**从 1 起算、不含表头（与 read_xlsx 的 rows 一一对应）；有表头时 `row:1` 在 Excel 里显示为第 2 行。改表头单元格用 `set_header`。
   - 改单元格：`{"op":"set_cell","sheet":"收入","row":2,"col":2,"value":999}`
   - 改表头：`{"op":"set_header","sheet":"收入","col":2,"value":"电商收入"}`
   - 加行（插到第 3 位）：`{"op":"add_row","sheet":"收入","row":["3月",110000,70000,"=SUM(B4:C4)"],"index":3}`
   - 加表：`{"op":"add_sheet","sheet":{"name":"费用","headers":["科目","金额"],"rows":[["房租",5000]]}}`
   - 全局改词：`{"op":"replace_text","find":"线上","replace":"电商"}`
4. 补齐类只写空单元格；已有值（哪怕看着可疑）一律不动，最多在交付说明备注。
5. 批量替换/删除后做**残留复查**：搜索→替换→再搜索，尽量让旧值剩余命中数归零；回读采样覆盖前部、中段、表尾。
6. `edit_xlsx(path, ops)` 执行，返回摘要后 `read_xlsx` 抽查；**关键公式要核对“真实落格”**——只看到计算后的显示值不能证明联动，回读时要确认公式字符串仍在（参考 Doubao sheet）。
7. 外来文件改前会自动备份 `*_原版备份.xlsx`，不要删它。
8. 编辑完成后写 `xlsx_qa_report.md`（极小改动可精简报告，但最终总结仍需附自检摘要）。

### 修复/清洗场景

当任务是“修复文件”“公式报错”“清洗乱表”时，按同一工具链处理：

1. 先 `read_xlsx(path)` 读回，定位问题类型：
   - 公式错误：`#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`
   - 公式区间错：聚合公式漏掉末行、把表头算进范围、区间首尾超出数据
   - 数据问题：汇总行混入明细、错位表头、重复/空行、日期/数字被存成文本
2. 按问题写 `ops`：改错公式、修正引用范围、删除/去重、改表头、把文本型数值改回数值。只做任务要求的修复，不做无关重构。
3. 修复后 `read_xlsx` 回读验证：
   - 错误值是否已清除；
   - 关键合计/比率可复算，并与源数据或用户给定口径对账；
   - 公式区间起止正确，无循环引用，零值/负值/除零边界已处理。

## 工作流 C：数据分析、审计与报表交付

当任务不只是"建一张表"，而是"从数据到结论"时，按数据链路走：

1. **确定任务深度**：
   - L1 定向任务：查找、筛选、计数、对账、规则/阈值判定，只处理回答所需字段；
   - L2 诊断任务：比较、异动、漏斗或原因分析，区分事实、推论与待验证假设；
   - L3 综合任务：经营复盘、实验分析、正式报告/看板，仍逐项回答用户问题，不为格式制造结论。
2. **读数据**：工作区已有 CSV/JSON/xlsx → `read_file`/`read_xlsx` 先看结构与口径；用户给了原始材料但没整理 → 先 `list_files` 定位。建立逐附件读取回执：文件名/类型 → 成功或失败 → 实际读到的 sheet、字段、时间范围；未读附件不得进入“已完成”。
3. **清洗/转换**：脏数据、多文件合并、去重、抽列、正则提取 → `transform_file`（`load_skill("data")`），不要逐行手改。
4. **定口径**：确认指标定义（收入=含税/不含税？用户=去重/活跃？）、时间范围、单位。规则解释优先级：**用户明确规则 > 附件说明/数据字典 > 可观察字段和值 > 领域惯例 > 分析假设**；口径写进表头或单独"说明"sheet。
5. **审计与对账**：
   - 汇总行不得与明细重复参与同一次聚合；有明细时用汇总值回验，无明细时标明无法下钻；
   - 用稳定业务键（业务语义字段或复合键，不是展示名/行号）连接与对账；
   - 关键数字建立“源数据有效数 → 计算结果数 → 写入文件数 → 最终交付物回读数”四层对账；
   - 复合筛选缺字段时，分别报告可证真命中、可证伪不命中、未知量，不把未知当 0；
   - 缺失值不编造：源数据/附件查不到的事实数据留空 + 备注，不用估算值充数。
6. **建 Workbook**：按"假设与模型分离 + 公式优先"组织；派生值（合计/同比/占比）写公式，不写死数字；表外参数/来源/口径写进表头、说明行或单独说明 sheet。
7. **交付验证**：`read_xlsx` 抽查关键值/公式/格式，对账关键合计；写 `xlsx_qa_report.md`；向用户交付时给 1~2 句结论，不只丢一张表。

**表格设计要点**（详见 reference/format-guide.md）：

- 一表一事：不同主题分 sheet，不要全塞一张表。
- 表头必给且列名简短；单位/口径写进表头或说明行。
- 列宽按内容分配：短字段（编号/状态/日期）紧凑，长文本列放宽；数字列右对齐，文本列左对齐（通过格式与内容呈现）。
- 数据中间不插空行，避免破坏 SUM 连续区域。
- 新增内容要能被看懂：新增列给可区分含义的表头，不与原列同名；日期列转换先扫全列锁定月/日位，逐格凭感觉解析容易月日颠倒。

> 常见 Excel 报表（经营月报/预算 vs 实际/财务模型/明细+SUMIF 汇总/任务跟踪/台账/财务预算预测/三表预测）的工作簿蓝图、数据分析玩法，均已随 `load_skill("xlsx")` 全量加载；需要细节时可直接精读对应 reference。

## 速查：Workbook JSON

顶层 `{name?, style?, sheets[]}`；style：default / academic / minimal（表头配色）。
每 sheet：`{name, headers?, rows, colWidths?, freeze?, formats?}`。

- `rows`：二维数组，**矩形**（每行列数一致）；单元格值 = 数字 | 字符串 | `"=公式"`。
- `headers`：可选，有则首行加粗+底纹，列数必须与 rows 一致。
- `formats`：可选，每列数字格式 hint：`money`（¥千分位两位小数）、`int`（千分位整数）、`percent`（0.0%）、`year`（年份不加千分位）、`date`（m/d/yyyy）、`number`（千分位两位小数）、`text`/`plain`（默认）。
- `colWidths`：可选每列宽 1~255；`freeze`：可选如 `"A2"`（冻结首行）或 `"B1"`（冻结首列）。

## 能力边界（重要：不要承诺做不到的功能）

**支持**：多工作表（≤20）、表头加粗底纹、公式（SUM/引用/跨表）、数字格式（money/int/percent/year/date/number）、列宽、冻结窗格、read_xlsx 读回与 edit_xlsx 编辑。

**不支持**（用户要求时**明确说明做不到**，并给替代方案）：
- 合并单元格、条件格式、数据验证（下拉/范围限制）
- Excel 图表、数据透视表、宏、公式锁定/工作表保护
- 单元格样式细节（字体/底色/边框/对齐/行高、斜体加粗）
- 图片嵌入、超链接、批注
- 外来 xlsx 的样式保留（近似导入只还原数值/文本/公式；样式与合并丢失）

替代思路：条件格式/数据验证这类"防呆"需求 → 在表头或备注行写明填写规范；样式需求 → 在交付说明里描述期望样式，让用户用 Excel 一键加样式。

## 排版与数据规范（详见 reference/format-guide.md）

- **公式优先**：派生值必须是公式，禁止硬编码计算结果；合计行用 `SUM` 公式。
- **公式可审计**：公式尽量简单、可读；复杂计算用辅助单元格分步，让用户能从输入追到输出。写聚合公式前确认区间起止：起点跳过表头、终点覆盖真实末行；避免循环引用；除零/空值用 `IFERROR` 或前置判断兜底。
- **公式兼容性**：优先使用 Excel-2007 时代即可求值的函数（如 `SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT`）；若交付后出现 `#NAME?`，优先改用这些兼容函数，不要依赖 `XLOOKUP`、`SORT`、`FILTER`、`UNIQUE`、`SEQUENCE` 等可能无缓存/无溢出的新函数。
- **数字格式**：金额用 `money`、比率用 `percent`（存小数如 0.08 = 8%，不要存 8）、年份用 `year`（防 2024 变 2,024）、数量用 `int`。
- **类型保真**：数字、百分比、货币、日期用类型化单元格值，不要拼成 `"$1,234"`、`"30.5%"`、`"2024/01/01"` 文本；文本只用于编号、身份证、SKU 等真正需要字面保真的标识符。
- **小数纪律**：要求两位小数就整列 `money`/`number`，不要出现 12875 混 12875.00。
- **假设与模型分离**（财务模型）：假设集中放一个 sheet（如"假设"），模型区只写引用假设的公式，不写死数字。
- **编辑完整性/样式守恒**：只改目标单元格/行，不动其它数据；编辑已有表时，原表未被要求调整的结构与格式保持不动；补齐只写空单元格；交付前 read_xlsx 验证表名与抽样数据还在。
- **口径与来源**：单位、口径、来源等元信息放表头、副标题或说明 sheet，不占用已有表头格/数据格；表外参数写明取值依据，未知/待核实写“暂未发布/未知/待核实”，不伪造来源。
