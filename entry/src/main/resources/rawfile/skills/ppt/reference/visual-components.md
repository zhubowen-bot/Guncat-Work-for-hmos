# PPT 视觉组件目录（参考 QwenWork pptx components）

在真实平台中，以下 12 类视觉组件是经过设计的"难对齐形状"；我们的 `write_pptx` 没有 python-pptx 组件库，因此**用原生版式 + write_svg 组合实现**。先判断内容该用哪种组件，再决定实现路径。

## 选型流程

```
需要展示…
├─ 单个大 KPI 数字？          → 指标区（KPI strip），2~4 个并排
├─ 引语/CEO 一句话？          → quote 页
├─ 2~4 个选项并排？           → 对比页（两栏/三栏/2×2）
├─ SWOT / 2×2 矩阵？          → SVG 象限图（写 svg 技能）
├─ 多维度评分？               → SVG 雷达图
├─ 转化/漏斗？                → SVG 漏斗图
├─ 项目排期？                 → SVG Gantt 或原生表格
├─ 阶段里程碑？               → SVG 时间轴/路线图
├─ 预算/占比分解？            → SVG 分配条/条形
├─ 核心资产+环绕节点？        → SVG 飞轮图
├─ 嵌套层级？                 → SVG 同心层图
└─ 多层架构？                 → SVG 分层架构图
```

## 组件要点（移植自 QwenWork）

| 组件 | 何时用 | 不要用于 | 实现路径 |
|---|---|---|---|
| metric_card / KPI 指标区 | 一个页面突出一个头部数字；2~4 个并排做 KPI strip | 多行统计表（用表格）、叙述文本 | content 页大数字 + 细线分隔；避免圆角卡片（除非 fallback） |
| quote_block | 引语、设计原则、策略 callout | 长段落、标题下小字 | `quote` 版式；左竖线/深色块 |
| comparison | 真正的对比：旧 vs 新、我们 vs 竞品、A vs B | 平行概念（用普通列表） | `two-col`；featured 推荐项放右侧 |
| swot | SWOT、机会/风险矩阵、概率×影响 | 普通四卡网格（象限要有轴含义） | write_svg 象限图；每象限 3~5 条 |
| radar | 4~6 维评分 | 3 维以下（三角不像雷达）、多系列 | write_svg 雷达图；单系列 |
| funnel | 逐级缩小的转化 | 等宽流程（用时间线/流程） | write_svg 漏斗；宽度递减 |
| gantt | 带时间轴的任务条 | 每阶段是讨论项（用 timeline） | write_svg 甘特图或原生表格 |
| timeline | 阶段路线图 + 交付物/关卡 | 任务级排期（用甘特） | write_svg 时间轴；3~6 阶段，当前阶段深色 |
| allocation_bars | 预算/收入/时间占比分解 | 7+ 项（用图表） | write_svg 分配条；2~6 项 |
| flywheel | 核心资产 + 3~6 个环绕力量 | 层级（用分层图） | write_svg 飞轮；节点 3~6，标签 8~14 字 |
| layered_diagram | 核心到外层的嵌套 | 平铺序列 | write_svg 同心圆；外层浅、内层深 |
| flow_matrix | 多层架构/生态/能力分层 | 普通卡片网格（每行必须有层级含义） | write_svg 分层架构；每行 2~4 节点 |

## 组件使用边界与阈值（参考 QwenWork components.md）

**什么情况不要用组件**：

- 纯文本、标题、要点、单图、双栏正文、简单表格、基础柱/折/饼图、单个图标 callout——直接用原生版式，不需要组件。
- 如果发现自己在连写 4 个相同矩形来搭一个结构，先查组件目录；但反过来，**强行套用不匹配的组件比直接搭更糟**——目录没有合适项时用原生版式。
- 对比页只用于“真正有胜负/取舍的对比”；平行概念（三件事我们提供什么）用普通列表，不要套 comparison。
- SWOT/2×2 象限要有“轴含义”；普通四卡网格不是 swot。
- 雷达图只用 4~6 维且单系列；3 维以下三角不像雷达，多系列改用图表。
- 漏斗只用于逐级缩小的转化；等宽阶段用时间线/流程，增长型用图表。
- 时间线用于“阶段讨论+交付物+关卡”，任务级排期用甘特。

**阈值速查**：

| 组件 | 内容阈值 | 关键约束 |
|---|---|---|
| KPI strip | 2~4 个并排 | `value` 是一条原子显示行，不要靠换行拆数字与单位；一页最多一个 primary 强调卡 |
| comparison | 2~4 面板 | 2 面板水平+VS，3 面板水平无 badge，4 面板 2×2；featured 固定右位 |
| swot | 每象限 3~5 条 | 画布 ≥8×6.5 in，太挤会压扁 |
| radar | 4~6 维、单系列 | 宽容器可图左注右 |
| funnel | 阶段数不限 | 宽度由内容控制；颜色自上而下由浅到深 |
| gantt | 任务条数不限 | 组件只拥有图区，标题单独放上方 |
| timeline | 3~6 阶段 | N 个阶段需要 N+1 个边界日期 |
| allocation_bars | 2~6 项 | 7+ 项用图表；`value` 是数据不是大标题 |
| flywheel | 中心+3~6 节点 | 节点 5~6 时加宽容器防标签碰撞 |
| layered_diagram | 2~6 层 | 外浅内深，纯色填充，不要堆矩形冒充同心圆 |
| flow_matrix | 每行 2~4 节点（最多 5） | 行必须有真实层级含义，普通卡片网格不要用 |

**House style 例外**：默认全方角、无阴影；唯一有意例外是 `allocation_bars`/进度条本体保持胶囊圆角（进度条惯用形），但仍然扁平、无阴影。

## 通用纪律（来自 QwenWork components 与 Doubao slide-taxonomy）

- 所有组件方形直角、扁平、无阴影；不用圆角卡片（fallback 除外）。
- 每页组件数量克制：一个视觉页元素 8~20 个（grouped），不要手堆 40~50 个矩形。
- 一页最多一个 `primary`/强调色变体；全页都强调 = 没有强调。
- 复杂形状优先 `write_svg` 生成，不要在 `write_pptx` 里硬堆 shape。
- 交付前 read_ppt/渲染检查重叠、越界、对齐。

## Authoring 陷阱校准（参考 QwenWork authoring.md，适配 Deck JSON / write_svg）

**坐标与版式**
- 所有元素必须落在画布内；`custom` 元素坐标/宽高 0~1，写完后按“元素是否越界、是否互相重叠”做一次机械检查，不要等渲染后才看。
- 有模板时，模板自身保留的页眉/页脚/页码是“内部安全区”，不要在它上面压内容。

**文字**
- 同一册引号风格统一（不要直引号/弯引号混排）。
- **CJK 字体不要预置**：现代 PowerPoint 会自动替补东亚字体；不要预先给每段指定 Noto/思源等字体名（会造成闪动/豆腐块）。只有用户报告豆腐块并给出确认的字体名时才处理（参考 QwenWork authoring.md）。
- 正文/要点/描述允许换行；KPI 数字、日期、ID、短标签等“原子显示文本”不要用换行硬塞，优先缩短、加宽或减少卡数。
- 不要用缩小字号/自动缩放掩盖溢出；真实修法是删内容、加宽容器或拆页。
- 正文不要居中，默认左对齐；只对标题、KPI 值、短标签这类刻意展示文本居中。

**形状与组件**
- 默认方角矩形；圆角/胶囊只在它是有意设计时使用，全册到处圆角是 AI 生成痕迹。
- 不叠加阴影/渐变；继承主题阴影也要显式去掉。
- 组件之间传独立色值，不要共用一个被多次修改的样式对象（对应到 Deck JSON：每页/每元素写清自己的颜色字段，不依赖“上一页改过的默认值”）。

**图片**
- 需要照片/地图/截图/logo 时使用真实图片，不要用矩形+文字拼一个“示意图冒充实拍”。
- 图片不要拉伸变形：`image`/`image-full` 用 `fit:"cover"`（填满裁剪）或 `contain`（完整显示），不要硬塞进不成比例的槽位。
- 图文内嵌图四周留白均匀；贴一边而另一边留大空会像错位。
- 封面/分节页/引语页等构图槽位不要“缩进去”：图片应铺满槽位，必要时裁剪溢出。
- 标题下不要加一条装饰性彩色细线：这是常见 AI 痕迹，用留白、背景色或标题本身粗细对比代替。

**可读性与层级**
- 避免低对比：浅底浅字、深底深字、图标颜色等于容器填充色都要修。
- 每页要有一个视觉落点（图表/图片/组件/强排版/风格化装饰 SVG），但不要为了“有图”而加**无关照片/与风格不符**的配图；V3 要求的每页装饰是统一视觉母题/纹理，不是无关配图。
- 跨页节奏由信息架构决定：重复能帮助比较就重复，变化能帮助理解才变化；不要为了“不重复”硬加媒体/组件。
