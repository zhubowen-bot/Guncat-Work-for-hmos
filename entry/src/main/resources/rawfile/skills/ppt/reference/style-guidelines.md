# ChatGPT 演示文稿风格指南（Style Guidelines 移植）

来源：`chatgpt/plugins/openai-primary-runtime/presentations/26.805.11740/skills/presentations/style_guidelines.md`。
这些是 ChatGPT 做每份 deck 时应用的通用原则；与 Doubao 场景设计系统叠加使用：Doubao 决定视觉场景，本文件决定叙事与文案。

## 1. 先定义沟通任务

不要急着选模板/配色。先写一句：

> 到结束时，**[目标受众]** 应该 **[结果/行动]**，因为 **[核心信息]**。

- 受众不一定是用户本人。
- deck 的任务可能是：教育、说服、销售、推荐、促成讨论、支持决策。
- 探索/参考型 deck 不强制给推荐，但要让受众带着明确的问题/理解离开。

## 2. 选择叙事弧

可选的叙事结构：

- 背景 → 利害 → 证据 → 启示 → 行动
- 问题 → 分析 → 答案
- 问题 → 原因/选项 → 推荐
- 现状 → 变化 → 未来
- 时间线 / 流程 / 学习进阶 / 论点 → 证据 → 结果

**目录不是叙事**；每一节都要为下一节制造需求。技术/参考型 deck 用逻辑、因果、时间、决策流推进，不硬套情绪化弧线。

## 3. 每页推进故事

- 每页一个叙事任务 + 一个主论断。
- 标题用"takeaway 式"而非"主题式"：写出结论，不只写章节名。
- 页序要让每页回答上一页提出的问题，或引入下一页要解决的问题。
- 删掉重复总结、多余过渡和与主线无关的内容。
- 用户给的视觉参考是约束，但不要复制无关结构、削弱叙事。

## 4. 把证据变成意义

- 不要罗列事实/指标/图表；每个证据都要说明：对受众意味着什么、为什么重要、如何改变结论/决策/下一步。
- 图表必须支撑当前页论断。
- 禁止编造人物、引语、事实、数据、结果。

## 5. 开头结尾有设计

- 开头用背景、目的、利害、问题或张力让受众值得看。
- 结尾回应开头：推荐/决策、明确行动、综合/应用、启示/有效问题。
- 不要以细节、技术产物、无框架总结或通用"谢谢"收尾。

## 6. 自然、面向受众的文案

- 可见文案不得暴露模型指令、规划笔记、时间支架、talk track。
- 标题和正文用具体、直接、自然的语言；避免"From X to Y"套模板、广告式碎片、机械对仗。
- 标题要像真人 presenter 会说出口的话；如果像提示词/口号生成器，就重写。

## 7. 构图纪律

- 全册视觉系统一致，但页面剪影要随内容变化。
- 标题页极简。
- 优先低密度高价值页面：先缩短文案或换版式，不要缩字号。
- 默认左右边距相等；避免拥挤和过度留白。
- **避免卡片网格、pills、徽章、按钮式文本框、tab、导航样式、密集 dashboard**——这些是组件库 UI 风格，暗示可交互。
- 少用花哨文本框，优先扁平结构。

## 8. 字号与适配（无用户指定时）

- deck 标题 ≥50pt
- 页标题 ≥35pt
- 副标题/callout/文本框标题 ≥24pt
- 正文 ≥16pt
- 检查意外换行：**单行标题/横幅绝不允许折成两行**；文案太长就缩短或换版式，不要靠缩字号或加密度硬塞。

## 与 Doubao 场景系统的关系

- 本文件管"讲什么、怎么讲"；`design-guide.md §0` 管"选哪套视觉系统、哪些硬规则"。
- 两者冲突时：用户明确要求 > 模板/品牌规范 > Doubao 场景规则 > 本通用文案/构图原则。
