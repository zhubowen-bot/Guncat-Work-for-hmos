# 常见演示文稿蓝图（Deck Blueprints）

面向不同任务给可直接套用的页面蓝图：**先按蓝图规划 → 再写 Deck JSON → 生成 → 自检**。
蓝图只规定页面节奏和每页信息职责，具体文案/数据必须来自工作区资料，禁止编造。

> **V3 篇幅门**：下表蓝图是**最小骨架**，不是页数上限。新建 PPT 默认 20 页以上：在蓝图每节补足 2~5 页内容页（背景/数据/案例/对比/问答/行动），可加开场页、证据页、方案页、风险页、行动页；用户明确指定更少才可少于 20 页。

> **关于"卡片"的说明**：蓝图里的"KPI 卡/卡片"只表示"内容块位置"。实际生成时，除 fallback 场景外，**不要用圆角矩形卡片搭建层级**——用大数字 + 细线 + 留白 + 字号对比实现同样功能；见 `design-guide.md §0`。

## 通用页面节奏（所有 deck 的骨架）

```
cover → toc(≥6页) → section → 内容页×N → section → 内容页×N → end
```

- 内容页 3~7 条要点或一个图表/表格；数据页用 chart/table，不要用要点复述数据。
- 相邻页避免同版式连用；每页一个主角。
- 所有关键来源/口径写 notes，页面 caption 只放一句来源。

## 蓝图 1：经营复盘 / 季度汇报

适合：周报/月报/季度经营分析、业绩复盘。

| # | 版式 | 内容职责 | 建议 |
|---|---|---|---|
| 1 | cover | 标题=结论（"Q3 营收 1.2 亿，同比 +18%"） | subtitle 写时间+汇报方 |
| 2 | toc | 3~6 章 | 与 section 逐字一致 |
| 3 | section | 业绩概览 | — |
| 4 | chart(line) | 整体趋势 | 月度营收/利润，单位写系列名 |
| 5 | table | 核心指标对照 | 计划/实际/同比，≤6 列 |
| 6 | content | 关键结论 3~5 条 | 每条一个事实+数字 |
| 7 | section | 问题与归因 | — |
| 8 | chart(bar) | 分区域/分产品对比 | 找差距最大的维度 |
| 9 | two-col | 亮点 vs 风险 | 不要空话，各 3 条 |
| 10 | section | 下季度计划 | — |
| 11 | content | 3 个优先级行动 | 每项有负责人/时间 |
| 12 | end | 谢谢/讨论 | notes 放附录口径 |

## 开场与结尾页通用结构（参考 ChatGPT presentations style_guidelines + Doubao ppt）

- **先写一句 communication job**：`By the end, [受众] should [结果] because [核心结论].` 探索/参考型 deck 不硬造推荐，改为定义“受众离开时应带走的问题/理解”。
- **选一条叙事弧**：context → stakes → evidence → implications → action；question → analysis → answer；problem → causes/options → recommendation；current state → change → future state。**Agenda 不是叙事**：章节顺序要有累积性，每节为下一节制造需求。
- **开场要“值得听”**：封面/第一张内容页用上下文、目的、利害、问题或张力打开，不要一上来就是干巴巴的目录。标题页保持极简：只放标题/副标题/日期/汇报方，不塞要点。
- **结尾要“回应开场”**：结尾页落在一个结果上——建议/决策、明确行动、综合应用、含义或可推进的问题；不要突然结束在某个技术细节、未定调总结或通用“谢谢观看”。
- **每页推进故事**：每页一个叙事任务 + 一个主论点；标题用结论式表达；顺序上让每页回答上一页留下的问题，或引入下一页要解决的问题。
- **每页 notes 给 3~5 句可读讲稿**（参考 Doubao ppt Step 7）：讲稿/口径/完整来源放 notes，可见页只写面向观众的话。

## 模板保真原则（参考 ChatGPT artifact-template 系列 + Doubao ppt 模板处理）

- 用户给参考 pptx/docx/xlsx 或明确"按某模板"时，**参考文件是设计权威**：不套通用蓝图覆盖它。
- 用户给的是"风格参考"而非逐页模板时：先看渲染效果，提炼可迁移的版式手法/风格/图形语法，再按场景设计系统搭建，不逐页照搬。
- 用户给的是"严格模板"（要求套用版式）：保留版式/字号/视觉系统再填内容；不能修改字体、背景图、品牌标识、真实人物/照片、原始文案、专属色值、装饰纹样。
- 模板槽位不硬填：没有真实数据时保留占位说明并告知用户，不编造事实填满模板。

## 从蓝图到 Deck 的步骤

1. 选蓝图 → 按实际内容增删页（每节 2~5 页内容，不要一节一页）。
2. 每页写"一句话任务"，写不出就删页。
3. 数据页先确认数据来源：工作区文件/搜索记录/用户提供。
4. 写 Deck JSON（长 deck 用 deck_file 分块写）。
5. 生成后 read_ppt 抽查 + 按 SKILL.md 自检清单复验。
