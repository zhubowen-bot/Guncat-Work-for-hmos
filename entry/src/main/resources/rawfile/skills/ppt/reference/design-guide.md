# PPT 设计规范

面向工作模式生成演示文稿的质量底线。按此执行，不依赖默认审美。
> **V3 追加：每页必须有视觉装饰，禁止纯色背景+文字；全册至少双色以上混搭。** 风格与纹理/勾边/图案/花色配方见 `reference/visual-styles.md`，主题扩展见 `reference/themes.md`。

## 0. 设计系统与场景路由（参考 Doubao slide-taxonomy / QwenWork pptx）

动笔前先确定**唯一主场景**，全册按该场景的设计语言执行；用户模板/品牌规范/配色/字体优先于本指南。

| 场景 | 典型诉求 | 读者任务 | 设计语言要点 |
|---|---|---|---|
| 分析决策 | 咨询、金融、行业研究、战略、投资分析 | 比较选项、形成判断、支撑决策 | 克制、数据表格、图表、来源可溯 |
| 商业提案 | 营销方案、融资路演、商业计划书 | 理解价值、相信方案、采取行动 | 封面有冲击力、章节节奏、方案对比 |
| 管理汇报 | 工作汇报、项目复盘、季度总结 | 掌握现状、暴露问题、确认行动 | 结论先行、指标区、风险与行动 |
| 学术研究 | 论文答辩、科研项目、开题/结题 | 评估问题、方法、证据与贡献 | 严谨、文献/证据、图表规范 |
| 教育培训 | 课件、教学演示、科普 | 理解、记住、正确应用 | 亲和、循序渐进、示例与练习 |
| 技术工程 | 架构评审、研发报告、技术方案 | 看清结构、依赖、指标与取舍 | 架构图、依赖、决策矩阵 |
| 品牌/创意 | 品牌故事、设计提案、作品集 | 建立认知、留下记忆 | 强视觉、氛围图、少而精的文字 |
| 兜底 fallback | 以上都不匹配 | 信息密度高的图文卡片 | 才允许卡片化布局 |

**硬性规则**：

- **每页必须有视觉装饰 + 内容配图**：内容页（content/two-col/table/chart/image-text/quote/custom）每页至少有一个装饰性 SVG/纹理背景（`background.image` / custom 元素），并且至少有一个**内容性配图**（流程图/时间轴/架构图/对比图/插画/信息图/数据可视化），不能只有纯文字+小图标；封面/分节/结尾页同样要有设计母题或大幅配图。禁止“纯色背景+纯文字”的裸页。
- **配色至少两色以上混搭**：用 `themeOverride` 把 primary/accent/bg/surface 扩成双色以上，禁止只用一个主色平铺。
- **匹配到七个场景之一 → 禁止用卡片搭建层级/对齐**；改用线条、留白、字号对比。只有 fallback 场景才允许卡片化布局。
- 每页主色 ≤3 种（不含图片/纹理渐变）：2~3 色混搭，禁止彩虹色和文字/背景靠色。
- 结构化信息（数据对比/指标清单/参数/维度）必须用**原生表格**，不得在页面输出 Markdown 表格。
- 涉及外部事实/数据必须标注来源、日期/时间区间、口径；来源用链接指向原始页面（当前可用 caption/notes 近似）。
- 封面/结尾/章节分割页禁止随意抽象 shape；用高质量图片或极简排版。风格化装饰 SVG（纹理/角标/母题）可以作设计元素，但不能堆砌无意义图形。
- 用户给了模板时，先看渲染效果，提炼可迁移的版式/风格/图形语法，不逐页照搬；不能修改字体、背景图、品牌标识、真实人物/照片、原始文案、专属色值、装饰纹样。
- **全篇禁止 emoji**（参考 Doubao ppt Step 7）：任何位置都不要用 emoji 当图标或正文；需要图标用 `write_svg` 生成语义图标或版式元素。

**版式安全区（参考 QwenWork pptx layouts）**：画布 13.333×7.5 in；安全边距左右 0.6、上下 0.55；所有元素必须 `x+w≤13.333`、`y+h≤7.5`；默认不制造意外重叠。

## 1. 页面节奏

**默认 20 页以上**，典型 20~30 页结构：

```
cover → toc(≥6页时) → 开场/背景 → section → 内容页×3~5 → section → 内容页×3~5 →
section → 数据/证据页×2~4 → section → 方案/结论页×2~4 → 行动/下一步 → end
```

- 内容页是大头；每个 section 下 2~5 页内容，不要一节一页。
- 一页一个任务：一页只讲一个观点/一组数据/一张图。写不出这页的任务就删掉它。
- 数据密集内容优先 table/chart，不要用要点列表复述表格。
- 常见场景（经营复盘/商业计划/技术分享/培训/路演）的完整页面蓝图见 `deck-blueprints.md`。

## 2. 标题即结论

- 内容页标题写判断句，不写话题词："营收同比 +18%，超预期" ✅；"营收情况" ❌。
- 标题 ≤20 字；超了说明页面承载过多，拆页。

## 3. 要点纪律

- 每页一级要点 3~7 条，每条一句话（≤25 字）；二级要点做补充事实或数据。
- 要点并行：同一页内要点语法结构一致（都是短句或都是"指标+数值"）。
- 禁止把整段文字塞进要点；成段的论述交给 docx，不是 pptx。

## 4. 图表语言

- 选型：时间趋势 → line；类目对比 → bar；构成占比 → pie/doughnut（≤5 块）；累计 → area。
- 一个图表一个信息点； series ≤3 个（超过就拆图）。
- categories 是类目名（短），values 是数值；单位写进 series name 或 caption。
- **数据必须来自工作区文件/搜索记录，禁止编造**；caption 标注来源与口径。
- 数字用阿拉伯数字，金额给单位（万/亿），比例给百分号。

## 5. 表格纪律

- ≤20 行、≤6 列；超出就拆页或转 chart。
- 首行是表头；行内同类信息对齐；长文本单元格压缩为短语。

## 6. 图片使用

- 优先级：用户提供的 > 工作区已有（pdf_to_images 产物等）> http(s) 直链；没有合适的就不放图。
- **装饰性 SVG 是每页标配**：不是“图片凑数”，而是全册视觉系统的一部分——用 `write_svg` 生成纹理/角标/母题，按 `reference/visual-styles.md` 的风格配方执行，`write_pptx` 通过 `background.image` 或 custom 元素引用。
- **内容配图 SVG 也是每页标配**：把要点/流程/架构/时间线/对比/概念转成流程图、时间轴、架构图、对比图或简单插画；用 `image-text` / `custom` 放进页面，而不是让整页只有文字。
- 图片不凑数：与内容无关的装饰图会拉低质量；但“有语义或克制的风格化 SVG 装饰”和“讲内容的内容配图”都是本技能要求的，不是无关配图。
- 全幅图（image-full）配 overlay 0.4~0.6 的封面用法；image-text 时图占 40%，文字要点在另一侧。
- 引用 PDF 图表截图时在 caption 标注出处（"来源：《xx 报告》P12"）。
- **透明背景处理**（参考 Doubao ppt 图片去底色经验）：图片要放在深色/彩色背景上时，优先用透明背景素材（PNG/SVG）；若素材带白底/黑底，不要直接压在不匹配的彩色背景上——要么选与背景色一致的素材，要么用 image-full 或整块色板承接，避免出现明显的矩形底块。黑白灰底图最影响观感；渐变底/复杂背景不建议硬抠。
- **背景/封面图不应带文字**（参考 Doubao ppt Step 3）：用于背景或封面的图片生成/检索后要检查，出现文字就换图或重做，不能把带文字背景直接垫在标题后面。

## 7. 文风禁令

- 禁止：闭环、赋能、抓手、颗粒度、组合拳、底层逻辑、 综上所述。
- 禁止 AI 腔："不是 X，而是 Y"句式滥用、"总而言之"、"值得注意的是"堆叠。
- 禁止空话："取得了良好的效果"、"迈上新台阶"——换成数字或事实。
- 全文用用户的语言；中文 deck 内的专有名词保留原文。

## 8. 场景速配

| 场景 | 主题建议 | 版式侧重 |
|---|---|---|
| 工作汇报/经营复盘 | brand-blue / graphite | content + chart + table |
| 方案/商业计划 | forest / sunset | cover+section 节奏 + two-col + table |
| 技术分享 | midnight / violet | content + image-text + custom |
| 教学/培训 | ivory / brand-blue | content + two-col + image |
| 发布/路演 | crimson / sunset | 大图 cover + chart + quote |

## 9. 一致性检查（交付前）

- 全册只用一个 theme；不要每页混用背景色。
- 同级标题字号一致（由版式保证，勿在 custom 里乱设 size）。
- 时间口径统一（"Q3"/"7-9月" 二选一），货币单位统一。
- notes 可为关键页补充口径说明（不会被观众看到）。

## 10. 版式多样性（AI 生成的典型失败模式）

- **连续重复版式是大忌**：content 三连、chart 两连都是"一眼 AI"信号。相邻页至少换一种表达：要点→表格→图表→图文→引用轮换。
- **每页一个主角**：一页只突出一个视觉元素（一张大图或一个图表），其余收敛为文字；全页塞满三个图表 = 没有一个被看清。
- **图文比例**：image-text 页图占一侧 40~55%，文字侧只放 3~5 条短要点；别让图和文字各占一半互相挤。
- **不要"标题+4 条要点"到底**：8 页以上的演示，纯要点页 ≤ 一半；纯要点页也必须用装饰背景/角标 SVG 避免裸页。
- **每页装饰一致性**：全册统一使用同一套纹理/角标/母题（见 `visual-styles.md`），不要每页换一种装饰风格。

## 11. 好/坏对照

| 坏 | 好 |
|---|---|
| 标题"经营情况" | 标题"营收 1.2 亿，同比 +18%" |
| content 三连页，全是 5 条要点 | 要点→表格→图表轮换 |
| 一页塞 3 个图表 | 一页一个图表 + 数据解读要点 |
| "同比增长 18%……综上所述……" | "营收 1.2 亿，同比 +18%（来源：财务中台）" |
| 配一张无关的通用配图 | 不放图，用表格/数据卡表达 |
| 深色主题配深色文字（看不清） | 深色背景自动反白为浅色文字 |

## 12. 听众视角与来源可追溯（参考 ChatGPT presentations skill）

- **可见内容写给最终观众**：页面不得出现"此处放图""我要讲""内部备注"等过程语言；讲稿/口径/完整来源放 notes。
- **来源规则**：
  - 页面 caption 写关键来源（"来源：财务中台""来源：《xx 报告》P12"）；
  - 外部数据、非平凡主张在对应页 notes 写完整出处（报告名/URL/日期/口径）；
  - 没有来源的数据不出现；宁可少写一个数字，也不编一个数字。
- **交付后读回核对**：用 `read_ppt`/`read_file` 抽查最终文件，确认页面上没有残留过程注释、来源标注和文字截断。

## 13. 信息密度与字体纪律

- **高价值内容优先**：低价值细节拆页、放附录或删掉，不堆在同一页。
- **文字太多时优先缩短文案**，其次换版式（要点→表格/图表），最后才考虑缩小字号；标题框/横幅文本框换行是"信息超载"信号，必须改文案或换版式。
- **每页一个主角**：一个页面只突出一个图表/图片/数据卡，其余收敛为短文字；不要做成组件库式 UI（卡片网格、徽章、按钮框、仪表盘）——用扁平、留白、清晰层级。
- **封面极简**：标题页只放标题/副标题/日期等必要信息；封面塞满要点是常见失败模式。

## 14. 字号下限与硬性视觉检查（参考 ChatGPT presentations skill）

- **无模板时字号下限**：deck 标题 ≥50pt；页面标题 ≥35pt；副标题/小标题/引用头 ≥24pt；正文 ≥16pt。
- **有模板时**：跟随模板字号，不要自创更小字号。
- **重叠是硬性错误**：生成/编辑后必须读回检查元素是否重叠；任何重叠都要先确认是设计意图，不是 bug——默认按 bug 修复。
- **单行标题框**：标题/横幅文本若预期单行，绝不允许换行成两行；超了先缩短标题。
- **视觉资产**：能用 `write_svg` 画的是图表/示意图/图标，不是照片级图片；不要用代码硬画照片/插画。

## 15. 模板跟随（用户给了 pptx/参考 deck 时）

- 用户提供 pptx 或参考 deck 时，**先 `read_ppt` 读取并保留模板的结构**：主题、版式、字号、页眉页脚/页码、视觉系统都是模板契约。
- 不要用通用 theme/版式覆盖模板；只在用户明确要求时才换风格。
- 在模板上编辑时最小改动：改文字/数据，不重排版式；页面顺序调整用 `move_slide`，全局换词用 `replace_text`。
- 交付后 `read_ppt` 抽查，确认没有破坏模板的统一元素（如底部标识、页码）。

## 16. QwenWork 模板编辑与从零构建原则（适配 Deck JSON / edit_ppt）

参考 `qwenwork/skills/pptx/editing.md` 与 `from_scratch.md`，把“模板容量/执行债务/视觉指纹”翻译到当前工具边界：

- **模板先 QA 再复用**：拿到模板后先 `read_ppt` 看结构，确认它的版式数量是否撑得起计划页数。不要为了“严格沿用模板”而把 8 种不同信息架构硬塞进 2 个重复版式；也不要因为模板漂亮就直接忽略它装不下的内容。
- **品牌身份 ≠ 执行债务**：模板的配色、字体、logo、页码、页脚、章节顺序是用户意图，必须保留；模板里的对齐漂移、装饰性空形状、只适合少量要点的布局，是“执行债务”，可以在模板自己的色板和字体下用 `custom`/`visual-components` 升级，而不是原样复制到每页。
- **少项模板槽位要整体删除**：模板某一页有 4 个成员位但用户只有 3 个时，删除第 4 个成员的整组元素（图片+文本框），不要只清空文字留一个空位。
- **加长文本必须先验证放不放得下**：替换为更长内容后可能溢出/换行；`read_ppt` 或渲染检查通过才叫完成，文本“存在”不等于“排得下”。
- **从零构建先锁定视觉指纹**：动笔前确定调色板、图片风格、封面轮廓、内容页轮廓、母题（motif）和 `forbid` 清单；全册保持一致，但不要为了保持指纹牺牲内容清晰度。
- **硬形状优先用组件/蓝图，不手工堆砌**：甘特/漏斗/SWOT/飞轮/分层/雷达/时间线等复杂视觉用 `reference/visual-components.md` 的组件化路径；手工堆 shape 容易产生细微错位。
- **新建 PPT 前置提问是硬门**：开篇用一次 `ask_user_question` 问全页数、风格、受众、素材、硬约束（见 SKILL.md §3）；编辑/读取场景才按“没有不确定项就跳过提问直接做”执行。

## 17. 真实图片与无图兜底原则（参考 QwenWork from_scratch）

- **封面/分节页/引语页等“锚点页”优先用真实照片**；内容页可以用图表、KPI 卡、图标、组件满足“有视觉”，不一定需要照片。
- **主题型 deck（城市、产品、工厂、人物、建筑、发布会）至少有一张真实照片**；如果当前工具链没有可用的真实照片，使用完整的无图版式（如大字封面、引用块、组件图），不要用空占位框或“此处放图”。
- **logo 用真实文件/下载素材，禁止用形状拼一个假 logo**：拿不到真实 logo 时，降级为纯文字品牌名。

**具体执行（QwenWork from_scratch § Fetching real photos 翻译到当前工具链）**：

1. **一个 deck 一个 `image_style`**：选方向时定下图片风格后缀，所有图片生成/检索都沿用同一条风格描述，保证全册照片看起来是一套。
2. **按版式定纵横比**：全幅封面/图半分栏用 16:9，方形插图用 1:1，只有竖排版式才用 9:16；先算好槽位比例再找图。
3. **先落盘再引用**：选中的图保存为工作区本地文件（如 `assets/cover.png`），再以相对路径或 data URL 放进 deck；不要把会失效的临时 URL 留在 pptx 里。
4. **每个图片槽位都预想兜底**：在开始前就定好该槽位失败时的完整无图版式（纸纹封面、引用块、组件、文字主导构图）。失败后用预定兜底并说明，不要在失败后才临时发明。
5. **禁止拿手绘/形状冒充图片**：不要用 `write_svg` 画一个矩形+文字代替照片，也不要用几何图形（圆形+首字母、色块网格）假装成用户要的图。
6. **返回图尺寸/比例不对时先适配再放弃**：轻微不符 → 主体保留裁剪；大幅不符 → 调整图片槽位并重排周围内容；槽位不能动 → 用 `contain` + 有意的方向协调背景，避免意外留白；以上都不可读才用无图兜底。

**素材兜底优先级（参考 Doubao ppt Step 7）**：

1. 主视觉优先用真实素材，**绝不留空白图框**。
2. 缺图先搜图/生图补这一页要用的图；补不到或不可用，用生成的近似图/抽象图。
3. 生图也不可用，才用结构图（SVG shape/line）表达，而不是假装成照片。
4. 数据类可视化缺真实数据时**不要编造数字**：优先换成不依赖数据的表达（结构图、要点、定性对比）；确需图表占位才标注「模拟数据，仅占位，待替换真实数据」。
5. 附件中提取的图片/表格可缩放适配排版，但**不做裁剪**，避免丢失原始信息。

## 18. 视觉方向与指纹（参考 QwenWork visual-directions）

> **V3：本节的四个方向是“构图指纹”；具体风格目录（科技/古风/简约/杂志/商务/学术/路演等）与纹理/勾边/花色 SVG 配方见 `reference/visual-styles.md`。** 从零构建（无模板/无品牌规范）时，先选一个**视觉方向**，不要直接进入“每页填内容”。QwenWork 给出四个可复用起点；它们不是封闭目录，但足够覆盖大多数场景。

| 方向 | 适合 | 色系/图像 | 封面轮廓 | 内容轮廓 | Motif | Forbid |
|---|---|---|---|---|---|---|
| **Institutional restraint** | 投资/经营复盘/汇报/研究/学术摘要 | 深藏青或石墨主色 + 象牙底 + 单一金色/柔红强调；真实摄影 | 双面板：深色标题栏 + 浅色单张 hero 照片，一条细线分隔 | KPI strip、2~3 栏对比、带状态列的证据表、时间线 + 里程碑卡、一页结语 | 细强调线在章节标题/hero 照片下重复出现；全方角 | 圆角卡片、阴影、渐变、满页装饰图标、三张相同卡片行 |
| **Editorial story** | 城市/文化/品牌长读/回顾/杂志风 | 暖中性底色 + 一个来自主题的高饱和品牌色；真实编辑摄影，大图优先 | 全幅照片 + 角落标题块，或偏置标题 + 纸纹理 | 一句话陈述页、图左/图右分栏、宽幅照片页、单数字数据 hero、结尾照片 | 细线 + 小 folio 页码；一个贯穿全册的编辑装置 | KPI 仪表盘、密集卡片网格、三卡片行、通稿渐变、文化简报用“商务蓝” |
| **Culture texture** | 古诗词/节气/国学/水墨/非遗/文化节目 | 宣纸底 + 墨黑 + 一次最多一个朱红或青绿强调；真实材质特写 | 全幅水墨/纸纹理 + 竖排标题；或左 1/3 标题 + 右 2/3 氛围图 | 竖排诗句、横轴时间线、纸纹理引语带、三图拼贴、结尾印章页 | 纸纹理、印章红、细墨线、偶尔竖排文字；不中途换纹理 | 白塑料卡片、渐变、冷蓝、AI 生成的“国风”合成图、像素化矩阵 |
| **Signal system** | AI/软件/基础设施/产品发布/技术战略/路线图 | 近黑/石墨底 + 单一高饱和强调色（青/荧光绿/品红/琥珀）+ 硬白/中灰 | 全幅深色 + 超大无衬线标题 + 一条强调线；或代码/图表母题 | 超大标题陈述页、深色数据 hero、带轴网格的图表页、架构分层图、结尾 wordmark 页 | 一个重复几何元素（角标、细网格、信号轮廓）；强调色每页最多一次 | 紫色光晕、三卡片行、柔和生活方式摄影、可爱涂鸦图标、粉彩 |

**跨方向硬规则**：

1. **先定指纹再动手**：方向选定后，在开头固定 5 个轴——`palette`（色板）、`image_style`（图片风格）、`cover silhouette`（封面轮廓）、`content silhouettes`（内容轮廓）、`motif`（母题）。对应到本环境：deck 的 `theme`/`themeOverride`、图片选择、版式序列、自定义元素母题。
2. **另一个版本 ≠ 只换颜色**：用户要“再来一版”时，尽量在色板、图片语言、封面轮廓、字号层级、母题五个轴上都有变化；只 recolor 通常不算真正的新版本。
3. **模板编辑不选方向**：用户给了模板时，不套用以上方向，采样模板自己的色板/字体并保持（见 §15/§16）。

## 19. 图表设计细则（参考 ChatGPT spreadsheets features/charts.md，适配 PPT chart / SVG 可视化）

**何时用图**：只有当图表能让 KPI、比较、趋势、分布、排名、进度、关系更容易读时才用图；否则用紧凑表格或摘要。精确值在少量条目上时，表格优于图表。

**选型**（示例而非硬规则）：

- 类目比较/排名 → 排序柱/条图；时间趋势 → 折线图，面积只在“填充体积有意义”时用。
- 构成占比 → 只有少量分片且“大致占比是重点”时用饼/环；否则排序柱或表格。
- 分布 → 直方图；中位数/离散/离群才是重点 → 箱线。
- 单个指标带上下文 → KPI + 小趋势，而不是整张图。
- 最终以“让结论最容易看出来”为准，即使和示例不同。

**可审计数据**：

- 图表数据要可溯源：categories/series 来自真实数据，禁止编造；图内数字与源表一致。
- 未知值用空位，不要发明 0；分类与系列范围对齐。
- 时间轴标签拥挤时，先加“年/季/月/周”分组字段再作图，不要硬塞原始日期。

**干净放置**：

- 图放在它解释的 KPI/表格旁边；留足空白，不与源数据、控件、注释或其他图重叠。
- 相关图表保持一致的坐标刻度、单位、颜色与时间范围。
- 图的大小按“渲染密度”定，不按可用空间铺满：小图保持紧凑，只有标签/图例/密集数据需要时才放大；大而空的图不专业。

**标题/轴/标签**：

- 图表标题用易懂的人类语言，如“营收同比 +18%，企业客户拉动”；不要生造词。
- 单位要能看见：放进标题、轴或标签（%、$、小时、数量、日期）。
- 轴格式显式设置（百分比、货币、日期/时间戳）；轴含义从标题/刻度/数据标签已能看出时，才不需要轴标题。
- 长类目标签用短标签，完整标签保留在源表；密集折线不要给每个点加数据标签。

**克制的设计**：

- 颜色只表达含义，不用做装饰；相关图表颜色含义保持一致；单系列图不要意外变成多色。
- 避免 chartjunk：不必要的渐变、重边框、过多网格线、装饰效果。
- 有意义的排序：时间序列按时间、排名按降序、流程按过程顺序。
- 交付后读回核对：空白图、断连范围、公式错误、单位不可读、标签被裁剪、刻度过挤、不支持的图表类型。

**编辑已有图表**：先检查源范围与公式再动；除非用户要求重设计，否则最小移动/缩放避免重叠；改完复查源、公式、轴、标签与渲染效果。
