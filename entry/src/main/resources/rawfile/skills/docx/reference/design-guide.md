# Word 文档排版规范与场景建议

面向用户的最终 Word 交付物：报告、方案、纪要、总结、论文、说明书、工作手册。
核心原则：**结构先行、结论标题、数据可信、图片真实**。

## 1. 结构设计（动笔前先定骨架）

典型报告骨架：

```
封面（可选，正式对外文档建议加）   title + subtitle + author + date
目录（≥8 块 / 章节 ≥3 时建议加）   打开后右键"更新域"生成
H1 章节（每章一个主题）
  H2 小节（每节一个论点）
    正文段落（一段一个观点）
    表格 / 图片（证据与数据）
  H2 ……
H1 结论与下一步
```

- 章节编号自己写进标题（"一、""1.1"）或让 Word 编号，二选一，不要混。
- 内容超过 3 页没有标题，用户无法导航——**任何 >2 段的文档都要有 H2 级以上的标题**。
- 常见场景（商务报告/方案/会议纪要/论文/操作手册）的完整结构蓝图见 `document-blueprints.md`。

## 2. 标题规范

- **标题是结论句**：✗"经营情况" → ✓"上半年营收 1.2 亿，同比 +18%"。
- 一个 H1 下至少 2 个 H2；H2 下再分时至少 2 个 H3。不出现单点悬空。
- 标题层级按 1→2→3 递进，跳级（H1→H4）会让目录难看、读者困惑。

## 3. 正文与列表

- **一段一个观点**：段落首句是观点，后接 1~3 句论据（数字、事实、来源）。
- 段落长度控制：中文 3~6 行/段；整屏一段是大忌。
- 并列信息用 list（≤7 条），不用连排段落；有序 list 用于步骤/优先级。
- 强调用加粗，不用下划线、不用整段斜体；行内代码只用于文件名/API/字段名。

## 4. 表格与图片

- 表格：≤10 行、≤6 列时最易读；更复杂先考虑拆表或只列关键指标。
- 表格/图片都加 caption 题注：`表 1 …（来源：xxx）` / `图 1 …（来源：xxx）`。
- 图片质量：优先工作区里真实的截图/照片；示意图用 write_svg；**没有合适图片就不放图**，纯文字版式好过无关配图。
- 图片宽度：图表类 width 0.8~1.0，插图 0.5~0.8；过大的图（如整页截图）会糊，先裁剪。
- 数据必须来自工作区资料，禁止编造；来源写进 caption 或正文。

## 5. 场景建议

| 场景 | style | 结构要点 |
|---|---|---|
| 商务报告/方案 | default | 封面 + 目录 + 结论式标题 + 图表题注 |
| 会议纪要 | default | 无封面；H1=议题，要点用有序 list，决议加粗 |
| 论文/学术 | academic | 摘要段 → 各章 H1/H2 → 参考文献（表格列引用） |
| 内部备忘/周报 | minimal | 无封面；H1=本周主题，进展用 list，下周计划单列 |

## 6. 语言红线

- 禁用 AI 腔与黑话："赋能""闭环""抓手""综上所述""值得注意的是""不是X而是Y"。
- 用具体名词与数字："营收 1.2 亿（同比 +18%）"优于"业绩显著增长"。
- 不写空泛口号；每句都要有信息量。

## 7. 中文排版细则（中英混排、标点、数字、表格）

- **中英文字体配对**：中文正文宋体/黑体（标题黑体、正文宋体），西文与数字用 Times New Roman（正文）/ Arial（标题与强调）——中英混排时西文与数字整体用西文字体，不要用中文全角字符写英文。代码块用等宽字体（Consolas/等宽）。
- **标点**：中文句子用全角标点（，。；：""『』《》）；英文与数字之间用半角；中英文之间可加一个空格（"使用 Word 编辑"）让混排更疏朗；百分比写"18%"，区间用"~"（"3~5 天"），不用波浪号"～"。
- **数字与单位**：千位分隔（12,345 元）；金额统一（万元/亿元）并全篇一致；日期写"2026 年 3 月 21 日"或"2026-03-21"，全篇统一。
- **表格细则**：表头加粗（渲染器自动）；数字列右对齐、文本列左对齐（模型通过内容排版体现：数字前不加空格、单位放表头）；学术/正式报告可用三线表风格（表头下、表尾上两条线，中间无竖线——用"表头加粗 + 无多余装饰"表达）；单元格内容短句，不写整段。
- **公文风（GB/T 9704 简化，如用户要求"公文/红头文件"）**：标题居中（H1 即可）、正文仿宋风格（当前无仿宋预设，用正文宋体+正式表述替代，并说明）、一级标题黑体（用 H2 加粗）、成文单位与日期落款右下（用右对齐段落）。在三种样式下用"标题层级 + 右对齐段落 + 正式措辞"近似表达，不必承诺字体完全一致。
- **好/坏对照**：
  - ✗ 标题"经营情况" / ✓ 标题"上半年营收 1.2 亿，同比 +18%"
  - ✗ 一段 10 行不分段 / ✓ 一段一个观点，3~6 行
  - ✗ 表格 20 列挤成一页 / ✓ 拆表或只列关键指标，≤10 行易读
  - ✗ "综上所述，公司实现了业绩的增长" / ✓ "营收 1.2 亿，同比 +18%（来源：财务中台）"
  - ✗ 图片无题注无来源 / ✓ "图 1 月度趋势（来源：财务中台）"

## 8. 文档形态选型与表格门禁（参考 ChatGPT documents skill）

动笔前先决定"这段信息用什么形态承载"，不要一律"标题 + 大段文字"：

| 信息类型 | 首选形态 | 何时换 |
|---|---|---|
| 叙述/背景/理由 | 段落 | 出现可扫描并列项 → 列表 |
| 决策/建议/关键结论 | 段首加粗 lead + 简短理由 | 一句能说清 → 就一句话 |
| 步骤/流程/操作 | 有序列表 | 带负责人/状态 → 表格 |
| 并列因素/要求/优缺点 | 无序列表 | 需要逐项对比 → 表格 |
| 待办/验收/检查项 | 清单 | 行数多 → 分节 |
| 定义/元数据/键值对 | 定义列表（`术语：解释`） | 数量多 → 表格 |
| 重复结构记录/预算/矩阵 | 表格 | 单元格成段 → 改 prose/list |
| 警告/注意/约束 | 引用块 | 需强视觉分离 → 加粗框（quote 近似） |
| 证据/引用/来源 | caption + 文末来源表 | 少时 → 括号注 |

**表格门禁**：

- 只有真正"行×列可比较/可查询"的数据才用表格；表格不是排版工具。
- 若多数单元格是句子/段落，把该节改回段落、列表、步骤或引用块。
- 两个以上相邻表格，检查是否至少一个应改为列表/段落（避免"表格三连"的 AI 排版感）。
- 表格列宽按内容分配：短字段（编号/状态/日期/金额）紧凑，长文本列放宽；不要默认均分。
- 表格跨页时保持表头可读（当前渲染器若无法重复表头，就尽量让一个表控制在一页内，或拆表）。

## 9. 结构复验（read_docx 不是可选项）

生成/编辑后必须读回最终文件做结构级 QA：

- [ ] read_docx 或 read_file 抽查过每个章节/表格/图片位置，确认没有内容丢失或顺序错乱？
- [ ] 表格没有出现"单元格整段文字"、图片没有消失？
- [ ] 长文封面/目录/标题层级与规划一致？
- [ ] 编辑任务只动了目标区域，其余内容原样保留？

## 10. 交付前自检

- [ ] 结构完整：标题、章节层级不跳级、长文有封面/目录？
- [ ] 标题都是结论句？段落一段一个观点？
- [ ] 每个表格/图片都有题注与来源？
- [ ] 引用的图片路径经 list_files 确认存在？
- [ ] read_docx 或 read_file 抽查过最终文件？
- [ ] 无 AI 腔、无编造数据？

## 11. 编辑纪律（参考 ChatGPT documents skill）

用户给的是**已有文档**（不是从零新建）时，按"最小、可追踪的改动"处理，不要推倒重写：

- **保留原文档**：除非用户明确要求重写，否则在原稿上做局部修改。
- **小改优先**：改词、改句、改段落用 `replace_text`/`update_block`；大段重排前先确认确有必要。
- **不动无关内容**：只改目标区域，其余章节/表格/图片原样保留。
- **结构确需调整时**：外科手术式调整（`move_block`/`add_block`/`delete_block`），不要"整篇划掉重来"。
- **占位符**：模板里 `{{字段}}`/`【待填】`/`TODO` 逐个 `replace_text` 替换，替换后读回确认无残留。
- **交付后核对**：read_docx 确认改动落在目标区域、无内容丢失或顺序错乱。

## 12. 权威排版参数（参考 Doubao Word writing-taxonomy）

当用户没有给模板/格式要求时，按以下参数生成中文 Word；用户模板优先。

**字体与字号**

| 元素 | 中文 | 西文/数字 | 字号 | 其他 |
|---|---|---|---|---|
| 标题 Title | 黑体 | Arial | 18pt | 加粗、居中、黑色、段后 18pt |
| 副标题 Subtitle | 楷体 | Arial | 12pt | 居中、黑色、段后 12pt |
| Heading 1 | 黑体 | Arial | 16pt | 加粗、黑色、段前 14pt/段后 6pt |
| Heading 2 | 黑体 | Arial | 14pt | 加粗、黑色、段前 11pt/段后 5pt |
| Heading 3 | 黑体 | Arial | 12pt | 加粗、黑色、段前 9pt/段后 4pt |
| Normal 正文 | 宋体 | Arial | 12pt | 两端对齐、1.5 倍行距、首行缩进 2 字符 |
| Caption 题注 | 宋体 | Arial | 10.5pt | 居中、黑色；图题注在图下方，表题注在表上方 |
| 表格文字 | 宋体 | Arial | 10.5pt | 按数据语义对齐，单倍行距 |

- 标题/标题不得用 Word 默认主题蓝；默认黑色。
- 中文正文字体必须按 `eastAsia` 设置，不要用一个全局字体覆盖模板继承。

**编号**：全文只用一套：中文公文 `一、 → （一） → 1. → （1）` 或技术/咨询/分析 `1 → 1.1 → 1.1.1`；禁止混用。

**页面**：A4；页边距上下左右 2.5cm；默认无页眉；页脚页码居中阿拉伯数字；封面/目录不编页码，正文从 1 开始。

**目录**：用户/模板决定优先；报告/方案/论文/手册/培训材料 >5000 字或 >5 页且有导航价值时必须动态 Word 目录（当前渲染器如不支持域，则明确告知用户需更新域）；短文档/表单/简历不做机械目录；目录取自真实 Heading 1–2，通常最多 2 级。

**表格**：表题在表上方居中，比正文小 0.5~1 号；表头居中、与表体同号；短文本（<12 字）居中、长文本左对齐、数字右对齐，整列统一；单元格垂直居中；表头浅灰 `#D9D9D9`/`#F2F2F2`，数据区白底或隔行 `#F2F2F2`；边框外粗内细；表格内不缩进。

**图片**：正文内嵌居中；宽度不超过版心；不得拉伸变形；图题注在图下方，与图同页。

**列表**：用真实 Word 项目符号/自动编号，不要手动打 `•`/`1.`。

**脚注/参考文献/附录**：脚注/尾注用 Word 原生能力；参考文献置于正文后、附录前，编号 `[1]`；附录用"附录A/B"，单独起页，附录图表单独编号（图A.1/表B.2）。
