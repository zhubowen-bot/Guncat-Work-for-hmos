# 信息图形态蓝图（参考 doubao-visualization mode-html-svg）

本文不是自创模板，而是把 Doubao 可视化 skill 的「常用信息图形态」与硬规则移植到我们的 SVG 场景。处理"用一张 SVG 把复杂信息讲清楚"时：先按形态表判断结构 → 再按硬规则设计 → 写 SVG → view_image 预览。

## 0. 主模式路由（参考 doubao-visualization SKILL）

按顺序判断，首次命中即确定主模式：

1. **图示是否明显优于文字？** 否 → 不要画图，直接用文本/表格。
2. **核心是否是精确数值的趋势/占比/排行/分布/相关性或多指标比较？** 是 → 用 SVG 图表（柱/折线/饼/雷达等）。
3. **核心是否是可准确枚举的流程、机制、架构、关系、时间线、状态或算法过程？** 是 → 用 SVG 信息图。
4. 结构或事实不足以可靠绘制 → 回退文本/表格。

## 1. 常用信息图形态（移植自 Doubao）

| 内容 | 推荐形态 |
|---|---|
| 流程、pipeline | 带方向的步骤流、泳道、阶段门 |
| 因果、机制 | 因果链、反馈回路、输入—处理—输出 |
| 架构、分层 | 水平分层、模块连接、数据流箭头 |
| 人物、角色 | 分组关系网、层级树、关系矩阵 |
| 时间、演进 | 时间轴、阶段带、转折节点 |
| 状态机 | 状态节点、条件标签、迁移箭头 |
| 对比、选型 | 双栏对比、矩阵、二维定位 |
| 分类、构成 | 树状层级、嵌套分区、分组列表 |
| 算法、证明 | 分步画布、当前步骤高亮、前后状态 |
| 参数、物理 | 滑块、实时数值、轨迹或曲线联动 |

> **不要把"标题 + 若干等大卡片"当成默认信息图**：每个节点和连线都应有信息意义；并列卡片只有在确实承载并列数据时才用。

## 2. 静态与交互选择

- **static 是默认**：阅读方向固定的流程/时间线、节点与连线可一次呈现的关系/架构、不需要改变参数的机制/比较、初始画面即可完整理解的状态结构，全部用静态 SVG。
- **interactive 只在有理解增益时用**：点击显示必要说明、拖动参数改变结果、播放揭示算法/过程、切换视图帮助比较、原图逐步高亮定位证据。
- 如果交互只是展开静态文字、装饰动画或 hover 高亮 → 改回静态。

## 3. 硬规则（移植自 Doubao）

- **初始可读**：主结论先用文字和初始静态状态表达，不依赖 hover、脚本或外部库。
- **证据保真**：依赖原图事实时保持原图位置/比例；示意结构显式标注"示意"。
- **数据可复核**：真实数字/年份/事件/专业细节只来自用户材料或已核验来源；示例数据明确标注。
- **降级**：复杂交互失败 → 静态 SVG → 结构化文字；任何失败都不能留下空白。
- **地图禁用**：当前工作模式不承接地图、地理轨迹、行政区划。
- **可访问性**：仅用颜色区分时必须增加文字、形状、线型或图例。

## 4. 落地到我们的 SVG

1. 按形态表选结构；信息太多先拆图（一张图一个核心信息）。
2. 定画布：PPT 内页约 960×540，文档配图约 800×450，独立图按内容定。
3. 按 `svg-craft.md` 写骨架（xmlns + width/height + viewBox + title）。
4. 节点 ≤7 个最清晰；超过就分层或拆图；连线/箭头语义全图一致。
5. `write_svg` → `view_image` 预览 → 对照形态表检查阅读顺序、层级、对齐 → 修正。
