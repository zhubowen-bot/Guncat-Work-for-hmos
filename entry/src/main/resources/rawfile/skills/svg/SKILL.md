# SVG 矢量绘图（生图）

模型不输出位图，但写好 SVG 是基本功：本技能把"手写 SVG"变成一条可靠的生图流水线——**路由 → 硬规则 → 落地流程 → 创意一致性 → 交付校验**，直到合格再交付。V2 在保持 `write_svg`/`view_image` 契约不变的前提下，按"先选对图形、静态优先、落地步骤、风格一致、交付校验"重排结构。

## 工具链

| 工具 | 用途 |
|---|---|
| `write_svg(path, svg, width?)` | 保存 `.svg` + 自动栅格化出 `<name>_preview.png`。根元素缺 width/height 时按 viewBox 自动补齐（但仍按模板显式写全，一次成功） |
| `view_image(path)` | 查看预览 PNG——这是你的眼睛，**生成后必看** |
| `write_pptx` | 图片参数可直接引用 `.svg`（导出时自动栅格化） |
| `write_docx` | 图片引用预览 PNG |
| `download_file(url)` | 需要照片级素材（真实照片）时下载现成图片，而不是硬画 |

**分界线**：几何图形、图标、图示、信息图 → SVG 生图；真实世界照片 → `download_file` 找现成图。给"风景照""人像"之类的需求写 SVG 是错误用法。

## 路由：先选对载体，再动手（移植 doubao-visualization）

SVG 是"确定性图表/示意图"的首选载体；不是所有图片需求都该走 SVG。按顺序判断，首次命中即确定主模式：

1. **图示是否明显优于文字？** 否，或用户只要文字 → 不画图，用文字/表格回答（`text_only`）。
2. **结论是否依赖真实照片（写实场景、人像、风景、实拍证据）？** 是 → `download_file` 取现成图，不用 SVG 硬画。
3. **核心是否是可准确枚举的流程/机制/架构/关系/时间线/状态，或精确数值的趋势/占比/排行/分布/比较？** 是 → SVG 生图（本技能主模式）。
4. **结构或事实不足以可靠绘制？** 是 → 回到文字/表格，不要硬画。

**不使用**（对齐 doubao-visualization 的"不使用"）：

- 简短事实、确认、普通改写、翻译、闲聊，纯文字已足够清楚。
- 海报、头像、壁纸、写实图片、艺术插画等照片级/风格化创作 → 不是本技能目标；需要时走 `download_file` 或说明能力缺口，不硬写 SVG。
- 地图、导航、地理轨迹、行政区划、经纬度点位 → 不绘制（本技能不承接地图类）。
- PDF/PPT/Word/Excel 等真实附件交付 → 用对应文件能力，不是 SVG。

## 硬规则（移植 doubao-visualization）

- **静态默认**：SVG 输出默认静态。装饰性动画/hover 高亮不属于本技能契约；需要表达"动态/变化"时用多帧分步示意或编号步骤，并明确说明。
- **证据保真**：依赖原图/工作区素材的位置、数量、比例、路径时保持原貌；示意性简化必须显式标注"示意"，不得冒充证据。
- **数据可复核**：图中数字、年份、名称、比例、单位只来自工作区资料或用户提供，**禁止编造**；示例数据必须明确标注为示例，来源写进图内标题、注释或交付说明。
- **模式单一**：默认一张图只讲一个信息点；信息点太多就拆成两张图，或改用 PPT chart/table 版式，不硬塞进一张 SVG。
- **初始可读**：核心结论先用文字和初始静态画面表达，不依赖交互、脚本或外部资源才能看懂。
- **失败可降级**：管线验证/栅格化失败 → 最小复现 → 增量叠加二分定位；任何失败都不能留下空白交付，失败就回到最小 SVG 重试。

## 最小内部计划（移植 doubao-visualization）

动手前只需在内部确定：

```json
{
  "mode": "svg",
  "behavior": "static",
  "source": "user_content",
  "secondary": null
}
```

- `mode`：`text_only` / `download_file` / `svg`。
- `behavior`：本技能默认 `static`（静态契约，无交互）。
- `source`：`user_content`（资料来自工作区）、`user_image`（原图证据）、`verified`（已核验）、`example`（示例数据）、`insufficient`（资料不足 → 澄清或标注）。
- `secondary`：默认 `null`；只有确需第二张互补图时才填写第二模式，最多两张。

## 落地流程（每张图都走完整循环）

1. **定规格**：这张图放哪（PPT 内页/封面/文档配图/独立交付）？用途决定画布比例与配色（放进 PPT 时配色对齐所选主题，见 ppt 技能的 themes）。
2. **规划风格锚点**：确定本任务的配色、描边宽度、圆角、字体、元素比例（同系列沿用同一锚点，见"创意设计流程"）。
3. **管线验证（新会话首次生图或复杂图必做）**：先用**仅含一个 `<rect>` 的最小 SVG** 走一次 write_svg + view_image，确认管线畅通再全量绘制——栅格/解码类失败一律按"**最小复现 → 增量叠加**"二分定位，不要先读回全文验证语法（刚写入的文件不存在语法损坏）。
4. **写 SVG**：按 `reference/svg-craft.md` 的规范写——根元素带 `xmlns` + `width/height` + `viewBox`，图形优先 path，图标加 `<title>`。
5. **生成**：`write_svg` 一次成型（返回预览 PNG 路径与尺寸；源码缺 width/height 会自动补齐并在返回中注明）。
6. **看图自检**：`view_image` 看预览，对照下方"生成前检查/交付自检"逐项检查。
7. **迭代**：有问题直接改 SVG 源码重新 `write_svg`（覆盖同一路径），不要生成一堆 v2/v3 文件；迭代仍失败时回到第 3 步的最小复现定位不兼容特性。
8. **交付**：确认合格后，在交付物里引用它；总结中说明文件路径与用途。

## 可视化类型选择（图形选型表）

先选对图形，再动手；要表达的信息与首选图形对应如下：

| 要表达的信息 | 首选图形 | 说明 |
|---|---|---|
| 趋势/时间变化 | 折线图 / 面积图 | 数据点来自工作区，标单位 |
| 类目对比/排名 | 柱状图 / 条形图 | 排序后画，突出结论 |
| 构成/占比 | 饼图/环形图 | ≤5 块；过多改横向条形 |
| 流程/步骤 | 流程图（节点+箭头） | 节点 ≤7 个，箭头语义一致 |
| 架构/层级/关系 | 架构图/树/网络 | 分组 `<g>` + 连线；避免交叉线 |
| 时间线/里程碑 | 时间轴 | 单向线性排列，事件标注日期 |
| 状态机/算法步骤 | 状态图/分步示意 | 明确起始态/终止态 |
| 因果/机制 | 因果链/机制图 | 箭头表示方向，不要自造符号 |

**数据纪律**（与硬规则联动）：

- 图中数字/比例必须来自工作区资料或用户提供，**禁止编造**；来源写进图内标题、注释或交付说明。
- 图表类优先用 SVG 几何图形表达数据，不写真实验照片；需要真实照片用 `download_file`。
- 一张图只讲一个信息点；信息点太多就拆成两张图，或改用 PPT chart/table 版式。

## 最小示例（保存为 assets/arrow-right.svg，可直接验证管线）

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="96" height="96" viewBox="0 0 24 24" fill="none"
     stroke="#1B2330" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <title>右箭头</title>
  <path d="M5 12h14M13 6l6 6-6 6"/>
</svg>
```

`write_svg` 后得到 `assets/arrow-right.svg` + `assets/arrow-right_preview.png`。

## 配方（按需加载）

24×24 描边图标、填充图标、横向流程图、架构图、信息图卡片、柱状对比图、时间轴、封面装饰、sparkline 等可直接套用的模板见 `reference/svg-recipes.md`（均含 width/height 与 `<title>`）；绘制规范与场景分级见 `reference/svg-craft.md`。

> 不知道整张信息图怎么布局？对比/流程/时间线/架构/KPI 卡/机制因果的蓝图见 `load_skill("svg","reference/infographic-blueprints.md")`——先选蓝图再写 SVG。

本技能只放通用规则与路由，具体模板与规范**按需加载**（用到哪个读哪个，不预读无关文件），对齐 doubao-visualization 的"按需加载"与 doubao-creative-design"主 SKILL 只放通用规则和路由、产物细则按需读 reference"的定位。

## 创意设计流程（移植 doubao-creative-design）

### 风格一致性 / 核心资产

- 同一任务、同一文档或同一系列的多张 SVG：先锁定**核心资产/风格锚点**——品牌色、Logo、图标风格、描边宽度、圆角半径、字体、元素比例——后续每一张都沿用同一锚点，禁止同系列中途换风格。
- 接续创作（用户说"基于刚才那张/继续做/改一下/延展上一版"）：先定位已有 SVG 文件并沿用其风格锚点，在**同一路径上覆盖迭代**，不要从零另起一张新图。
- 第一张被后续沿用的图即升级为当前风格锚点；系列内任何调整必须保持核心识别特征，不脱离重画。

### 澄清规则

默认先规划、少问问题。只有缺失信息会影响执行路径、风格锚点/核心资产引用、交付范围或数据准确性时，才问 1-2 个关键问题（用选择题）；缺失 1 项关键参数时用合理默认值补全并把默认值写进内部计划；事实性内容（价格、销量、比例、日期、专名）缺来源时必须问或明确标注来源。

### 张数 / 批量策略

- 每次 `write_svg` 只产出目标图本身；同图迭代用覆盖同一路径，不生成 v2/v3 文件堆叠。
- 需求一次要多张系列图时，先出 1 张**最具代表性的代表图**，确认方向后再按同一风格锚点批量，不一次性画完所有。
- 没有明确张数时不默认扩展；多张系列图必须共用同一风格锚点，张数与一致性冲突时优先减少张数保一致。

### 复杂任务

满足任一条件即先给执行计划并等用户确认：需要一组有关联的系列图；需要先生成核心资产/风格锚点再基于它衍生其他图；需要在 SVG 与 `download_file` 照片之间切换；涉及多比例、多轮迭代或完整方案。计划中写清：目标图形、风格锚点、每张图用途、是否需要用户补充关键文字或数值。

## 生成前检查（移植 doubao-creative-design）

调用 `write_svg` 前确认：

1. 是否已走完"路由 → 硬规则 → 图形选型 → 风格锚点"？
2. 数字/比例/名称来源清晰可复核，示例已标注？
3. 接续创作时是否沿用已锁定风格锚点，且写清保留项/修改项？
4. `write_svg` 参数正确（path / svg / width?），根元素三件套齐全？
5. 是否已确认管线畅通（复杂图先走最小 rect 验证）？

## 交付前自检清单（统一交付检查）

- [ ] 根元素带 `xmlns`、`width/height`、`viewBox` 三件套？
- [ ] `view_image` 预览看过：无越界、无重叠、无文字截断、缩到小尺寸仍清晰？
- [ ] 图形是否确实增加理解，且模式与素材性质匹配（SVG vs 真实照片 vs 纯文字）？
- [ ] 图标/信息图带 `<title>` 可访问性标注？
- [ ] 用了 `<text>` 的话预览里渲染正常（字体依赖是最大风险，异常就转 path）？
- [ ] 数据、术语、单位、时间范围、来源一致，示意性质是否明确标注？
- [ ] 配色与元素数符合场景分级（图标/信息图从严，卡通插画放宽至 4~6 色、30+ 元素）？
- [ ] 背景透明是否合适（放深色页会看不见深色笔画）？
- [ ] 图形含义准确、没有自造的符号、没有误用地图？文件落在合理路径（如 assets/）？
- [ ] 最终交付物引用的是 svg/preview 路径，且路径真实存在？

## 结果反馈（移植 doubao-creative-design）

生成后不要机械复述"已完成"。如果结果可继续优化，只给 1-3 个具体方向，例如：换比例、调整配色/对比度、加强文字可读性、按当前风格锚点继续系列延展。引导用户根据反馈继续对话或迭代。
